# Support

`<Product>` is an early-stage, community-supported open-source project. There is no paid support and no SLA.

## Where to go

| You want to... | Do this |
|---|---|
| Report a bug | Open a **Bug report** issue. Include the product version, RabbitMQ version and how you run it (container, desktop, team server). |
| Propose a feature | Open a **Feature request** issue. Describe the problem before the solution. |
| Propose or challenge a decision | Open an **ADR proposal** issue ([docs/adr/README.md](docs/adr/README.md)). |
| Report wrong RabbitMQ behaviour in the semantics registry | Open a **Semantics RFC** issue; these are handled with security-level priority. |
| Report a vulnerability | Do **not** open an issue. Follow [SECURITY.md](SECURITY.md). |
| Ask a usage question | Open an issue with the `question` label until GitHub Discussions is enabled. |
| Report a Code of Conduct problem | See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). |

## What to expect

- Issues are triaged by the maintainers on a best-effort basis.
- Fixes land on the latest release only. There is no supported-versions table yet; one will be published before Web 1.0 (milestone M1), together with the support and LTS policy ([SECURITY.md](SECURITY.md)).
- Pre-release (alpha) versions carry no compatibility promise.

## Before you ask

- Search existing issues and the [documentation](docs/README.md).
- Remove credentials, hostnames and message payloads from anything you paste. The product never needs them to diagnose a problem.
