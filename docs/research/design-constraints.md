# Design constraints DC-01…DC-60

Binding constraints derived from the [verified fact sheet](fact-sheet.md). A deviation needs verified evidence and an ADR (for example ADR-004 deviates from part of DC-49).

| ID | Constraint | Rationale | Affects |
| --- | --- | --- | --- |
| DC-01 | Encode all RabbitMQ behaviour that differs by version as a data-driven BrokerSemantics registry. Key it by era (3.13 / 4.0-4.2 / 4.3 / 4.4), queue type, settle action and distribution. Give each entry a source citation and a conformance-test ID. Peek plans, warnings, button labels, receipts and MCP tool contracts are all generated from this registry; nothing is hard-coded. | Behaviour differs fundamentally across eras (AC vs DC limit basis, TAIL vs HEAD, carry-over, timeouts). Every competitor is wrong for at least one era. | engine/semantics, UI warnings, MCP, docs |
| DC-02 | Resolve semantics per cluster, conservatively. Use 3.13 rules if any node is below 4.0. Use 4.0-4.2 rules if any node is below 4.3, or flag rabbitmq_4.3.0 is not enabled (it is 'stable', not 'required'), or any QQ member status reports Machine Version < 8. Apply the same 4.0-4.2 rules to unknown or commercial builds (4.2.10/4.2.11, Tanzu) until conformance-tested. | Mixed clusters keep v7 QQ behaviour. Feature flags and per-node machine versions are the only HTTP-visible signals. | engine/capability-probe, semantics |
| DC-03 | Peek on classic and quorum queues settles only with basic.nack(requeue=true), or with AMQP 1.0 released (4.0+, credit N plus drain). It never uses basic.reject, modified(delivery-failed=true), rejected/discard, HTTP reject_* or ack_requeue_false. On 3.13 it never sends AMQP 1.0 modified, because the plugin maps it to reject(requeue=false). | Only nack/released are non-failed returns on 4.3+. Reject counts. On 3.13, modified destroys the message. | engine/peek, adapters |
| DC-04 | Never return held deliveries by closing a channel, session or connection, or by detaching a link. Always send an explicit nack, then a synchronous basic.qos barrier, then close. Electron before-quit, powerMonitor suspend, the team-server SIGTERM handler and job cancellation all flush pending nacks first. | On 4.3 any DOWN of the consuming process, graceful or not, counts as a failed delivery (DC+1). HZN shipped exactly this bug. | engine/peek, Electron main, server lifecycle |
| DC-05 | A peek is a short, atomic, engine-side job: acquire, copy, return within a 5 s target and a 30 s hard abort, lowered further by TTL and consumer timeout. An engine watchdog enforces it. The UI renders copies only. Deliveries never stay unacked across user think-time, HTTP round trips or route changes. | Holds hide messages from consumers. Crashes and sleep during a hold count on 4.3. Classic queues have no server timeout from 4.3. | engine/peek, UI |
| DC-06 | Run a mandatory HTTP-only preflight before every CQ or QQ peek. It covers: queue type, exclusive owner, auto_delete, the real delivery_limit stat, DLX and DLQ topology, delayed-retry state, length limit and overflow, TTL, SAC and active consumers, QQ quorum and leader health, and size. Gates either block the peek or require consent. | Hazards include over-limit drops, drop-head, TTL expiry, 405 on SAC or exclusive queues, and auto-delete deletion. | engine/peek-planner |
| DC-07 | On 4.3+, block by default any peek of a quorum queue whose finite delivery limit is not above every dead-letter source's limit + 1. Offer a one-click policy fix (delivery-limit -1) and a lint rule. | Delivery count is carried into the QQ DLQ, so any return, nack peeks included, drops or re-dead-letters over-limit arrivals. | peek-planner, linter, policy editor |
| DC-08 | On 4.0-4.2 quorum queues, every peek requires explicit budget consent. The prompt shows L and each message's attempts used. Caps are 20 by default and 50 maximum (200 for admins), with no auto-refresh and a post-acquire guard: stop at x-delivery-count (= acquired count) >= L. | Every return increments acquired_count, which is the limit counter. The (L+1)th return dead-letters or drops the message. | peek-planner, UI |
| DC-09 | Run a post-acquire guard on every fetched QQ message (4.3+: DC > L; 4.0-4.2: AC >= L; 3.13 with a limit: DC >= L). It stops acquisition and applies the rescue option the user chose beforehand: copy to a quarantine queue with publisher confirms on a separate connection, then ack. Unattended and AI-initiated runs may never 'let RabbitMQ handle' a doomed message. | Doomed messages are deleted or dead-lettered by the return itself. | engine/peek, MCP policy |
| DC-10 | The primary CQ/QQ peek transport is AMQP 0-9-1 basic.get on an engine-owned dedicated connection. HTTP POST /get is a fallback only, with ackmode ack_requeue_true, count <= 50, truncate, and the same preflight. When a broker might hold over-limit messages, HTTP /get is not offered for that queue. | Only the AMQP path allows the post-acquire guard. HTTP /get auto-nacks everything and holds every body in handler memory, with no server cap. | engine/peek, adapters |
| DC-11 | Never call basic.get, or HTTP /get, on a stream. Isolate risky calls (passive declares, gets on SAC or exclusive queues) on throwaway channels. A peek connection has at most one in-flight peek job and never publishes. | Stream basic.get raises a connection-level 540, and 4.3 passive-declare 403s close channels. Either turns the held QQ deliveries on that connection into failed deliveries. | engine/connection manager |
| DC-12 | Use a small, role-separated set of connections per broker profile: control, peek, publish/replay, and consume/tap/stream. Budget them against probed and provider limits (connection_max, channel_max, consumer_max_per_channel, which is 10 on Amazon MQ 4.x). Use one consumer per channel. Queue jobs instead of exceeding the budget. | Memory alarms block publishing connections, and connection errors cascade to every channel. Managed plans have tight limits (CloudAMQP shared: 20/100 connections). | engine/connection manager |
| DC-13 | Read a QQ's effective delivery limit from the GET /api/queues 'delivery_limit' stat, never from a recomputation. Surface mismatches with arguments and policies (W-UPGRADED). The policy editor warns that any matching policy change applies the effective limit (default 20) to 3.13-era queues that are still unlimited. | Upgraded queues keep 'unlimited' until a policy event. Tick reconciliation is buggy (orelse guard). | peek-planner, policy editor |
| DC-14 | Peek planning must account for 4.3 delayed retry (types all/returned delay nack-peeked messages by at least the minimum delay). Delayed and scheduled messages are listed as not peekable. Delayed-retry policy keys are offered only on 4.3.1+. | Delayed messages are invisible to consumers, get and the CLI peek. The policy keys are rejected on 4.3.0. | peek-planner, policy editor |
| DC-15 | Use honest wording everywhere. Say 'side-effect-aware peek' and 'messages stay in the queue'. Never say 'non-destructive' or 'read-only' for CQ/QQ reads. 'Non-destructive' is reserved for anonymous stream browsing and the optional node-agent QQ peek. Every peek produces a side-effect receipt (era, method, AC/DC deltas, positions, hold time) that is logged to audit and returned from MCP. | Every AMQP or HTTP read sets redelivered, changes counters or order, and holds messages. | UI copy, docs, audit, MCP |
| DC-16 | Treat the 3.13 x-delivery-limit=-1 argument as 'drop on first return'. Lint it, and refuse peeks on such queues. Show '-1 = unlimited' only on 4.0+. | 3.13 does not normalise negative limits, so 1 > -1 discards the message on its first return. | linter, peek-planner, policy editor |
| DC-17 | Taps default to a copied-binding exclusive classic queue. It has an explicit name within the user's configure regex (never amq.*), x-queue-type=classic, x-overflow=drop-head, a small x-max-length, x-message-ttl and x-expires. Bindings are copied with their arguments and re-synced while the tap runs. Policy matching for the tap name is simulated first, and alarms are checked first. | Inherited reject-publish policies (e.g. Amazon MQ) nack production publishers. Headers bindings without arguments match everything. 4.3 denies transient non-exclusive queues. | engine/tap |
| DC-18 | By default, refuse to tap x-consistent-hash, x-modulus-hash, x-random, x-local-random and unknown plugin exchange types unless the user accepts diversion explicitly. Never create exchange-to-exchange taps on consistent-hash exchanges below 4.3.6. Sweep orphaned tap exchanges. | Taps on these types steal messages (and remap keys on modulus-hash). #17255 causes silent loss on 4.3.0-4.3.5. | engine/tap, linter |
| DC-19 | The UI badges the default-exchange blind spot. It also badges alternate-exchange, mandatory-return and unroutable-metric masking whenever a tap matches more than the existing bindings do. Firehose is offered as the only mode that sees direct-to-queue and unroutable publishes. | No binding can involve the default exchange. A broad tap changes routability. | UI/tap |
| DC-20 | Firehose control is admin-only, per node, and on a lease with automatic switch-off. Enable it via PUT /api/traces/node/{node}/{vhost}/{name} when rabbitmq_tracing is present, or by generating per-node 'rabbitmqctl trace_on -n' runbooks. Never toggle tracing via PUT /api/vhosts. Track and re-verify per-node state after restarts. Label capture 'partial' behind load balancers. | Tracing state is node-local and not persisted. The vhost toggle reaches only the serving node. | engine/firehose, team RBAC |
| DC-21 | Any vhost write is GET-merge-PUT carrying description, tags, default_queue_type and tracing together. An integration test asserts that a non-default default_queue_type survives the round trip. | Source-verified at v4.3.6: a PUT without default_queue_type resets it to the node default and wipes description and tags. | engine/admin, tests |
| DC-22 | Stream browsing defaults to AMQP. On 4.0+ use the in-house spec-correct rhea AMQP 1.0 adapter, with described filter-set values, ulong offsets and timestamps in ms. Fall back to AMQP 0-9-1 x-stream-offset (manual ack, prefetch > 0), which is also the path on 3.13. The stream protocol is an optional fast path enabled only when probes confirm that every advertised host:port is reachable. Readers are always anonymous: no names, no storeOffset, no singleActive. | rabbitmq_stream is not enabled by default and 5552 is often unreachable. Amazon MQ has no streams. Named consumers mutate server state. | engine/stream browser, adapters |
| DC-23 | Every AMQP 1.0 stream attach compares the requested filters with the filter-set the broker reports as applied in the attach reply. It fails closed with 'broker ignored filter X' instead of scanning. | 4.3 silently drops non-described stream filters, and future removals may drop others. | adapter-amqp10 |
| DC-24 | The rabbitmq-amqp-js-client 1.0.0 package is not used on the production path. CI fails if any dependency resolves from a git URL. If installed for tests, its rhea is pinned via overrides to registry 3.0.5. | Filter encoding, BigInt offsets, vhost, credit, link race and address-encoding defects. Git dependencies have no integrity or provenance. | engine deps, CI |
| DC-25 | The AMQP 1.0 adapter always opens receivers with credit_window 0, autoaccept and autosettle off. It grants explicit credit N, then drains, and settles every delivery explicitly before detach. Tap links use bounded credit windows that are refilled only as the UI consumes. | rhea's default credit of 1000, refilled on arrival, would acquire up to 1000 messages per peek. | adapter-amqp10 |
| DC-26 | The stream browser and the DLQ views must disclose header-conversion loss. For streams: 0-9-1 non-x- table and array headers are lost at write time. For CQ/QQ messages read across protocols: the same loss happens on conversion. DLQ and peek reads of CQ/QQ use AMQP 0-9-1 to keep typed header tables. | Streams store AMQP 1.0 encoding. The 0-9-1 to 1.0 conversion drops array/table headers (conversions.md). | stream browser, DLQ centre, decoders |
| DC-27 | DLQ replay: republish from the engine on a dedicated confirm channel with mandatory set. Ack the source only after the confirm. Throttle with a token bucket, run a canary, and keep a journal. Pause when re-failures appear. Strip broker-managed headers (x-death*, x-first/last-death-*, x-delivery-count, x-acquired-count, elapsed expiration, mismatched user_id). Preserve logical message ids. Add switchable provenance headers. | 4.x ignores client-published x-death, and copied counters survive to the next delivery. user_id is validated. Inboxes dedupe on ids. | DLQ operations centre |
| DC-28 | The replay destination is resolved queue-first: framework field, then the newest rejected/delivery_limit x-death entry, then a naming convention. Publish via the default exchange. Exchange-based replay requires an explicit fan-out confirmation. Never route by x-first-death-queue alone. | First-death headers can point at delay queues. Original-exchange replay duplicates to other consumers. | DLQ operations centre |
| DC-29 | Shovel-based moves and redrive are capability-gated and deprioritised. Block them on 4.3.0-4.3.6 (reject loop). Prefer local shovels on 4.2+ only after counter and death carry-over has been tested. | #17794 is fixed only in untagged 4.3.7. Local shovels forward annotations. | DLQ centre, ops |
| DC-31 | Run a read-only capability probe on every connect. It produces a cached BrokerProfile (product, provider, version, tags, load-balancer fronting, nodes, extensions, plugins, restrictions, limits, auth and TLS). Every feature gate shows a 'why disabled' reason with a source link. Write-shaped probes run only on demand. | Managed brokers differ widely, and LavinMQ and ApsaraMQ are not RabbitMQ. | engine/probe, UI gating |
| DC-32 | Gate features on version, flags and stats mode using the known-bug table as data. Use ?disable_stats=true&enable_queue_totals=true for list views. Never send disable_stats to /api/channels below 4.3.6. Expect policy and delivery_limit fields to be missing with stats off below 4.2.5. Take rates and node resources from Prometheus. | Stats-off behaviour differs per patch release. | engine/mgmt client, metrics |
| DC-33 | Metrics are Prometheus-first and scraped per node, never through a Service or load balancer. Discovery order: provider adapters (Amazon MQ 16001-16003, CloudAMQP per-node hosts), then overview listeners, then default ports. Use the queue= filter only on 4.3+. Never call /metrics/per-object on Amazon MQ. Scrape at 60 s or slower there. Fall back to management API sampling. | Prometheus endpoints, ports and features vary by provider and version. | metrics/alerts |
| DC-34 | All broker I/O happens in the engine (Electron utilityProcess, local Node process, or team server). The browser UI never talks to brokers. The tool never requires users to configure management.cors.* or to enable Web-STOMP. | CORS is opt-in and empty by default. AMQP over WebSocket is Tanzu-only. | architecture, UI |
| DC-35 | Desktop UI-to-engine transport is a MessagePort (MessageChannelMain). The Angular RPC layer is transport-agnostic (MessagePort for desktop, WebSocket for local web). The local CLI and the stdio MCP shim use a permission-protected Unix socket or named pipe. No TCP listener for local MCP. | Removes the DNS-rebinding, CSRF and LNA surface. Electron disables LNA. | Electron main, engine/transport, UI |
| DC-36 | Local web mode binds 127.0.0.1 by default and refuses public binds without real authentication and TLS. It uses a startup token in the URL fragment, Host/Origin allow-lists, JSON-only bodies and no GET mutations. Docker docs prescribe -p 127.0.0.1:PORT:PORT, and the token is always required inside containers. | Published Docker ports bypass host firewalls, and DNS rebinding is a risk. | local web mode, docs |
| DC-37 | The identity subsystem has pluggable credential providers: password, OAuth PKCE loopback, device code, client credentials, token command, static token, x509/EXTERNAL, Vault/OpenBao dynamic, delegated user. Profiles hold separate HTTP and AMQP credentials. A TokenManager refreshes per protocol and asserts that the username claim is unchanged: update-secret for 0-9-1; PUT /auth/tokens on 4.1+ for 1.0; reconnect for 4.0 AMQP 1.0 and for streams; HTTP 401 retries only idempotent requests. | The HTTP chain can differ (4.0.8+). A username change is refused. Expiry behaviour varies by version. | engine/identity |
| DC-38 | On brokers up to 4.2.5 (AMQP 0-9-1), the engine cancels its own taps and consumers at token expiry. On 4.2.6+/4.3 it handles 320 CONNECTION_FORCED reconnects without disrupting the user. It warns before use when a Bearer header exceeds ~4,000 bytes or a PLAIN response exceeds the pre-auth frame limit (4096 on ≤4.0, 8192 on 4.1+), and always prefers Bearer over Basic-with-token. | Older brokers leave zombie consumers running. Oversized tokens cause 431 or frame_too_large. | engine/identity |
| DC-39 | OAuth discovery reads unauthenticated /js/oidc-oauth/bootstrap.js, falling back to /api/auth only on ≤4.1. The tool shows the issuer and pins it to the profile, checking it against an allow-list. Desktop logins use the system browser only, never an embedded webview. | /api/auth was removed in 4.2. A malicious broker could advertise a phishing or SSRF IdP. RFC 8252. | engine/identity, desktop |
| DC-40 | The team server is the system of record. It keeps an append-only audit log with attempt and outcome rows for every purge, get/peek, publish, tap, firehose and admin action. RBAC is deny-by-default and stricter than the broker: peek, consume, purge, replay, publish, topology admin and user admin are separate permissions. Peeks on budget-limited QQs and bulk replays require an operator role or four-eyes approval. All of this ships free. | Purge needs only read permission. The broker emits no purge event and logs no HTTP requests by default. Free team features are the differentiator. | team server |
| DC-41 | Team-server broker credential mode is chosen per connection: delegated OAuth (access tokens for the broker audience only, never ID tokens), Vault/OpenBao dynamic, personal LDAP, or service account. It is always intersected with the tool's RBAC. Delegated mode uses per-user connection pools. | A connection's username cannot change on refresh. RabbitMQ does not check token type. | team server/identity |
| DC-42 | MCP and AI go through the same policy-enforced action layer. The team-server /mcp is its own OAuth resource with no token passthrough. Tools reference connections only by human-created opaque IDs: models never supply hosts, URLs or credentials. Peeks are classified as mutations. Mutating tools are off by default and need human approval. Payloads are quoted, size-capped, control-character-stripped and secret-masked. | MCP spec bans passthrough. CVE-2026-18655. amazon-mq's 'read-only' get_messages can consume. | MCP/AI |
| DC-43 | Every outbound socket goes through one Dialer that applies the SSRF/egress policy. That covers broker, OIDC discovery, JWKS and Vault URLs. The policy is an admin allow-list, with link-local, metadata, loopback and private ranges denied by default on the team server, connect-time DNS validation, and no redirects. The Dialer supports direct, SOCKS5, HTTP CONNECT, ssh2, system OpenSSH and Kubernetes port-forward, with servername/SNI preserved. | User-supplied URLs make SSRF possible. Enterprise networks need tunnels. | engine/dialer |
| DC-44 | TLS trust is configured in code. Call tls.setDefaultCACertificates(bundled + system + org CAs). Concatenate per-profile CAs with the defaults rather than replacing them. Never pin the leaf certificate. Offer a CA import and server-name override. The insecure switch is explicit and shows a banner. | Electron ignores NODE_EXTRA_CA_CERTS once the NodeOptions fuse is off. Amazon MQ rotates certificates. IBM uses a private CA. | engine/TrustStore |
| DC-45 | Secrets are encrypted with AES-256-GCM, with a data key wrapped by safeStorage's async API or by @napi-rs/keyring forced to Secret Service. A master password is required on Linux basic_text or keyutils. The team server uses envelope encryption (KMS / Vault Transit). AMQP URIs, Authorization headers, JWT-bearing x- headers and shovel/federation URIs are redacted in logs and exports. No tokens in localStorage. | OS keystore limits. The official UI stores tokens in localStorage. | desktop, team server, logging |
| DC-46 | Electron release hardening: RunAsNode, NodeOptions and NodeCliInspect fuses off; ASAR integrity on; renderer sandbox and contextIsolation; strict CSP; navigation and window-open guards; an openExternal allow-list. A separate test-fused binary is used for Playwright and engine tests. The engine exits from its own SIGTERM handler with a ~2 s drain. | Playwright needs the inspect fuse. Electron 46 kill() no longer force-kills. | Electron packaging, CI |
| DC-47 | Run a public conformance suite in CI. It uses Testcontainers on Linux against RabbitMQ 3.13.7, 4.0.9, 4.1.8, 4.2.9 and 4.3.6, plus nightly alpha images (allowed to fail), crossed with Node 24.22, Node 26.12 and Electron's Node. It covers every settle path and every registry cell. The extended container exposes 5552 and 15692. The resulting compatibility matrix is published. | Nothing has been lab-tested yet. No Node client tests 4.3. Correctness is the headline differentiator. | CI, QA, website |
| DC-48 | Every protocol client sits behind a port interface (Amqp091Port, Amqp10Port, StreamPort, MgmtHttpPort). Contract suites run against amqplib and @cloudamqp/amqp-client. The management HTTP client is built in-house (undici + zod) with golden fixtures per broker version. | amqplib bus factor is about 1, and no typed TS management client exists. | engine/adapters |
| DC-49 | Pin toolchains exactly: TypeScript 6.0.x workspace-wide (Angular 22 requires >=6.0 <6.1), with TS 7 and @types/amqplib banned by lint and lockfile checks. Pin NestJS 12.1.x, Orval, amqplib and rhea exactly. Add no direct fastify version other than 5.12.5. Use @nestjs/swagger 12's standardSchemaConverter instead of nestjs-zod. Use Nx without @nx/nest for the engine. | AI agents install npm 'latest'. Peer ranges exclude the current majors. | monorepo, CI |
| DC-50 | A CI licence gate allows MIT, ISC, BSD-2/3, 0BSD, Apache-2.0 and 'MPL-2.0 OR Apache-2.0'. Named exceptions: elkjs (EPL-2.0) and CC-BY-4.0 for assets only. It hard-bans primeng >=22, @primeui/*, ag-grid-enterprise and apexcharts. THIRD_PARTY_NOTICES are generated per artefact. electron-builder is pinned >=26.16.1. | PrimeNG and AG Enterprise licences are incompatible with an Apache-2.0 tool. Notice obligations apply. | CI, packaging |
| DC-51 | elkjs ships unmodified as a separate worker asset under an elected EPL-2.0, with its licence text, a source pointer and a label. It is never inlined or re-minified into our bundles. dagre is the MIT fallback. | EPL-2.0 compliance for binaries; avoids creating a Modified Work. | UI build, packaging |
| DC-52 | UI component choices: Spartan/CDK/Aria + Tailwind 4; AG Grid Community behind an adapter, with our own context menu, clipboard and status bar; our own ESM Monaco 0.57 wrapper (not ngx-monaco-editor-v2); Cytoscape with WebGL feature detection and canvas fallback. | Licence and technical constraints are verified (PrimeNG proprietary; ngx-monaco AMD; WebGL limits). | Angular UI |
| DC-53 | Decoders implement detect / decode / fingerprint / replayPlan in a public TS plugin SDK, published with a machine-readable framework header registry. v1.0 ships the generic layer, MassTransit, Spring, NServiceBus, EasyNetQ and Celery. Delay and retry infrastructure (nsb.v2.delay-level-*, celery_delayed_*, mt-delay-*, delay_*_retry, {q}.delay.{ms}, {q}-retry, {q}.DQ) is recognised so that 'expired' deaths are not counted as failures. Pickle and PHP objects are never deserialized. | Framework formats vary, delay queues create misleading deaths, and unsafe deserialization is a code-execution risk. | DLQ operations centre |
| DC-54 | Queues managed by other systems are detected and read-only by default: ServiceControl or Particular-connector consumers on error/_error queues, Wolverine DLQ recovery, Kubernetes Topology Operator-owned objects, and provider-owned objects (AWS-*, ibm user, protected users). Detection uses /api/consumers, client_properties and fingerprints. NServiceBus nsb.{q}.delivery-limit policies are shown and never overridden. | Avoids fighting other operators or reconcilers, and avoids breaking NServiceBus startup. | DLQ centre, topology-as-code, policy editor |
| DC-55 | The HTTP /get adapter is product-aware. It always sends an explicit ackmode, plus "requeue": true for LavinMQ. On LavinMQ it never sends ack_requeue_true without requeue:true. It treats ApsaraMQ and other brokers where /api/overview returns 404 as AMQP-only mode. | LavinMQ ack_requeue_true means reject without requeue, and a missing ackmode means ack. | engine/mgmt client |
| DC-56 | The linter and upgrade advisor encode verified hazards. Broker: QQ DLQs at default limits on 4.3; x-delivery-limit=-1 on 3.13; QQs without a DLX; delayed-retry interplay with peeks; queue-master-locator; transient non-exclusive queues; global QoS; CQv1 arguments; legacy AMQP filter encodings; CHX E2E on 4.3.0-4.3.5; topic '' bindings without topic_binding_projection_v5; permitted deprecated features; delayed-message-exchange dependency before 4.3. Security: verify_aud=false; ANONYMOUS/guest; client-secret leak versions. It inspects only brokers the user connected to and never scans networks. | Verified hazards. SignPath's 'No hacking tools' clause rules out network scanning. | linter/advisor |
| DC-57 | Naming: a coined, non-rabbit brand with the descriptor 'for RabbitMQ®'. 'RabbitMQ' and 'RMQ' appear in no identifier (product, domain, npm scope, image, chart, org, repo, binary). No RabbitMQ logo or rabbit imagery. Broadcom attribution and a non-affiliation line in the README, About dialog and site footer. Listing via a factual one-line devtools.md PR. | Broadcom trademark guidelines. | branding, packaging, website |
| DC-58 | Distribution: macOS builds are Developer ID-signed and notarised from day one ($99/yr; own Homebrew tap first). The first-class Windows channel is Microsoft Store MSIX, plus GitHub NSIS/zip builds, with SignPath signing added once reputable (sign the app, build NSIS, sign the installer, then regenerate latest.yml and the blockmap). Linux ships deb/rpm with the AppArmor profile, plus AppImage with the Ubuntu 24.04 caveat; never default to --no-sandbox. npm (provenance), GHCR multi-arch images (cosign, SBOM) and an OCI Helm chart. | Gatekeeper and Homebrew rules, SmartScreen behaviour, signing eligibility for an EU individual. | release pipeline |
| DC-60 | Supported broker window: 3.13 through 4.3, with 4.4 readiness. Tier 1 is 4.2 and 4.3; Tier 2 is 3.13 and 4.1; 4.0 is best effort; alphas run nightly. Each new minor or patch is re-verified against the conformance suite before support is claimed. | Amazon MQ and IBM still run 3.13, Bitnami images are frozen at ≤4.1.x, and semantics change in patch releases. | support policy, CI, docs |
