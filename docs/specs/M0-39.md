# M0-39 Lab cells: DOWN paths: close, cancel-then-close, TCP loss, detach, consumer timeout (U-01 priority 1)

**Issue:** #35 · **Milestone:** M0 · **Wave:** M0-W2 · **Size:** M by label, about 1,200 changed lines by estimate for the slices recommended here (over the 800 limit as one change; see Slices and question Q-1) · **Owner area:** conformance, semantics (lane: evidence) · **trust:critical:** yes

## Goal

Measure, on the five pinned lab brokers (3.13.7, 4.0.9, 4.1.8, 4.2.9, 4.3.6), what a quorum queue does to a message whose holder goes away: a graceful channel close while holding, and a close after `basic.cancel`. Record the counter deltas (AC, DC), the position and the survival, so the registry's `close_while_holding` cells for AMQP 0-9-1 are confirmed or contradicted by lab evidence instead of by fact-sheet text. This is U-01 priority 1 ("on 4.3, graceful channel.close, connection.close and basic.cancel-then-close count as failed deliveries"). It serves invariant I-14, amendment A-20, blueprint 5.2, DC-16 and the planner's "never close while holding" rule (fact sheet b.8).

The issue title also names TCP loss, detach and consumer timeout. Those need a lab variant, an AMQP 1.0 DSL and long waits that do not exist yet; the spec splits them out as follow-up slices (below) and flags them. **This session writes a spec only.** The lab evidence and any change to a cell's `status` come from CI and a human (I-14); nothing here edits `testing/lab-evidence/**` or flips a status.

### The CF-DOWN-01 scenario (slice B)

AMQP 0-9-1, quorum queues (the registry cells are quorum only), the default delayed-retry setting (4.3 `disabled`, the only 4.3 cells that exist, OQ-392). One scenario for all five versions; the evidence differs by version, the scenario does not. A holder connection (`holder`) and the observing connection (`main`) are separate, so the observer survives the holder's close. Per case: declare a queue, publish `m1` and `m2`, hold `m1` on a channel of `holder`, make the holder go away, `awaitReady`, `observe` (the drain consumes the queue, so each measurement point has its own queue).

| Dimension | Values |
| --------- | ------ |
| Delivery limit | `unset` (no argument; the registry's 3.13 `unset` cells, on 4.x it is the default 20 and is not projected), `finite` (`x-delivery-limit` 2), `minus1` (`x-delivery-limit` -1) |
| Path | `get` (held by `basic.get`, no consumer), `consume-active` (consumer left active), `consume-cancelled` (consumer cancelled, then close: cancel-then-close) |
| Close | graceful channel close; the `finite` cases additionally run three hold-and-close rounds (limit crossing: does the (L+1)th return drop the message) |

That is 3 x 3 single-round queues plus 3 crossing queues (one per path on `finite`): 12 queues, all published with message ids only (a short fixed id as the body, no headers). Connection close (`connection.close`) is covered by the new `closeConnection` step in a `consume-active` case on `finite` (one more queue, 13 in all, 26 messages), because the registry row groups channel close, connection close and session end (fact sheet b.2); whether connection close needs its own id is Q-3.

### The projection (slice B)

What an artefact shows, by the key of the cell asking:

- `era 4.3`: `x-acquired-count` is AC, `x-delivery-count` is DC (absent while 0, read as 0). Project `deltaAC`, `deltaDC`.
- `era 4.0-4.2`: `x-delivery-count` **is AC** (fact sheet b.1); DC has no header. Project `deltaAC` only; **never infer `deltaDC`** from that header.
- `era 3.13`: `x-delivery-count` is DC; there is no AC header. Project `deltaDC` only; the registry's `deltaAC: 0` for 3.13 is not asserted from a missing header.
- `position`: from the `observe` position of `m1` in the single-round queue (0 is `head`, last is `tail`, otherwise `original`); `destructive` and `dlx-or-drop`: `m1` did not survive.
- `countsTowardLimit`: from the crossing queue (`finite`): `m1` gone after the (L+1)th return means `yes`; still there with the counters at 3 means `no` (or `if-dc-gt-limit`, which the 3-round data cannot tell apart from `yes`: Q-4); for `minus1`, `no` when `m1` survives, and `yes` with `destructive` when it was dropped on the first return (3.13).
- If the three paths of a case disagree, return `null` (the cell stays `unverified`), and `pathDivergence` names the difference so the cell spec prints it. A disagreement is a finding for a human, never resolved by choosing a path.
