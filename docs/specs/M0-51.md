## Goal

Give the web app its VS Code-style shell (activity bar, explorer tree, tabbed workspace with splits, bottom panel, status bar) on routes `/c/:cid/...`, persist the layout per connection profile through `layouts.get` and `layouts.put`, put every visible string behind Transloco keys, and enforce bundle budgets from day one (initial bundle at most 350 kB gzip). Serves feature EXP-01, DC-15 (honest wording over the new i18n files), ADR-021 (UI stack, DC-50 to DC-52; controlled reload on a failed lazy chunk) and blueprint 3.7 (skew handling) and 10.

This work package is too large for one landing. It is specified whole so the acceptance criteria stay together, and **section "Proposed split" cuts it into four landable work packages** (the issue asks for a split when it is picked up). The maintainer approves the split before any code is written.

## Findings that shape the spec (checked in the worktree on 2026-10-20)

- `apps/web` today holds `App` (an `<h1>` and a `<router-outlet>`), `app.config.ts` (zoneless defaults, `provideDesignSystem()`, an empty route table plus the dev-only gallery) and `main.ts`. It does **not** yet call `bootstrapPlatform()`, `providePlatform()` or `provideEngineData()`, so nothing can reach the engine. The shell wires them (M0-49 delivered the pieces).
- `@jsverse/transloco` is **not** in the `pnpm-workspace.yaml` catalog or in `tools/supply-chain/deps-allowlist.json`. Neither are `@angular/aria`, `@angular/cdk`, Spartan, Tailwind, `@lucide/angular` (OQ-340) or Playwright/axe (OQ-342). Adding a dependency is a protected-path change that a maintainer applies.
- `apps/e2e-web` does not exist (it is M0-60, which depends on this WP). The issue's `pnpm nx e2e e2e-web --grep=@shell` cannot run; section Verification gives the interim proof.
- `pnpm nx show project web` has the targets `build`, `serve`, `serve-static`, `test`, `lint`, `typecheck`. There is no `budgets` target. The production build has Angular `budgets` of 500 kb warning and 1 mb error (raw size, not gzip).
- Baseline, measured here with a production build: `main-*.js` 193 351 bytes raw, 59 876 gzip; `styles-*.css` 985 gzip. The initial bundle is about 61 kB gzip, so the 350 kB budget has room; Transloco, Angular router and forms-free shell code must stay inside it.
- `layouts.put` is a `command` with audit `attempt+outcome`. Through the real router every call is classed `prod` (OQ-283), so `layouts.put` answers 422 `GATE_BLOCKED` (`prod-lock`) unless the connection is armed (OQ-380). A layout save on an unarmed connection therefore fails today. This is the main risk to AC-5 and is listed as a question, not decided here.
- No action returns whether a connection is armed, and no health action exists. The status bar's "lock" and "engine health" segments have no data source yet (questions 6 and 7).
- The CSP the engine serves (`libs/engine/transport/src/static-ui.ts`) allows `script-src 'self'`, so translation JSON must be bundled chunks loaded by dynamic `import()`. Transloco's default HTTP loader would use `HttpClient`, which this app routes through the engine transport, and `fetch` is banned outside `libs/ui/platform` (`@app/no-direct-fetch`).

## Risks / questions

Open questions for the maintainer (none is decided in this spec; where the spec needs a default to be writable, it says "proposed"):

1. **Split.** Four parts as proposed, or three with `oversize-approved`? New ids and graph edges (see Proposed split).
2. **Transloco.** `@jsverse/transloco` 8.4.0 must be added to the catalog and allow-list by a maintainer (protected). Is its peer range compatible with Angular 22.2.3 (not verified here)? Is the bundled-JSON `import()` loader acceptable instead of the HTTP loader (the HTTP loader would pass through the engine transport and `no-direct-fetch` forbids a direct one)? Blocks Part A.
3. **ARIA, CDK and Spartan (OQ-340).** AGENTS.md section 9 asks for Aria and CDK patterns, but the packages are not available. Proposed default: a small local splitter, tabs and tree written to the WAI-ARIA patterns, kept in `apps/web/src/app/shell/` so they can be swapped for the aria wrappers later. Or add `@angular/aria` and `@angular/cdk` first and write 51c on them?
4. **Browser proof of "no horizontal page scroll".** Accept the interim proof (pure fit rules, style assertions, one recorded manual run) until M0-60 adds `@shell`, or pull the e2e-web scaffold (Playwright, axe-core in the catalog) forward?
5. **Layout saves on a locked connection (OQ-380, OQ-283).** Through the real router `layouts.put` answers 422 `GATE_BLOCKED` until the connection is armed, so a restart restores nothing on an unarmed prod-classed profile, which today is every profile. Options belong to the guardrail owner: exempt actions with risk `none` and no broker port, a declared local scope, or per-target classes. AC-5 passes against the fake engine and the golden-path HTTP behaviour, not yet against the real router. Also OQ-383: the audit cost of a save per resize; proposed idle delay 1 500 ms plus a flush when the page becomes hidden (best effort; the transport gives no guaranteed send on unload). Confirm the delay.
6. **Lock segment.** No action returns the arming state and `ConnectionProfile` has no read-only flag. What does the "lock" segment show, and where does it read from (`ops.arm` result held by M0-52, a new query, or the gate)? Proposed fail-closed default: `locked` unless the engine said armed. Also the wording: the label sits under a `lock` key (allowed to say "read-only" by the OQ-30 defaults); confirm it should say that at all, given DC-15.
7. **Engine health.** There is no health action. `LiveClient.state` is `idle` until something subscribes, and no topic exists for the shell. Proposed: derive from `LiveClient.state` (`ready` = ok, `reconnecting`, `down`) and show `unknown` while `idle`; does the shell open the live session itself (which topic?), or wait for the first feature to?
8. **UI build version for skew (AC-14).** Compare `LiveClient.engineVersion()` with the `engineVersion` seen at page load (from `meta.get` or `/bootstrap.json`, which `PlatformSetup` does not expose), or with a build-time constant (`define`) set by the release? Local dev builds would show `0.0.0` on both.
9. **Chunk failure detection and reload window (AC-13).** "ChunkLoadError" is the webpack name; the esbuild-based Angular builder fails with a `TypeError` on a failed dynamic `import()` whose message differs by browser. `isChunkLoadFailure` needs to be checked against a real removed chunk in Chromium, Firefox and WebKit. Proposed: one reload per 60 s, state in `sessionStorage`. Confirm the window.
10. **Budget method (AC-3).** Is 1 kB 1 000 or 1 024 bytes (proposed: 1 000, the stricter reading)? `ui.md` says "<= 350 kB gzip (error at 450)" while the issue says "at most 350": proposed `web:budgets` fails above 350 and the Angular raw-size `budgets` in `project.json` stay as a coarse backstop. Feature chunk limit 200 kB gzip as in `ui.md`. Which gzip level? How is "initial" defined (everything `index.html` references, including modulepreload)? Do translation chunks of the scopes count as initial (the `shell` and `system` scopes are, the proposal)?
11. **Layout document.** Proposed caps: 3 editor groups, 30 tabs per group, 60 tabs total, 512-character URL, 120-character label, all inside the 65 536-character contract limit. Schema is shell-owned and versioned (`version: 1`); a newer version is read as the default and not overwritten until the person edits. Stored per principal and profile, so web and desktop share it. Confirm the numbers and that sidebar/panel sizes are pixels (clamped on load) rather than ratios.
12. **Activity bar contents in M0.** Proposed: show only entries that have a registered route (Explorer in M0, Settings when its route exists), and Team only when `meta.get` says the mode is `team`, so nothing is shown that cannot open. The product list (Explorer, Messages, Streams, Topology, Admin, Metrics, Diagnostics, Team, Settings) is then reached as features land. Confirm; and confirm the explorer tree shows only the connection root node until M0-48/M0-54 supply a source (M0-48 is not a dependency of this WP).
13. **Key layout and allow-lists (OQ-30).** Three scopes (`shell`, `status`, `system`) as above, English only. No change to `tools/eslint-rules/src/rules/honest-wording.ts` defaults is proposed; any new allowed key is a loosening and needs approval.
14. **`ngCspNonce` (OQ-347).** Not in the issue scope; proposed: a separate issue. The served UI under the real CSP (which also sets Trusted Types) is not proven by this WP.
15. **Decision record.** ADR-021 addendum (proposed) or a new ADR for the layout document, the bundled-JSON loader and the budget method?
16. **Where the theme choice lives (OQ-348)** stays in the browser; this WP does not move it.

Other risks:

- The shell sets region sizes with style bindings (numbers from a clamped, validated layout). The served CSP allows `style-src-attr 'unsafe-inline'`; no engine text ever reaches a style. If that directive is tightened, sizes move to CSS custom properties set through the CSSOM.
- `@app/contracts` is compiled into the browser bundle by the shell (OQ-76). Part A measures it and, if the emitters inflate the bundle, asks for a subpath export before the budget is set.
- Hand-written splitter, tabs and tree duplicate what the aria wrappers will give; a bug here is an accessibility bug in every feature. The AC-10 test and the later axe run are the guard.
- `apps/web` is not `trust:critical`, but the status bar carries safety cues (environment, lock, verification). Part D should get a fresh-session `/review-wp` that looks at fail-closed behaviour (AC-12) even though CODEOWNERS sign-off is not required.
- Protected paths this work needs a human to change: `pnpm-workspace.yaml` (catalog), `tools/supply-chain/deps-allowlist.json`, and, if the lock-state ruling touches the guardrails, `libs/engine/kernel` (trust-critical, CODEOWNERS). No change to `.claude/`, hooks, `testing/lab-evidence/` or workflows is needed.
