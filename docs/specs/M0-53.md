# M0-53 ui-grid adapter: AG Grid Community with engine-windowed infinite model (S-14)

**Issue:** #49 · **Milestone:** M0 · **Wave:** M0-W3 · **Size:** M (issue label; the estimate below is larger, see "Size") · **Owner area:** ui, adapters, engine · **trust:critical:** no

## Goal

One grid adapter, `<app-data-grid>`, that wraps AG Grid Community 36.2.0 behind a contract the features can use without seeing AG Grid. It reads 100k rows through engine windows (block 200, at most 25 blocks resident) with flat memory, and it owns the features AG Grid keeps in its commercial tier: the context menu, the clipboard, the column chooser and the status bar. This WP also runs spike S-14 (AG Grid infinite model at 100k rows) and records its numbers.

Serves: DC-52 (AG Grid Community behind an adapter, our own menu, clipboard and status bar), DC-50 (no `ag-grid-enterprise`), EXP-02 (the grid the explorer uses, delivered by M0-54), ADR-021 and its S-04 addendum (CSP and Trusted Types rules for `ui-grid`), invariants I-6 (bounded), I-7 (no unbounded collection in the UI), I-10 (secrets stay write-only), I-13 (no silent loss) and I-11 (AG Grid imported only by `ui-grid`).

```ts
// @app/ui-grid (libs/ui/grid/src/index.ts). Shapes are proposals; see Q-6, Q-10.

/** Fixed by blueprint 10 and the issue. */
export const GRID_BLOCK_SIZE = 200;
export const GRID_MAX_BLOCKS = 25;

export interface GridSort {
  readonly columnId: string;
  readonly direction: 'asc' | 'desc';
}

export interface GridWindowRequest {
  readonly offset: number; // multiple of GRID_BLOCK_SIZE
  readonly limit: number; // at most GRID_BLOCK_SIZE
  readonly sort: readonly GridSort[];
}

export interface GridWindow<Row> {
  readonly rows: readonly Row[]; // at most `limit`
  readonly total: number | null; // null: not known (the end has not been reached)
}

export type GridRowChange<Row> =
  | { readonly kind: 'upsert'; readonly row: Row }
  | { readonly kind: 'remove'; readonly rowId: string };

/** What the explorer hands the grid. The grid never learns how the engine answers (M0-48, M0-54). */
export interface EngineWindowSource<Row> {
  readonly rowId: (row: Row) => string;
  window(request: GridWindowRequest, signal: AbortSignal): Promise<GridWindow<Row>>;
  /** Optional live feed (the `explorer.window` deltas). The grid reports the ids it shows. */
  watch?(visibleIds: ReadonlySet<string>): void;
  onChanges?(listener: (changes: readonly GridRowChange<Row>[]) => void): () => void;
}

export interface GridColumn<Row> {
  readonly id: string;
  readonly header: string; // already translated
  /** A function. A string expression is not representable (it would call `new Function`, ADR-021). */
  readonly value: (row: Row) => string | number | boolean | null | undefined;
  readonly format?: (value: ReturnType<GridColumn<Row>['value']>) => string;
  readonly width?: number;
  readonly minWidth?: number;
  readonly sortable?: boolean;
  readonly hidden?: boolean;
  readonly align?: 'start' | 'end';
}

export interface GridColumnState {
  readonly version: 1;
  readonly columns: readonly {
    readonly id: string;
    readonly hidden?: boolean;
    readonly width?: number;
    readonly pinned?: 'left' | 'right' | null;
  }[]; // array order is the display order
  readonly sort: readonly GridSort[];
}

export interface GridCellTarget<Row> {
  readonly rowId: string;
  readonly row: Row | undefined; // undefined while its block is not loaded
  readonly columnId: string;
}

/** `kind: 'gated'` renders the engine's decision; a missing or non-true `gate.enabled` is closed. */
export type GridMenuItem =
  | { readonly kind: 'plain'; readonly id: string; readonly label: string }
  | {
      readonly kind: 'gated';
      readonly id: string;
      readonly label: string;
      readonly gate: GateDecision | null | undefined;
    }
  | { readonly kind: 'separator' };

export type GridMenuProvider<Row> = (target: GridCellTarget<Row>) => readonly GridMenuItem[];

export interface GridKeybinding {
  readonly id: string;
  readonly chord: { readonly key: string; readonly ctrlOrMeta?: boolean; readonly shift?: boolean; readonly alt?: boolean };
  readonly run: (context: GridKeyContext) => void;
}

export interface GridStats {
  readonly blocksLoaded: number;
  readonly blocksFailed: number;
  readonly changesApplied: number;
  readonly changesDropped: number; // a change for an id that is not shown (counted, I-13)
  readonly refreshes: number;
  readonly copyTruncated: number;
}

// <app-data-grid> (selector `app-data-grid`, standalone, OnPush, signals)
//   columns        = input.required<readonly GridColumn<Row>[]>()
//   source         = input.required<EngineWindowSource<Row>>()   // a new object is a new query: purge and rebind
//   selectionMode  = input<'none' | 'single' | 'multiple'>('single')
//   selection      = model<ReadonlySet<string>>()                // row ids, not indexes
//   columnState    = model<GridColumnState | null>()
//   keybindings    = input<readonly GridKeybinding[]>()          // defaults: copy, open menu
//   contextMenu    = input<GridMenuProvider<Row> | null>()       // the issue's onContextMenu
//   labels         = input.required<GridLabels>()                // every word, already translated (no Transloco in ui-lib yet)
//   menuAction     = output<{ itemId: string; target: GridCellTarget<Row> }>()
//   stats          = signal<GridStats> (readonly)

// Consumed from other projects:
//   @app/contracts  GateDecision                         (the engine's gate, rendered as sent)
//   @app/ui-design  ThemeService (revision, token(), density)
//   ag-grid-community 36.2.0 (new dependency, protected-path change, see Risks)
```

## Out of scope

- The explorer screens, filter chips, the regex filter, saved views and the `inventory.query` / `explorer.window` wiring (M0-54). The grid exposes `columnState` and the sort model; storing a view is M0-54 (`views.*`, OQ-385).
- The engine side of windows (`svc-explorer`, S-13): M0-48.
- Client row model for up to about 5k rows with `applyTransactionAsync` (blueprint 10); this WP builds the infinite model only. A feature with a small list uses it with a source that answers in one block, or waits for a follow-up issue.
- Column filters (text, number, date, set), quick filter, grouping, tree data, pivot, range selection, Excel export, the AG Grid column menu and tool panels: either Enterprise or owned by the feature. The adapter turns the AG Grid menus off.
- "Select all" over an unbounded collection (I-7): not offered.
- Cell editors, custom cell renderers, row drag, master/detail.
- Translations: `labels` are inputs; Transloco arrives with M0-51.
- A dev-gallery page for the grid and a Playwright/axe spec (no `apps/e2e-web` yet, M0-60; OQ-342).
- A CI workflow or schedule for `perf:grid-100k` (`perf:smoke` / `perf:nightly` placement is a separate decision, Q-4).
- A lint rule against AG Grid string expressions (OQ-235, Q-3). The adapter makes them unrepresentable at its own boundary; a rule for the library's internals stays open.
- TanStack Table (the documented swap-in).
- Desktop `app://` behaviour (M2-P15).

**Open questions for the maintainer (none decided here).**

- **Q-1 (OQ-230).** Which packages: `ag-grid-community` only (the spike's choice; the component calls `createGrid` itself and the S-04 run proved it under the policy) or also `ag-grid-angular` 36.2.0 (the fact sheet lists "AG Grid Community + angular")? This spec assumes `ag-grid-community` only; the confinement pattern `ag-grid-*` covers both.
- **Q-2 (OQ-340).** `@angular/aria` and `@angular/cdk` are not in the catalog, so "our Aria menu" cannot use `@angular/aria` yet. This spec writes the menu by hand to the WAI-ARIA menu pattern and positions it with CSSOM (`[style.--x]` style bindings, which the CSP allows; no CDK overlay), behind `GridContextMenu` so it can swap to the Aria menu later. Alternative: wait for the packages. Which?
- **Q-3 (OQ-235).** Lint rule against AG Grid string expressions in `ui-grid`? The adapter's `GridColumn.value` is function-only (AC-10), so features cannot pass one; the question is only the library's own code. Undecided.
- **Q-4.** `perf` project and `perf:grid-100k`: (a) `apps/perf` does not exist and no perf bench has landed (`perf:messageport-p95` is also absent), so this WP creates it unless another does first; (b) the browser comes from the machine (`PERF_BROWSER`), as in the S-04 harness; Playwright is not in the catalog, so the driver speaks the DevTools protocol itself (about 300 lines, not a new dependency); (c) definitions to confirm: "at least 55 fps" as the mean over the scroll window or a low percentile; "no long task above 50 ms" counted on the main thread from the trace; flat memory as 1.15 times after a forced GC; the density (comfortable and compact) and viewport (1280x720) tested; CI runner class and whether it runs in `perf:smoke` on PRs or only `perf:nightly` (execution plan section 4). Headless software rendering on shared runners may not reach 55 fps; that would be a measured S-14 finding, not a reason to loosen the test silently.
- **Q-5 (size).** See "Size": about 1,800 to 2,300 changed lines against the 800 limit. Split, or add `oversize-approved`?
- **Q-6.** The `EngineWindowSource` shape is this spec's proposal because `inventory.query {kind, filter, sort, window}` and the `explorer.window` topic (M0-48) do not exist yet and M0-53 does not depend on M0-48. M0-54 writes the adapter from `inventory.query`/`explorer.window` to this interface. Should M0-48 define the window shape first (offset/limit versus cursor), and should the type live in `ui-grid` (this spec) or in `ui-data`?
- **Q-7.** The blueprint budget table says "50k-row grid >= 55 fps"; the issue and the design entry say 100k. This spec follows the issue (the stricter). Confirm.
- **Q-8.** Row height: `scale-first` says fixed 24 px; the design tokens have comfortable rows at 32 px and compact at 24 px (OQ-343, still open). The grid follows the density token (AC-17) and does not choose a number.
- **Q-9.** Clipboard policy: (a) cap on copied rows (proposal: 5,000, equal to the 25 x 200 resident rows); (b) spreadsheet formula injection: a value that starts with `=`, `+`, `-` or `@` pasted into a spreadsheet can run as a formula; prefix it or copy it verbatim? (c) `navigator.clipboard.writeText` needs a secure context and a user gesture; `PlatformBridge` has no clipboard method, and `app://` behaviour is M2-P15. AC-11 pins a cap and an error path but not (b).
- **Q-10.** `GridKeybinding`: the command registry (tinykeys) is not landed and tinykeys is not in the catalog, so the chord is a small structure of our own and the registry can feed it later. Confirm the shape, or defer `keybindings` to the registry WP.
- **Q-11.** Register an explicit list of Community modules (infinite row model, row selection, column auto size and the like, chosen when the spike runs) instead of `AllCommunityModule`, to protect the feature-chunk budget (<= 200 kB gzip) and to make AC-3 a statement about names? The S-04 harness used `AllCommunityModule`.
- **Q-12 (OQ-231, OQ-233, OQ-347).** The CSP rules for the grid (`styleNonce`, function getters only, no `unsafe-eval`) come from the ADR-021 addendum, still marked proposed. Where does the nonce come from at run time: the `csp-nonce` meta tag read by the adapter, or a token the app provides? `ngCspNonce` is not set on the web shell yet (OQ-347). AC-16 runs under the harness policy, not the real shell.
- **Q-13 (OQ-342).** No Playwright or axe yet, so accessibility is proved by role, name, focus and live-region assertions in component specs, not by axe. AG Grid's own ARIA grid roles are relied on and not re-tested. Accept until M0-60?
- **Q-14.** The `library` generator creates `libs/<dir>/<name>` with project name equal to the directory name, but the repository's UI projects are `ui-design` at `libs/ui/design` and the alias is `@app/ui-design`. To get project `ui-grid` at `libs/ui/grid`, run the generator (`pnpm nx g @app/generators:library grid --type=ui-lib --importPath=@app/ui-grid`, to be confirmed with `--help`) and rename the project in `project.json`, as `ui-design` evidently did. If the generator cannot produce this, stop and ask; do not hand-write the scaffold.
- **Q-15.** AG Grid ships its own English strings (overlays, aria labels). The adapter forwards every one it can show to `labels` through the locale-text hook; any string it cannot intercept is a gap the S-14 run must list. Honest wording applies to every label (`@app/honest-wording`).
- **Q-16.** Where S-14 is recorded: a new `docs/architecture/s-14-ag-grid-infinite-100k.md` plus an ADR-021 addendum (this spec), or only an addendum?

**Uncertainties the first run must settle (S-14, not questions).**

- Whether AG Grid 36.2.0's infinite model keeps a selection across block eviction when `getRowId` is set, or the adapter must re-apply `selection` itself (AC-15 assumes the adapter owns the set).
- The exact trace events for frame counting and long tasks under headless Chrome and Edge.
- Whether the theme bridge works through the AG Grid theming API under the nonce (the S-04 run saw 25 injected `<style>` elements, all nonced) and what `ThemeService.token()` values it needs.
- jsdom rendering of AG Grid with virtualisation off: if it is not stable, the rendering ACs (AC-9, AC-13) move to the harness and the spec is amended.
- The `esbuild` copy to use for `bundle-check`: it is a dependency of `@angular/build`, not of the workspace (pnpm strict), so the script resolves it from there as the S-04 build does.

**Invariants and constraints this WP must keep.** I-6 and I-7 (block and cache bounds, copy cap, bounded counters); I-10 (the grid copies and renders what the engine sent, already masked; it logs no cell values); I-11 (only `libs/ui/grid` imports `ag-grid-*`); I-13 (a failed block, a dropped change, a truncated copy and an unknown total are each shown or counted, never silent); no `innerHTML`, no `bypassSecurityTrust*`, no direct `fetch`; no raw template text (labels are inputs); the UI never computes authorisation (menu gates are rendered as sent, fail closed). Honest wording: the grid has no read or peek wording of its own; labels come from the feature.
