# M0-59 Local web mode: serve and container mode (PLAT-08, ADR-016)

**Issue:** #51 · **Milestone:** M0 · **Wave:** M0-W3 · **Size:** M · **Owner area:** platform (`apps/engine`) · **trust:critical:** yes (a listener, the token, the Host and Origin allow-list)

Status: working spec, written under the agile-mode waiver of the approval stop. Checked against `origin/main` at `7746a33`. Assumptions are rows OQ-810 to OQ-818 in `docs/open-questions.md`.

## Goal

Make the local web mode a documented, tested delivery mode: the engine bundle serves the built web UI, binds loopback by default, prints a launch URL with the token in the URL fragment, opens a browser only when asked, keeps its data in a data directory under the single-instance lock, and has an explicit container mode (ADR-016) with a mandatory token, a loopback-only publish documented, a banner that prints the exact `docker run -p 127.0.0.1:...` line, and a healthcheck. Serves PLAT-08, DC-36 (and its container exception), ADR-016, amendment A-12 and invariants I-1, I-9, I-10, I-12.

## What the code gives and what it does not

| Fact | Where | Consequence |
| --- | --- | --- |

## Files & interfaces

**Create**

- `apps/engine/src/modes/web-binding.ts`: pure resolution of where and how the local web mode listens (runtime, host, port, public origins, token source, data dir, key file, open). Mode logic lives in `modes/` (ADR-001).
- `apps/engine/src/modes/web-binding.spec.ts`, `apps/engine/src/modes/local-web.spec.ts`: unit and in-process socket tests.
- `apps/engine/src/entry/open-browser.ts` and `.spec.ts`: the opener with an injected spawn, clock and file system.
- `apps/engine/scripts/healthcheck.mjs` and `apps/engine/src/healthcheck.spec.ts`: the container healthcheck client (`node healthcheck.mjs`, exit 0 only on `{"status":"ok"}` from `/healthz`), copied into the image by M0-64.

**Modify**

- `apps/engine/src/entry/args.ts`: new flags `--host=`, `--public-origin=`, `--token-file=`, bare `--open` and `--no-open`.
- `apps/engine/src/entry/start.ts`, `entry/main.ts`: pass `env` and an `openBrowser` port to the mode and print the mode's notice lines before the launch URL; open the browser after the listener is up when asked.
- `apps/engine/src/modes/local.ts`, `modes/types.ts`: use the binding; `ModeHost.env`, `ModeBoot.notice`, `ModeBoot.openOnReady`.
- `apps/engine/src/compose-core.ts`: `ModeProfile.listener.containerNamespace` (the ADR-016 exception); a bind outside loopback is allowed only with it and at least one authenticator.
- `apps/engine/scripts/serve.mjs`: extra command-line arguments are passed to the bundle (`pnpm nx run engine:serve -- --open`).
- `apps/engine/README.md`, `docs/runbooks/run-locally.md` (new section: local web mode and container mode), `docs/open-questions.md`, `AGENTS.md` section 7 (healthcheck and container-mode proof commands).

**Interfaces**

```ts
// Command line (strict, --name=value; --open and --no-open are the only bare flags)
//   --host=<127.0.0.1|::1|localhost>   native: loopback only. container: 0.0.0.0 (default), ::, or loopback
//   --port=<0..65535>                  native default 0 (system pick); container default 8765
//   --data-dir=<path>                  native: required; container: default /data
//   --token-file=<path>                the launch token, read from a file (32..512 chars of A-Za-z0-9_-)
//   --public-origin=<origin[,origin]>  loopback-form origins only until real auth + https exist (A-12)
//   --open | --no-open                 open the default browser at the launch URL (native only; default no)
// Environment (read with loadConfig, prefix APP; a flag wins over the variable)
//   APP_RUNTIME=container|native  APP_PORT  APP_HOST  APP_DATA_DIR  APP_KEK_PATH  APP_PUBLIC_ORIGIN
//   APP_TOKEN  or  APP_TOKEN_FILE (a file secret)   APP_UI_DIR  APP_LOG_LEVEL

export interface WebBinding {
  readonly runtime: 'native' | 'container';
  readonly host: string;
  readonly port: number;
  readonly publicOrigins: readonly string[];
  readonly dataDir: string;
  readonly kekFile?: string;
  readonly uiDir?: string;
  readonly token: { readonly value: string; readonly source: 'generated' | 'env' | 'file' };
  readonly open: boolean;
}
export function resolveWebBinding(args: EngineArgs, env: Readonly<Record<string, string | undefined>>, readFile?: (path: string) => string): WebBinding;

// compose-core.ts
listener?: { host: string; port: number; /** ADR-016 only */ containerNamespace?: true };
// modes/types.ts
ModeHost.env; ModeBoot.notice?: (address) => readonly string[]; ModeBoot.openOnReady?: boolean;
```

## Risks / questions

- OQ-810: the issue's CLI scope (`apps/cli`) and verification do not exist; the engine bundle carries the flags. OQ-811: flag names and the `--no-open` default. OQ-812: environment variable names under the `APP` placeholder prefix. OQ-813: a token in `APP_TOKEN` is visible in `docker inspect`; a file secret is recommended and the env form is allowed because the issue asks for it. OQ-814: non-loopback `PUBLIC_ORIGIN` is refused (A-12) although the issue AC says it is "accepted". OQ-815: a generated token in container mode appears in `docker logs`.
- Protected paths: none needed. `pnpm-workspace.yaml`, the allow-list, CODEOWNERS and the image workflow are untouched.
- Binding `0.0.0.0` in a test may raise an operating-system firewall prompt on a developer machine; the in-process container tests and the smoke container case bind the wildcard on a system-picked port and are reached through `127.0.0.1` (OQ-818).
- Estimated changed lines: about 1,250 including tests, over three code slices.
