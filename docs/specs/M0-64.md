# M0-64 Container image (PLAT-09, ADR-016)

**Issue:** #57 · **Milestone:** M0 · **Wave:** M0-W4 · **Size:** M · **Owner area:** platform (`packaging/docker`, `.github/workflows/image.yml`) · **trust:critical:** no

Status: working spec (landed; the live results of the first workflow run are in "Result of the first run" below), written under the agile-mode waiver of the approval stop (the issue already carries two Given/When/Then criteria and exact verification commands). Checked against `origin/main` at `ef2587e`. Assumptions are rows OQ-1486 to OQ-1491 in `docs/open-questions.md`.

## Goal

A distroless, non-root, multi-architecture image of the single-user web app that runs the engine bundle in container mode (ADR-016), with a healthcheck, a SIGTERM drain, a compose file, and a workflow that builds natively on amd64 and arm64, scans with Trivy, and (when a maintainer enables publishing) pushes by digest with SBOM and provenance, merges one manifest list and signs it keyless with cosign. Serves PLAT-09, ADR-016, amendments A-12 and A-26, invariants I-1, I-9, I-10 and I-12.

## Out of scope

- The release workflow, the order of release stages, attaching the image digest to the release, and opt-in update checks (M0-68, issue #58).
- The npm CLI package, THIRD_PARTY_NOTICES and the SBOM from the esbuild metafile (M0-65). The image carries the repository `LICENSE`, `NOTICE` and the web build's `3rdpartylicenses.txt`; the engine bundle's notices join when M0-65 generates them.
- Helm chart, team-server compose with Postgres (M3), desktop (M2).
- A network-less run of the whole image under a deny-all egress proxy (OQ-400); the live test only proves that the image works with `--network none`.
- Choosing the product or image name (ADR-029, A-22). Publishing stays off until the `IMAGE_NAME` repository variable is set.

## Verification

```sh
pnpm nx run docker:build          # needs a Docker daemon; skips loudly without
pnpm nx run docker:test           # static checks; live checks when a daemon answers
pnpm nx run-many -t lint -p docker
pnpm nx run supply-chain:actions-pinned
pnpm nx run supply-chain:gates
pnpm format:check
pnpm nx affected -t lint typecheck test --base=origin/main
```

Not runnable on the machine that wrote this: `docker:build` and the live half of `docker:test` (no daemon), every `workflow` row, and the real arm64 build. What was done instead: the build context was reproduced from `Dockerfile.dockerignore` into a clean directory, `pnpm install --frozen-lockfile` and `pnpm nx run-many -t build -p engine web` were run in it, the runtime tree was assembled with the Dockerfile's own copy commands, and that tree was started with `APP_RUNTIME=container` (health 200, 401 without the token, 200 with it, the web index served, the image's healthcheck exit 0). That proves the build stage and the layout, not the container.

## Result of the first run

The first push to `main` (`a1b20d5`) started `image.yml` on the repository's runners (run 40315920496): `verify (amd64)` and `verify (arm64)` both succeeded. On each, the image built natively, `node --test` ran 35 tests with 0 failures and 0 skipped (the 30 static checks and the live AC-7 to AC-11), and Trivy found no CRITICAL vulnerability or secret. `push` and `merge` were skipped because `IMAGE_NAME` is not set, so the push by digest, the SBOM and provenance attestations, the manifest list, the cosign signature and its verification (AC-13 and the signing half of AC-6) are **still unproved**.

## Risks / questions

- OQ-1486: the base images are pinned by digest read from the registries on 2026-10-26; the distroless image's Node patch version is not visible from the tag and may differ from `.nvmrc` (24.22.0). The contract is `engines >=24.15`.
- OQ-1487: the image name and who may publish (A-22). The workflow takes the name from the repository variable `IMAGE_NAME`.
- OQ-1488: Trivy fails on any `CRITICAL`, fixed or not (the AC says "no CRITICAL"). A distro package with no fix would block the image; the choice of `ignore-unfixed` or a reviewed `.trivyignore` with an expiry is the maintainer's.
- OQ-1489: the tag trigger and `GITHUB_TOKEN` (see the table). Needs M0-68 or a token change.
- OQ-1490: `docker diff` empty and the ownership of a `COPY --chown`-created `/data` are expected from Docker's behaviour and are checked by the live tests only; if either fails on first run, fix the Dockerfile, not the test.
- OQ-1491: the pnpm binary is installed with `npm install --global pnpm@<version>` (integrity from the registry's lockfile-less install). A corepack pin with a hash is stronger and needs a `packageManager` hash, a protected-path change in practice.
- Protected paths: none touched. No dependency added. `.github/workflows/image.yml` is not protected; `release*.yml` is untouched.
- Trust-critical: no (no listener or token logic changes), but the signing job is the one that can hold an OIDC token; a second reader should look at `image.yml` before the first publish.
