## Goal

A **pure** function that answers "if I publish this message to this exchange, which queues get a copy, and why?": `simulate(topology, publish)` evaluates direct, topic, fanout and headers exchanges, exchange-to-exchange (E2E) chains, alternate exchanges (AE), the default exchange and the CC/BCC headers exactly as the broker's own routing code does. Every queue comes with the **path** that reached it (each hop names the exchange, the binding and the matching rule); an unroutable publish says what happens to it (returned with `basic.return` when `mandatory`, dropped otherwise); a loop in the E2E graph ends the walk and is reported; the walk is bounded and every cut is counted (I-6, I-13); an exchange type the library cannot model (consistent-hash, delayed-message, recent-history, ...) makes the answer an honest **lower bound** ("indeterminate"), never a guess.

Serves: TOP-02 (routing simulator core), DC-19 (AE and default-exchange blind spots are explainable), the DLQ and topology views that M1-03 and later work packages build on; invariants I-3 (no broker version is compared: the matching rules are the same on 3.13.7 to 4.3.6 and the only version-dependent fact, the `#` limit on a new topic binding, is data in the registry), I-6 and I-13 (bounded work, counted truncation). Blueprint section on the topology model and routing; fact sheet sections on routing and taps.

## Rules

**R1 Pure and total.** No I/O, no clock, no randomness, no global state; the input is never mutated (it may be deeply frozen); a result is a new value; the same input gives the same output, with queues sorted by name and paths in walk order. `simulate` never throws for a topology or publish that has the right shape: a problem is a field of the result (`refusal`, `notes`, `truncation`).

**R2 Faithful walk.** The walk is the broker's: an exchange is expanded once; the AE is used if and only if the exchange's own destination list is empty (before existence checks); an unseen existing exchange destination is expanded; a missing one is skipped with a note; a queue destination absent from the topology is not delivered to and is noted (`dangling-destination`). The default exchange has no AE and no bindings. The walk is breadth-first so the **first** path to an exchange is a shortest one.

**R3 Paths.** `paths` has one entry per distinct (final hop) that delivers to a queue: `{queue, hops[]}`; a hop is `{exchange, how: 'default-exchange' | 'binding' | 'alternate-exchange', destination, destinationType, binding, rule}`, where `rule` says why the binding matched (`direct` with the key and the key's source `routing-key | cc | bcc`; `topic` with the pattern and the key; `fanout`; `headers` with the mode and the argument names that decided; `default-exchange` with the key). The prefix of a hop chain is the shortest path to its exchange. At most `maxPathsPerQueue` paths are kept per queue; the rest are counted.

**R4 Honest unknown.** An exchange whose type is not direct, fanout, topic or headers is **not expanded**. It is listed in `unknownExchanges` with its type, a hint code (`hash-single-destination`, `random-single-destination`, `delayed`, `recent-history`, `unmodelled`) and its AE. The result is then `exact: false`: the queues found are a lower bound, and `outcome` is `indeterminate` when none was found (never `unroutable`).

**R5 Bounded work (I-6, I-13).** Limits (all counted, with defaults): `maxDepth` 64 exchange hops, `maxExchanges` 1,000 expanded, `maxBindingsScanned` 200,000 binding evaluations, `maxQueues` 10,000, `maxPathsPerQueue` 8, `maxLoops` 16, `maxTopicWords` 256 per key and pattern. Hitting a limit never stops silently: `truncation` carries a count per limit, `exact` is false, `notes` has a `truncated` entry, and `outcome` is `indeterminate` if nothing was found. A topic match is O(pattern words x key words) (a table, no backtracking), so no key can make it exponential.

**R6 Loops.** The edges the walk takes between exchanges (bindings and AE hops, including edges to exchanges already seen) are checked for cycles with a strongly-connected-component pass (iterative, bounded by the expanded exchanges); each loop is reported as the sorted list of its exchanges. The walk itself is unaffected (R2); a loop is information (a publish through it still ends, and delivers once).

**R7 Outcome.** `outcome`: `routed` (at least one queue and exact or not), `unroutable` (exact, no queue), `indeterminate` (not exact and no queue), `refused` (404 unknown exchange, 403 internal exchange, 406 bad CC/BCC type; no walk). `fate` (only for what the broker does): `delivered`, `returned` (unroutable and `mandatory`), `dropped` (unroutable, not mandatory), `refused`, `unknown` (indeterminate). `unroutable` is true only for the exact empty case. `usedAE` is true when at least one AE hop was taken.

**R8 Notes are codes, not prose** (the UI words them): `invalid-x-match`, `dangling-destination`, `missing-exchange`, `ignored-default-exchange-binding`, `keys-ignored` (CC/BCC keys on a fanout or headers exchange), `bcc-stripped`, `duplicate-exchange`, `truncated`. Each carries the exchange and a short detail value (a name or a number), never English text, never a broker message.

**R9 Binding validation** (`validateBinding(exchangeType, binding, rules)`): the checks the broker makes when a binding is created and that a planner needs before it sends one: headers `x-match` must be a string `all`, `any`, `all-with-x` or `any-with-x` (anything else is rejected); topic key with more `#` words than `rules.topicMaxHashWildcards` (when set) is rejected. The limit is an argument; where it comes from (the registry capability `topicBindingHashWildcardLimit`, slice C) is the caller's business, so no version is compared here (I-3).
