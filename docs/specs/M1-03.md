Status: working spec, agile mode (working defaults, every assumption a row of `docs/open-questions.md`, "Spec questions: M1-03", ids OQ-1300 and up). ## Goal

Add the **dead-letter half** of the routing simulator to `libs/shared/routing`, still pure:

1. `deadLetterPath`: "if a message dies in this queue, for this reason, where does it go?" It reuses `simulate` for the dead-letter exchange, follows the chain through queues that dead-letter again, and ends honestly (delivered, dropped by the cycle rule, indeterminate).
2. `dlxLoops` (cycles): finds the cycles of the queue-to-queue dead-letter graph and says which are **drop loops** (no death in the cycle can be a rejection, so the broker drops the message when it comes back to a queue it already died in).
3. `dlxSources(topology, queue)`: every queue whose dead letters can arrive in `queue`, with that source's delivery limit, plus `complete` and `unknownReasons[]` (amendment **A-2**) so that an empty or partial list never reads as "no hazard".
4. Notes for exchanges whose choice among destinations the simulator cannot predict: `x-consistent-hash` gives a "non-deterministic weight share" note, `x-random` a "random single destination" note.

Serves: DLQ-01/02/03/08 inputs, **W-OVERLIMIT** and `PeekPreflight.dlxSources` (core-interfaces, blueprint 5.4), DC-07, DC-16 (the carry-over reading of a source's limit); ADR-010; invariants I-3 (no broker version is compared here), I-6 and I-13 (bounded work, counted cuts, no silent "complete"). Consumers that come later: M1-12 (peek planner), M1-20 (svc-topology actions), M1-33 (replay planner), M1-51 (DLQ centre).

## Rules

**R1 Pure and total.** Same as M1-02 R1: no I/O, no clock, no randomness, input never mutated, results sorted and deterministic, nothing thrown for a well-shaped input. A problem is a field (`unknownReasons`, `notes`, `truncation`).

**R2 The topology grows, additively.** `TopologyQueue` gains optional fields, all absent in M1-02 inputs (so every M1-02 test stays valid):

```ts
interface TopologyQueue {
  readonly name: string;
  // new, all optional:
  readonly type?: 'classic' | 'quorum' | 'stream';
  /** Resolved: argument over policy (M1-01). `unknown` = a policy that could not be read decides it. */
  readonly deadLetter?: DeadLetterSetting;       // absent = none
  readonly messageTtlMs?: number | null;         // resolved min(arg, policy); null/absent = no TTL
  readonly maxLength?: number | null;
  readonly maxLengthBytes?: number | null;
  readonly overflow?: 'drop-head' | 'reject-publish' | 'reject-publish-dlx' | null;
  readonly deliveryLimit?: DeliveryLimit;        // from @app/semantics; absent = unknown (never "unlimited")
  /** A consumer may reject (nack/reject without requeue). Absent = not known to. */
  readonly rejectable?: boolean;
  /** The queue holds messages whose broker x-death lists these source queues (A-2). */
  readonly heldDeathSources?: readonly string[];
}
type DeadLetterSetting =
  | { readonly status: 'set'; readonly exchange: string; readonly routingKey?: string | null; readonly strategy?: 'at-most-once' | 'at-least-once' }
  | { readonly status: 'unknown'; readonly why: UnknownReasonCode };
```

`deliveryLimit` absent is **unknown**, not unlimited (the same default as `isDoomed`: unreadable limit is the dangerous reading). The type comes from `@app/semantics` (`DeliveryLimit`, `type:pure`, import allowed).

**R3 `deadLetterReasons(queue)`** (`ttl.ts`, `dlx.ts`): the reasons a queue can dead-letter, as a sorted list from the closed set `rejected | expired | maxlen | delivery_limit`: `rejected` only if `rejectable === true`; `expired` if `messageTtlMs` is a finite number >= 0 (a per-message `expiration` cannot be seen in a topology: OQ-1303); `maxlen` if a length limit is set and `overflow` is `drop-head`, `reject-publish-dlx` or absent; `delivery_limit` if `type = 'quorum'` and the limit is `finite` or `unknown`. A queue with `deadLetter` absent has no reasons that go anywhere (it drops). Queue `expires` (queue TTL) deletes the queue and dead-letters nothing; it is not a reason.

**R4 `deadLetterPath(topology, from, options)`** (`dlx.ts`). `options` carries the reason (default: every reason in `deadLetterReasons(from)`, one path each), the original routing keys when known (`keys?`: publish key, CC and BCC), and limits. Each **step** is `{from, reason, exchange, keys: string[] | 'original', result: RoutingResult (the M1-02 result for the DLX), targets: string[], dropped: string[] (removed by the cycle rule), strategy}`. With a fixed dead-letter routing key or known `keys` the walk is exact (`simulate` with `PublishInput{exchange, routingKey}` and the other keys passed as the `CC` header so that every key is routed; a fixed key is exactly one key). With `keys: 'original'` and a routing-key-dependent exchange the step is `may-reach`: the exchange's bindings are all candidates (direct: any binding; topic: any pattern; fanout and headers: as `simulate`), marked `certainty: 'possible'`. The path then continues from each target that itself dead-letters, breadth first, one expansion per queue; the **first** path to a queue is a shortest one. Ends: `terminal` (target with no dead letter), `dropped-no-dlx` (a queue with no DLX: the message dies there), `dropped-cycle`, `indeterminate` (unknown setting, unknown exchange, or a cut), `truncated`.

**R5 `findDlxLoops(topology)`** (`cycles.ts`). Nodes are queues; an edge `A -> B` exists when `deadLetterPath`'s one-step reach from A includes B for at least one reason (may-reach included, marked). Cycles come from an iterative strongly-connected-component pass (the M1-02 `findLoops` works on any named edges and is reused). A loop is `{queues (sorted), kind}`: `drop-loop` when **no** queue in it has `rejectable === true` (so no death in the cycle can be a rejection and the broker drops the message when the cycle closes, on the first lap for a self-loop), `retry-ring` when at least one has (a delay/retry pattern; it keeps only messages that were rejected somewhere in the ring; informational), and `possible` is set when any edge is may-reach. A self-loop (queue dead-letters into an exchange that routes back to itself) is a loop of one.

**R6 Hash and random notes** (`hash-random-notes.ts`). New note codes, appended to `NoteCode` (additive): `non-deterministic-share` (consistent-hash: one of the bound queues, chosen by hash and weight; detail = the number of candidates) and `random-destination` (x-random). Both come with `candidates: string[]` (the queues bound to the exchange, sorted, bounded by `maxQueues`), never a chosen queue. `deadLetterPath` and `dlxSources` treat every candidate as **may-reach**. The M1-02 behaviour (exchange listed in `unknownExchanges`, `exact: false`) is unchanged.

**R7 `dlxSources(topology, queue, context?)`** (`dlx-sources.ts`, A-2). Returns

```ts
interface DlxSourcesResult {
  readonly sources: ReadonlyArray<{
    readonly queue: string;
    readonly limit: DeliveryLimit;           // the SOURCE's limit, from the source's deliveryLimit (absent -> unknown)
    readonly certainty: 'definite' | 'possible';
    readonly via: readonly string[];         // the dead-letter exchange chain, first path
    readonly reasons: readonly DeadLetterReason[];
  }>;
  readonly complete: boolean;                // false if ANY unknownReason exists
  readonly unknownReasons: readonly UnknownReason[];   // closed codes + subject, sorted, deduplicated
  readonly truncation: DlxTruncation;
}
```

A source is any queue with `deadLetter.status = 'set'` whose one-step reach (R4, may-reach when the key is open) contains `queue`; chains through intermediate dead-lettering queues are **not** sources of `queue` (they are sources of the intermediate); the direct source is what feeds the counter. `complete` is false, and `unknownReasons` names why, when any of: `policy-unreadable` / `operator-policy-unreadable` / `stats-fields-missing` (passed by the caller in `context.gaps`: the topology cannot know what it could not read), `dead-letter-unknown` (a queue with `deadLetter.status = 'unknown'` could feed `queue`: every such queue is listed as a possible source with limit `unknown`), `source-limit-unknown` (a source whose `deliveryLimit` is absent or `unknown`), `unknown-exchange-in-path` (a plugin exchange on a dead-letter route), `held-death-source-missing` (the target holds x-death entries from a queue that is not in the topology or not listed as a source: the broker-written `heldDeathSources` of `queue` count as DLX sources even if no current source exists), `other-clients-may-declare` (always present when `context.gaps` says the principal cannot see all queues of the vhost), `truncated`. **An empty `sources` with `complete: true` is the only "no hazard"**; every other combination is a hazard the consumer must treat as finite-unknown L (the consumer's rule, A-2; this WP provides the data). A queue name in `heldDeathSources` that is not in the topology becomes a `possible` source with limit `unknown`.

**R8 Bounded (I-6, I-13).** New limits in their own `DlxLimits` with `DEFAULT_DLX_LIMITS` (so `SimulationLimits` and its M1-02 tests stay untouched; defaults, counted, never silent): `maxDlxSourcesScanned` 10,000 queues examined, `maxDlxSteps` 1,000 path steps, `maxDlxPaths` 64 paths per start, `maxDlxLoops` 16, `maxDlxCandidates` 1,000 per hash/random exchange. Each cut adds to `DlxTruncation`, sets `complete: false` (sources) or `exact: false` (path) and adds a `truncated` reason/note. The per-source reach test reuses one `simulate` index (`indexTopology`) so a scan over N sources is O(N x bindings of their DLX), not N full builds.

**R9 Notes and reasons are codes** (as M1-02 R8): no English, no broker text.

## Risks / questions

Working defaults are in use; none blocks the first manual test. Ids in `docs/open-questions.md`, "Spec questions: M1-03":

- OQ-1300 Where the new code lives and the `TopologyQueue` growth (additive optional fields; a separate `DeadLetterTopology` type was rejected because `simulate` and the sources scan would then take two inputs).
- OQ-1301 An absent `deliveryLimit` is `unknown`, not `unlimited` (the safe reading, as `isDoomed`).
- OQ-1302 How the topology says "a consumer may reject": `rejectable`, default absent = not known to.
