# M1-09 Capture store: encrypted captures, blobs, FTS5 ingest/search worker (MSG-10 core)

**Issue:** #94 · **Milestone:** M1 · **Wave:** M1-W1 · **Size:** M (split into five slices of at most 600 changed lines each, A to E, tests included) · **Owner area:** engine, persistence, messages · **trust:critical:** no tag (the new library carries none), but the data is user data encrypted at rest: a security review is recommended before any action exposes it

Working spec written under the maintainer's agile mode (no approval stop). Questions decided by default are the rows OQ-980 to OQ-992 in `docs/open-questions.md`; each has a working default in use.

## Goal

The engine-side store for messages a person explicitly saves into the local workspace: encrypted at rest, content-addressed blobs with a size cap and a quota, metadata in the database, a full-text index on a redacted projection only, an ingest path that stays off the main loop (a worker thread on SQLite), windowed search, and retention that really deletes. Serves MSG-10 (core), blueprint 1.4 (the capture-ingest/search worker), 6.2 to 6.4 and invariants I-5, I-6, I-7, I-10, I-13. No message is read here: later work packages (M1-10 codecs, the peek, tap and export actions) pass messages in through the store; there is no broker I/O, no consume and no action.

**Interfaces**

```ts
// @app/ports (rows only; the repository never sees a key or a plaintext body)
export type CaptureBodyState = 'inline' | 'blob' | 'omitted';
export interface CaptureRepository {
  createCapture(c: NewCapture): Promise<void>;                        // owner, env class, expiry, index flag
  getCapture(ownerId: string, id: string): Promise<CaptureRecord | undefined>;
  listCaptures(ownerId: string, q: WindowQuery): Promise<Window<CaptureRecord>>;
  appendMessages(batch: AppendBatch, limits: AppendLimits): Promise<AppendResult>; // one transaction
  queryMessages(ownerId: string, q: MessageQuery): Promise<Window<MessageSummary>>;
  getMessage(ownerId: string, captureId: string, id: string): Promise<StoredMessage | undefined>;
  getBlobChunks(ownerId: string, ref: string, from: number, to: number): Promise<readonly BlobChunk[]>;
  noteLoss(captureId: string, loss: CaptureLoss): Promise<void>;       // queue-full and similar, counted (I-13)
  deleteCapture(ownerId: string, id: string): Promise<DeleteResult>;
  purgeExpired(now: number, limit: number): Promise<DeleteResult>;     // bounded
  usage(ownerId: string): Promise<{ captures: number; storedBytes: number }>;
  searchAvailable(): Promise<boolean>;
}

// @app/svc-messages (internal API for the later actions)
export interface CaptureStore {
  create(owner: string, input: CaptureInput): Promise<CaptureView>;    // persist: 'volatile' | 'saved'
  append(owner: string, captureId: string, messages: readonly CapturedMessageInput[]): Promise<AppendReceipt>; // bounded, never throws for a full queue
  query(owner: string, q: CaptureQuery): Promise<Window<CapturedMessageView>>;
  get(owner: string, captureId: string, id: string): Promise<CapturedMessageDetail | undefined>; // opens the seals
  blob(owner: string, ref: string, offset: number, length: number): Promise<Uint8Array>;
  save(owner: string, volatileId: string, options?: SaveOptions): Promise<CaptureView>; // explicit save
  remove(owner: string, captureId: string): Promise<DeleteResult>;
  purgeExpired(): Promise<DeleteResult>;
  flush(): Promise<void>; stats(): CaptureStats; close(): Promise<void>;
}
```

Storage decisions (all working defaults, see the OQ rows): a body up to 64 KiB is sealed inline in its row (AAD `captured_messages:body_sealed:<id>`); a larger one is split into 256 KiB chunks, each sealed (AAD `capture_blob_chunks:sealed:<ref>.<n>`), addressed by the sha256 of the plaintext and reference-counted; a body over the blob cap (16 MiB) is stored as `omitted` with its size and hash and is counted. Properties and headers are sealed together (`captured_messages:meta_sealed:<id>`). Plain columns hold only routing facts (exchange, routing key, source, content type, size, time, hash). The searchable text is a redacted projection: an environment class of `prod` (or unset) indexes metadata only, never the body.

## Out of scope

- Any action, topic, HTTP route, MCP tool or UI (`captures.query`, `captures.export`, `captures.import` are M1-33 and later), the peek and tap that produce messages (M1-04, M1-15), payload codecs (M1-10: the store keeps raw bytes and a plain-text projection of text-like bodies only).
- Export and import hooks (the issue names none; `queryMessages` and `getMessage` are what an export reads).
- Re-sealing old rows under a new key (rows name their key; a retired key opens them), per-capture data keys, an encrypted backup of `capture.db` (OQ rows).
- Wiring the worker into the engine start-up (`apps/engine/src/entry` is not touched): the host is started by the first consumer.

## Risks / questions

- Postgres is proved by CI only on this machine (no Docker): OQ-990. The SQL differs only where it must (`tsvector`, the index maintenance).
- The masked text is plaintext at rest by design (blueprint 6.2: a masked-text column and an index): OQ-981. A person who needs more than redaction keeps the capture `metadata only`.
- Content-addressing by the plaintext hash lets a reader of the database test a guess of a large body: OQ-983.
- Security review recommended before any action exposes the store (trust of the redaction rules, the sealing layout, the worker boundary).
- Estimated 2,400 changed lines in five slices (tests included).
