# M1-10 Payload codecs v1 in the tier-1 worker pool (MSG-08)

**Issue:** #95 · **Milestone:** M1 · **Wave:** M1-W1 · **Size:** M (five slices of at most 600 changed lines each, A to E) · **Owner area:** engine, messages · **trust:critical:** no (the pool runs first-party code only; no new listener, no socket, no secret)

Working spec written under the maintainer's agile mode (no approval stop). Questions decided by default are rows OQ-1200 to OQ-1209 in `docs/open-questions.md`; each has a working default in use.

## Goal

Decode the common payload formats of a message body safely and **off the main loop**: a codec registry, a tier-1 (first-party, no third-party parser) set of codecs that work on bytes only, and a bounded `node:worker_threads` pool that runs them with a timeout, a memory limit, an abort and counted rejections. Serves MSG-08, DC-53 (blueprint section 11, "CodecPlugin", trust tier 1) and invariants I-5, I-6, I-10, I-13. The message browser, the DLQ centre and the replay editor (M1-09, M1-34 and later) consume it; this work package builds no UI and no action.

## Files & interfaces

**Create**

- `libs/engine/decoders` (`type:adapter`, `runtime:node`, generator output plus):
  - `src/codecs/{types,limits,errors,registry}.ts`: the `CodecPlugin` shape, the limits, the error catalogue, the registry.
  - `src/codecs/{text,json,base64,hex,gzip,deflate,brotli,zstd,msgpack,cbor,xml,cloudevents,pickle,php}.ts` and `src/codecs/compress.ts` (the shared, output-capped inflate).
  - `src/payload/{decode-payload,select,rules,result,view}.ts`: the pipeline, the selection (rule, then headers, then sniff), the structured result.
  - `src/worker-entry.ts` and `src/worker-url.ts`: the worker side of the pool convention.
  - specs next to each file, `src/payload/properties.spec.ts` (fast-check).
- `libs/engine/plugin-host` (`type:kernel`, `runtime:node`): `src/{pool,types,stats}.ts`, `src/testing/test-worker.ts`, specs.
- `libs/testkit/src/payload-codecs.spec.ts`: the pool over the real worker entry.

**Modify**

- `tsconfig.base.json`: the two `@app/*` aliases (generator output).
- `libs/engine/decoders/src/{index,builtin/index}.ts`: `.ts` import suffixes, new exports.
- READMEs of both projects, `AGENTS.md` sections 3 and 7, `docs/open-questions.md` (rows).

**Interfaces**

```ts
// @app/decoders
export interface PayloadInput {
  body: Uint8Array;
  bodyTruncated?: boolean;          // the capture already cut the body (counted, surfaced)
  contentType?: string;             // the AMQP content_type property
  contentEncoding?: string;         // the AMQP content_encoding property
  queue?: string;                   // for per-queue rules
  rules?: readonly PayloadRule[];   // { queue: 'orders.*', codec: 'msgpack', encoding?: 'gzip' }: exact or one * wildcard, no regex
  limits?: Partial<CodecLimits>;    // can only be tightened
}
export interface DecodedPayload {
  codec: CodecId;                   // the codec that produced the view ('hex' on a fallback)
  detected: { type: string; mime: string; confidence: number; source: 'rule' | 'header' | 'sniff' | 'fallback' };
  layers: readonly { encoding: string; inBytes: number; outBytes: number }[];
  view: PayloadView;                // tree | text | hex | base64 | disassembly
  error?: { code: CodecErrorCode; message: string; offset?: number }; // fixed phrases, never payload bytes
  truncations: readonly { what: TruncationKind; max: number; dropped: number | null }[];
  counters: { inputBytes: number; decodedBytes: number; viewBytes: number };
}
export function decodePayload(input: PayloadInput): DecodedPayload; // sync, pure, NEVER throws
export function encodePayload(codec: ReversibleCodecId, value: unknown): Uint8Array;
export const codecWorkerUrl: URL;

// @app/plugin-host
export function createWorkerPool<I, O>(options: WorkerPoolOptions): WorkerPool<I, O>;
export interface WorkerPool<I, O> {
  run(input: I, options?: { signal?: AbortSignal; timeoutMs?: number }): Promise<PoolOutcome<O>>; // never rejects
  stats(): PoolStats;                // queued, running, workers, per-reason counters
  close(): Promise<void>;
}
export type PoolOutcome<O> =
  | { ok: true; value: O }
  | { ok: false; reason: 'timeout' | 'out-of-memory' | 'aborted' | 'queue-full' | 'input-too-large' | 'worker-error' | 'closed' };
```

Defaults (blueprint section 11, tier 1): 250 ms per call, 64 MB old generation, input 16 MiB, view 4 MiB, decompressed bytes 16 MiB, ratio 1000 (above 64 KiB of output), depth 64, 200000 nodes, 3 encoding layers, queue 64, 2 workers (at most 8).

## Out of scope

- Any action, contract, topic or UI: the message browser (M1-09), the DLQ centre and the framework decoders (M1-34 and later `decoder` generator runs), the replay editor. The `CodecPlugin` here is the stand-in until `plugin-sdk` lands (OQ-1201).
- Third-party codecs that need a dependency: protobuf (with schema), avro, thrift, flatbuffers, parquet. Human-gated follow-up listed in the report.
- Tier 2 (declarative) and tier 3 (QuickJS sandbox) codecs; per-queue rule persistence and its UI (the rules are an input here).
- Wiring the pool into `apps/engine`, the second esbuild entry for the worker (OQ-1202), `perf` gates.
- CloudEvents binary content mode (it needs the attribute header names recorded from a real producer; structured JSON mode only, OQ-1207).

## Acceptance criteria

| ID | Given | When | Then | Test (name quotes the AC id) |
| --- | --- | --- | --- | --- |
| AC-1 | `content-encoding: gzip` and a msgpack body | decoded | the view is a tree of the msgpack value, `layers` lists gzip, `detected.type` is `msgpack`. A malformed payload (declared JSON, cut off) gives a hex view plus an inline error with the code and the byte offset | `decode-payload.spec.ts`: "M1-10 AC-1 ..." (two tests) |
| AC-2 | a decode that runs past 250 ms, or past the memory limit | the pool runs it | the worker is terminated, the outcome is `timeout` or `out-of-memory`, the next job is served by a fresh worker, and `stats()` counts the termination | `pool.spec.ts`: "M1-10 AC-2 ..." (timeout, memory) |
| AC-3 | a pickle stream that would run code on load, and a PHP serialized object | decoded | the view is an opcode disassembly or a token view (`deserialised: false`), never an object; `decoders/src` imports no `vm`, `child_process`, `eval` or `Function` | `pickle.spec.ts`, `php.spec.ts`, `no-exec.spec.ts`: "M1-10 AC-3 ..." |
| AC-4 | a rule, a content type, a content encoding and a sniffable body that disagree | selecting | the order is rule, then headers, then sniff, then the hex fallback; `detected.source` says which; a `charset` parameter, a BOM or a UTF-16 pattern picks the text charset; unknown charsets and encodings fall back to hex with an error | `select.spec.ts`: "M1-10 AC-4 ..." |
| AC-5 | JSON bodies: valid, nested beyond the depth limit, with 10 MiB of text, with `__proto__` keys and large integers | decoded | a pretty view that keeps number lexemes; depth and node limits are counted truncations (the tree is dropped, the text view remains); `__proto__` is a plain key | `json.spec.ts`: "M1-10 AC-5 ..." |
| AC-6 | binary bodies and text in hex and base64 | viewed and decoded | hex and base64 views are capped with the dropped bytes counted; base64 text (standard, URL-safe, unpadded, with line breaks) decodes and is re-run through the pipeline; bad input is a coded error | `views.spec.ts`: "M1-10 AC-6 ..." |
| AC-7 | gzip, deflate, brotli and zstd bombs (megabytes of zeros in a few hundred bytes), a stack of 4 layers | decoded | the output never exceeds the decompressed cap, the ratio cap refuses, layers above 3 are refused; the view is the compressed bytes in hex with `OUTPUT_LIMIT`, `RATIO_LIMIT` or `LAYER_LIMIT` | `compress.spec.ts`: "M1-10 AC-7 ..." |
| AC-8 | any bytes (fast-check), any headers, any rules | decoded | no throw; `viewBytes` is within the cap; every error message is one of the catalogue's fixed phrases | `properties.spec.ts`: "M1-10 AC-8 ..." |
| AC-9 | text, hex, base64, JSON, gzip, deflate, brotli, zstd, msgpack | `encodePayload` then decoded | the value round trips | `properties.spec.ts`: "M1-10 AC-9 ..." |
| AC-10 | a pool of 1 worker and a queue of 2, with the worker held | 4 jobs are submitted | the 4th is `queue-full` at once, `stats().queued` never exceeds 2 (checked on every transition), the rejection is counted, and the held jobs finish when released | `pool.spec.ts`: "M1-10 AC-10 ..." |
| AC-11 | a queued job and a running job | their signals abort | the queued job leaves the queue, the running job's worker is terminated, both are `aborted` and counted; a signal aborted before `run` is rejected without starting | `pool.spec.ts`: "M1-10 AC-11 ..." |
| AC-12 | a worker busy until the main loop has run 50 `setImmediate` ticks | the pool runs it | the main loop makes those ticks (a count, no wall-clock percentile) and the job then completes: decoding is off the main loop; the same holds for the real codec worker with a 16 MiB body | `pool.spec.ts`, `payload-codecs.spec.ts`: "M1-10 AC-12 ..." |
| AC-13 | hostile payloads containing a marker string | decoded and run through the pool with an event sink | no error message, pool event or stat contains payload bytes (I-10); events carry sizes and codes only | `no-leak.spec.ts`: "M1-10 AC-13 ..." |
| AC-14 | a CloudEvents structured-mode JSON body, with `data_base64` and with `data` | decoded | the context attributes and the data are separated; an invalid envelope falls back to the plain JSON view with a coded note | `cloudevents.spec.ts`: "M1-10 AC-14 ..." |
| AC-15 | XML with a DOCTYPE, entity declarations, a billion-laughs shape, deep nesting and a valid document | decoded | the DOCTYPE is refused without expansion, entities beyond the five predefined and numeric ones are refused, depth and node limits are counted, a valid document gives an indented view | `xml.spec.ts`: "M1-10 AC-15 ..." |

AC-1, AC-3 to AC-9, AC-13 to AC-15 are proved with synthetic payloads built in the specs (RFC 8949 appendix A and the MessagePack specification vectors for cbor and msgpack, hand-written pickle protocol 0 to 5 streams). No payload recorded from a real framework is used (none exists in `testing/fixtures`); that is a stated limit (OQ-1209).
