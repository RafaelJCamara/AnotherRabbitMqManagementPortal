# M1-13 Peek preflight and rescue preflight (DC-06, DC-09)

**Issue:** #98 · **Milestone:** M1 · **Wave:** M1-W2 · **Size:** M (estimated at about 2,100 changed lines with specs, see Slices) · **Owner area:** engine / peek · **trust:critical:** yes

## Goal

Fill the planner's input from the broker with **HTTP GET requests only** (the peek preflight, DC-06), and make the quarantine path ready and checked before any message is acquired (the rescue preflight, DC-09): the name and the literal shape of `<Product>.quarantine`, a check of what the broker would do to a queue of that name (policies, headroom, permissions, alarms, blocked connections), and the one idempotent declare that arms it. Implements blueprint 5.4 (preflight) and 5.5 (rescue preflight, steps 1 to 5) and amendments **A-2** (the DLX evidence arrives with `complete` and `unknownReasons`) and **A-5** (`QuarantineQueueSpec`, headroom against matching policies). Serves ADR-008; invariants I-2, I-3, I-4, I-6, I-8, I-10 and I-13 (see "Invariants and how each AC proves them").

Scope boundary: the pure planner is M1-12 (done); the executor is M1-14; the post-acquire guard and the quarantine copy-and-ack are M1-15; the `messages.peek` action that calls the preflight in `plan()`, arms the quarantine in `execute()` and writes the receipt is M1-16. This WP ships the functions and ports those WPs call. It adds no action, no contract and no HTTP route.

### What the issue assumes that the repository does not have

1. A way to know that classic queues are disabled (3.13 never; 4.2 and later can): the profile field exists but is never filled (OQ-1469).
2. A port or lease method that declares a queue: none does (OQ-1466).
3. `dlxSources` and the effective config for the peeked queue inside `svc-peek`: they live in `svc-topology` and a service cannot import a service (OQ-1468).
4. "Created once per vhost and reused" with a plan that makes reads only: `plan()` may not write, so creation can only happen in `execute()` (OQ-1467).
5. A round-trip time for `rttMs` from an **HTTP-only** preflight: the planner means the time of one `basic.get` (OQ-1473).
6. A registry row for the quarantine rules and a "quarantine full" cell (A-5) (OQ-1471).
7. `x-death` sources for `heldDeathSources`: reading them needs a message, and a preflight touches none (OQ-1474).

### Where each call happens (the I-2 and I-8 line)

| Step | Call | Runs in | Port | Mutates |
| --- | --- | --- | --- | --- |
| Queue detail, consumers, policies, operator policies, nodes (alarm flags), our connections, the user's permission on the vhost | `GET` (about 7 to 9 reads) | the preflight, from `plan()` and `revalidate()` of the peek action (M1-16) | `MgmtReadPort`, lane `interactive`, through the `BrokerScheduler` | no |
| DLX sources, effective config of the peeked queue | the evidence port | same | `PeekEvidencePort` (composition root, over query actions) | no |
| Quarantine name, spec, headroom, policy simulation, registry lookups | pure | same | none | no |
| `PUT /api/queues/{vhost}/{name}` (create the quarantine once per vhost) | `ensureQuarantine` | `execute()` of the peek action (M1-16), **before** the first `get` | the `send` of `ctx.writes.mgmt` | **yes** |
| Open the `publish` lease and read `blocked()` ("pre-arm") | `ConnectionManager.publish` | the same `execute()`, before the first `get` | `ctx.writes.connections` | opens a connection, sends nothing |

The last two rows are written here so the hand-over to M1-16 is exact; this WP implements the first four rows and the `ensureQuarantine` function of the fifth. The pre-arm of the publish lease is M1-16 (OQ-1475).

## Invariants and how each AC proves them

| Invariant | What it means here | Proved by |

## Risks / questions

Agile mode: every question has a working default that this spec implements; none needs an answer before the first manual test. Ids continue after OQ-1465 (M1-23) and are logged in `docs/open-questions.md` in the commit that adds this spec.

- **OQ-1466 Where may the quarantine be declared, and over which protocol?** No lease declares a queue except an observe lease for tap queues (the peek and source leases cannot, by design; `leases.types.spec.ts` pins it). Default: over HTTP, `PUT /api/queues/{vhost}/{name}`, from `ensureQuarantine`, called only from `execute()` of the peek action with `ctx.writes.mgmt.send`. The management API needs the user to hold a management tag, which the preflight already requires. Alternative: a new method on a lease; rejected because it widens a role-typed lease that is a safety property.
- **OQ-1467 "Created once per vhost" with a plan that may not write.** `plan()` makes reads only, so the first creation can only happen in `execute()`, before the first `get`. Default: `rescue.queueReady` means "exists and conforms, or is creatable here"; the result says which (`queue.state`), the plan preview (M1-16) shows "will create `<name>` once on this vhost", and if the declare fails at the arm step the peek does not start (nothing is held yet) and the person re-plans. Please confirm that a durable queue created by a peek, shown in the plan, is acceptable on a production broker; the alternative is an explicit "prepare the quarantine" action the person runs first.
- **OQ-1468 How does `svc-peek` get `dlxSources` and the effective config?** They are computed by `svc-topology` from a whole-vhost snapshot, and a service may not import a service. Default: a `PeekEvidencePort` in `ports`, implemented in `apps/engine` (M1-16) over `ActionExecutor.run` of `routing.dlx-sources` and `queues.effective-config` with the caller's principal, so permission and the 15 s snapshot cache are reused. Rejected: copying the snapshot and routing code into `svc-peek` (a second, drifting implementation of a trust-critical read).
- **OQ-1469 `classicEnabled` is always `'unknown'`.** The blueprint says classic may be disabled from 4.2; the probe never fills the field. Default: `'unknown'` is treated as available and the result says `classicAssumed: true`; an existing conforming classic quarantine queue is proof; a refused first declare at the arm step makes the quarantine unavailable and the peek does not start. Proposed follow-up issue (not filed here): make the probe fill `classicEnabled` and add a registry rule for it. Fail-closed alternative (treat unknown as disabled) would make the quarantine unavailable on every real broker.
- **OQ-1470 The name.** The issue writes `'<product>.quarantine'`. Default: `quarantineName(prefix)` with the prefix injected by the composition root; the value is `product` until ADR-029 settles the name (the same placeholder the ConnectionManager uses); the prefix is validated (no "rabbitmq" or "rmq", no `amq` start) and fails at startup. The amendments' "configurable tap and quarantine prefixes" is met by the injected value; a user-facing setting is not built here.
- **OQ-1471 What makes the quarantine "overflow-safe", and the missing "quarantine full" cell.** A-5 asks for explicit `x-overflow=reject-publish`, no max-length argument and a headroom check against matching policies, and for a "quarantine full" cell. The registry has no such cell and the planner has no "full" reason code. Default: `overflowSafe` is false when headroom is short (reported in `failures: ['headroom']` and `headroom`), and, as an **extension of A-5 that this spec adds**, also when an effective `message-ttl` or `expires` would expire quarantined messages or the queue. The effective values come from `resolveHypothetical` with the registry rules (a classic `x-overflow` argument beats the policy; `max-length` is the smaller of the two; a quorum `overflow` policy wins over the argument, so the fallback can be judged unsafe). Proposed follow-ups (not filed here): a code-derived registry cell "quarantine full" with citations and CF ids (`/new-semantics-cell`, no status flip), and a `quarantine-full` reason in the planner. Please confirm the TTL and expiry extension.
- **OQ-1472 Required headroom.** The doomed message is the first one met and acquisition stops there, so a peek rescues at most one message. Default: one message and, when a byte limit is effective, `max(profile.limits.maxMessageBytes, 16 MiB)` where the limit is known, else 16 MiB (the largest default byte cap of the peek table). Please confirm or give a number.
- **OQ-1473 `rttMs` from an HTTP-only preflight.** The planner wants the time of one `basic.get`; the preflight may not open an AMQP channel. Default: the elapsed time of the queue read on the injected clock, floor 1 ms, reported as such. This is a proxy, not a measurement of the AMQP path, and may be larger or smaller. The executor checks the target time before every `get` (M1-14), so a wrong proxy cannot extend the hold. A measurement on a throwaway channel at the arm step is a possible later refinement.
- **OQ-1474 `heldDeathSources`.** Reading `x-death` needs a message and the preflight touches none. Default: always absent, so the planner reports `heldDeath: 'not-checked'` and A-2's "a queue holding x-death entries counts as a DLX target" is not applied by this WP. A later source is the capture store (a saved capture of this queue); not built here.
- **OQ-1475 Scope of "a blocked publish connection or an alarm stops the peek".** The issue's AC reads as unconditional; the blueprint (5.5, rescue preflight) scopes it to a plan that uses the quarantine. Default: the facts are always filled when `rescue: 'check'`, and the planner (not this WP) decides that a classic or unlimited-limit plan needs no rescue; blocked and alarm therefore stop a plan that depends on the quarantine, not every peek. A connection list the principal may not read is reported, not treated as blocked, because the pre-arm of the publish lease in `execute()` (M1-16) reads `PublishLease.blocked()` and is the authoritative check. Please confirm, or ask that every peek stops on an alarm.
- **OQ-1476 The name the write permission is tested against.** For a publish to the default exchange the name tested against the user's `write` regex (the empty name or `amq.default`) is not in the fact sheet or the registry and I could not confirm it from the repository. Default: the preflight requires the `write` regex to match **both**, and `configure` to match the queue name only when it must declare. AC-26 records the real answer on the lab brokers; the default is loosened by a later change only on that evidence.
- **OQ-1477 The registry follow-ups #286 to #289.** Read with `gh issue view` on 2026-10-26, all open. #286 (carry-over and peek-method rows): the planner infers them and this WP neither reads nor changes them. #287 (classic settle cells): not used; a classic plan has `effects: 'not-in-registry'`. #288 (planner-owned warnings): not used. #289 (policy-write fix action): not used. None of the four is a precondition; none is made worse by this WP.
- **OQ-1478 Executor states and the `it` target.** M1-14's spec says M1-13 adds the executor state `preflighted`. Default: not added here; the preflight is a plan input, the executor starts at `acquiring`, and `preflighted` and `rescuing` join the table with the guard (M1-15) and the action (M1-16) if they are still wanted. `svc-peek:it` is also planned by M1-14 slice C (#99, open): whichever lands first creates the `it` target and `libs/testkit/src/it/svc-peek.it.ts`; the other adds its describe block.
- **OQ-1479 Trust-critical work in progress.** `trust:critical` WPs are capped at 2 in progress (AGENTS.md section 12): check the count before slice A. `CODEOWNERS` already covers `/libs/engine/svc-peek/`; `libs/engine/ports/` is not trust-critical. No protected path (lab evidence, workflows, `pnpm-workspace.yaml`, the allow-list, `.claude/settings.json`) needs a change. No dependency is added.
- **OQ-1480 Size.** About 2,350 changed lines with specs in four slices (550, 750, 800, 250). `oversize-approved` is not asked for. The adversarial review (`security-review`) runs on slice C, which holds the fail-closed decisions, and on the I-2 argument of slice A.

Not decided here and not claimed: what a real broker lists in `GET /api/queues/{vhost}/{name}` for `members`, `online`, `consumer_details` and `delivery_limit` per version and provider (the fixtures and AC-26 show it; fields the broker omits stay absent), and what the broker does when a returned message meets a quarantine whose limit is `-1` on each era (the registry cell says; no lab evidence is written by this WP).
