# M1-14 Peek executor: state machine, hold journal, watchdog, nack + qos barrier

**Issue:** #99 · **Milestone:** M1 · **Wave:** M1-W2 · **Size:** L · **Owner area:** engine / peek · **trust:critical:** yes

## Goal

The engine-side peek executor: a short, atomic, sequential `basic.get` loop that never returns messages by closing. A hold ends in one `nack(lastUnackedTag, multiple, requeue)`, then a `basic.qos` barrier, then a lazy channel close, and its write-ahead journal row is settled. Serves the core of MSG-03 and MSG-04 and invariant I-4; implements DC-03, DC-04, DC-05 and DC-11 as the issue states them. Design follows blueprint §5.5 and ADR-008 (sequential `basic.get`, mandatory disposition, preflighted peek).

Scope boundary: the post-acquire guard and the dispositions (quarantine, raise-limit, let-broker-handle) belong to M1-15; the rescue preflight to M1-13; svc-peek actions, receipts and captures to M1-16; the AMQP 1.0 credit-1 path to M1-37. The executor takes the guard as an input (see Risks).

### Create

- `libs/engine/svc-peek/src/internal/state-machine.ts`: the states and the transition table. States in this WP: `idle`, `acquiring`, `returning`, `settled`, `incident`. The blueprint's `preflighted`, `guarding`, `rescuing` and `raising` states are added by M1-13 and M1-15.

// libs/engine/ports/src/repos.ts (new; async from day one)
export type HoldState = 'acquiring' | 'settled' | 'incident';
export interface HoldJournalRepository {
  open(hold: { id: string; connectionId: string; vhost: string; queue: string; startedAt: number }): Promise<void>;
  settle(id: string, returned: number, endedAt: number): Promise<void>;
  markIncident(id: string, reason: string, endedAt: number): Promise<void>;
  /** Rows left in `acquiring` by a process that stopped mid-peek. */
  listInterrupted(): Promise<readonly { id: string; connectionId: string; vhost: string; queue: string }[]>;
}

// libs/engine/svc-peek/src/internal/executor.ts (introduced here)
export interface PeekExecution {
  readonly queue: string;
  readonly count: number; // caps.count of the plan (PeekPlanPreview.caps)
  readonly bytes: number; // caps.bytes of the plan
  readonly targetMs: number; // hold.targetMs
  readonly hardAbortMs: number; // hold.hardAbortMs
}
export type StopReason = 'count' | 'bytes' | 'target' | 'empty' | 'abort' | 'watchdog' | 'copy-failed';
export type ExecutionResult =
  | { readonly outcome: 'settled'; readonly taken: number; readonly returned: number; readonly stop: StopReason }
  | { readonly outcome: 'incident'; readonly reason: string; readonly returned: number };
export interface ExecutorDeps {
  /** Injected by the caller. M1-14 never decides doomed-ness itself (see Risks). */
  guard(delivery: Delivery): 'not-doomed' | 'doomed';
  /** Copy of each delivery (the blueprint's step 2). Failure stops the loop and returns the holds. */
  copy(delivery: Delivery): Promise<void>;
  journal: HoldJournalRepository;
  now(): number;
}
export interface PeekExecutor {
  execute(lease: PeekLease, plan: PeekExecution, deps: ExecutorDeps, signal: AbortSignal): Promise<ExecutionResult>;
  /** Nack and barrier every in-flight hold, then close. Awaits the barrier before close. */
  flushAll(reason: 'shutdown' | 'suspend'): Promise<void>;
  reconcileInterrupted(): Promise<{ readonly marked: number }>;
}

## Risks / questions

Each question below is for the human. Each has a default this spec implements. Approved 2026-10-26: OQ-215 is decided as written below; the other defaults stand as logged assumptions until a maintainer changes them.

- **OQ-215 (quorum barrier, decided 2026-10-26: wait).** The barrier answers before a quorum queue shows the nack. Decision of the maintainer: classic queues return at the barrier; quorum queues also wait up to 10 s (`QUORUM_RETURN_WAIT_MS`) for the ready count to be back at the value read before the first `get` (a passive declare on a throwaway channel), and report the delay (`returnConfirmedAfterMs`). If the count is not back in time, or cannot be read, the hold ends as an `incident` with reason `return-unconfirmed` and `returned: 0`; the lease is not poisoned, because the barrier itself answered. The baseline is the count before the first `get`, not the number taken, so a queue with more than `taken` messages is judged correctly. A concurrent consumer that drains the queue during the wait can make the return unconfirmed; that is reported, never assumed. AC-1 covers classic and quorum.
- **Guard input (I-2 and M1-15).** The guard is injected. Default: `execute` refuses to start without a guard (fail closed, `incident`), so no unguarded peek can run. The default guard of M1-15 is the production one. Tests use an explicit `not-doomed` guard.
- **Where `get` and `nackRequeue` may be called (I-2).** Both touch messages, so the invariant asks for an `implementAction` module. Default: the executor is exported from `svc-peek` and called only from the peek action of M1-16; the arch-test is extended only if it does not already cover the lease's write methods. Please confirm.
- **Copy and the capture store (service layering).** The blueprint's step 2 writes a copy to the capture store, which lives in `svc-messages`. A service cannot import another service. Default: `ExecutorDeps.copy` is injected and M1-16 supplies it through the `CaptureRepository` port; a copy failure stops the loop and returns the holds (AC-8), so nothing is lost.
- **Watchdog value.** The issue says "the hard limit". Default: `hardAbortMs` from the planner's hold (at most 30 s, from `holdBudget`), counted from the start of `execute`, on an injected timer. The watchdog never waits on the broker to abort it.
- **reconcileInterrupted (AC-9).** Default: a crashed process's `acquiring` rows are marked `incident` and nothing is re-acquired, because the broker requeues unacked deliveries when the channel closes. This is a claim about broker behaviour: the uncertainty U-04 (a DOWN overtaking a pipelined nack) bears on it, and the lab run in M1-06 measures it. Confirm the default.
- **Journal encryption (ADR-014).** ADR-014 covers the journal. Default: queue names and tags are field-encrypted through `@app/secrets`; the id, state and times are plain. Please confirm the field list.
- **Trust-critical WIP cap.** `trust:critical` WPs are capped at 2 in progress (AGENTS.md section 12). Check the current count before the slice starts.
- **Protected paths (human-only).** `CODEOWNERS` needs a line for `/libs/engine/svc-peek/` with the trust-critical owner. Proposed text, for a maintainer to apply: `/libs/engine/svc-peek/ @RafaelJCamara`. No `pnpm-workspace.yaml` or supply-chain change is needed, because the WP adds no dependency.
- **Size (AGENTS.md section 5: 800 changed lines).** Estimate about 900 to 1,100 changed lines, which is over the guidance. Proposed split, in this order: **A** the journal (migration and repository), the state machine and the execute loop with the fake lease (AC-1, AC-4, AC-6, AC-7); **B** the watchdog, `flushAll`, the failure path and `reconcileInterrupted` (AC-2, AC-3, AC-5, AC-8, AC-9); **C** the lab run `svc-peek:it` on the five versions (planned, after the lab cells M0-38 to M0-41 are green). Each slice lands as one commit on `main`.
- **Uncertainties (U-nn).** U-04 as above. The chaos evidence of M1-38 (seven clean nights) is not a precondition of this WP, but the peek flag stays off until it is (IP-6).
