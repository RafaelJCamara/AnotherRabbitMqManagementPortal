**Issue:** #105 · **Milestone:** M1 · **Wave:** M1-W2 · **Size:** M by label; four slices with budgets (see "Slices") · **Owner area:** topology · **trust:critical:** no. ## Goal

The engine face of two pure libraries. A new service module `svc-topology` reads one vhost of a connected broker (queues with their arguments, exchanges, bindings, policies, operator policies, consumers), turns it into the plain inputs of `@app/routing` and `@app/effective-config`, and answers six read-only queries:

| Action | Library behind it | Answers |
| --- | --- | --- |
| `topology.graph` | (own, R4) | the vhost as a bounded graph, aggregated when larger than the cap |
| `topology.subgraph` | (own, R4) | the neighbourhood of one exchange or queue, depth at most 2, at most 2,000 elements |
| `routing.simulate` | `simulate` | which queues a publish reaches and by which path; `unroutable` or the alternate-exchange path |
| `routing.dead-letter` | `deadLetterPath`, `findDlxLoops` | where a message goes when it dies in a queue, and the dead-letter loops that include the queue |
| `routing.dlx-sources` | `dlxSources` | every queue that can dead-letter into a queue, with `complete` and `unknownReasons` (A-2) |
| `queues.effective-config` | `resolveEffective` | per key: the value a queue really has, the rule, and the provenance of every input |

Serves: TOP-01..03 and POL-01 (engine half), DC-07, DC-30, DC-16 inputs, `PeekPreflight.dlxSources` (core-interfaces, blueprint 5.4) and amendment **A-2**; ADR-009, ADR-010; invariants I-2 (reads only, no `WritePort`), I-3 (no broker version compared here), I-5, I-6, I-7, I-8, I-13. Consumers that come later: M1-12 and M1-13 (peek planner and preflight), M1-32 (hazard advisor), M1-49 (topology view), M1-50 (routing simulator UI, effective-config view).

The issue calls the last action `effective-config.get`; the contract kit and the generator accept only a lowercase namespace without a hyphen (`namespace.name`), so the id is `queues.effective-config` (OQ-1414). The route is `POST /connections/{cid}/effective-config/queries` and the CLI words are `effective-config get`.

## Rules

**R1 Reads only, through the scheduler (I-2, I-8).** `SvcTopologyDeps` names `mgmt: MgmtReadPort`, `profiles`, `connections` and optional `clock`, `limits`. There is no write port and no adapter import; `mgmt` is the BrokerScheduler's wrapper, every request names the lane `interactive` (a person is waiting). All six actions are `kind: 'query'`, `permission: 'broker.read'`, `risk: 'none'`, `planning: 'none'`, `audit: 'none'`, HTTP `POST` with the vhost and names in the body (vhost names contain `/`; the precedent is `inventory.query`).

**R2 Resolve queue settings before the library sees them.** `internal/settings.ts` turns a queue row and the policy lists into a `TopologyQueue` and an `ExchangeSettings`:
- **Version for the registry** is `profile.versions.min` (the lowest node; `null` when unreadable gives `unknown` keys, never a guess; OQ-971). A mixed-version cluster is reported (`mixedVersions`); per-node resolution waits for the UI (OQ-1409).
- **Policy layer of a queue** (one for the user policy, one for the operator policy) is `none`, `policy` (a definition) or `unknown`. It is `policy` when the stat `policy` names a listed policy; `none` when the stat is `null` (or, if the stat is absent and the list is readable, when no policy matches); `unknown` when the list is unreadable and the stat is absent or names a policy, when the stat names a policy that is not in the list, when the match is ambiguous (`matchPolicy` says `ambiguous`), or when the stat is absent and the list is unreadable.
- **Dead-letter exchange** (`deadLetter`): the argument `x-dead-letter-exchange` if it is a string (`set`, argument over policy, even over an operator policy); if it is present and not a string, `unknown`. Otherwise, with both layers known, the `dead-letter-exchange` entry of `resolveEffective` (`effective`: `set`; `unset` and `default` with no value: absent; `unknown` or `invalid`: `unknown`); with a layer `unknown`: `unknown`. Routing key and strategy follow the same rule.
- **Limits** (`messageTtlMs`, `maxLength`, `maxLengthBytes`, `overflow`) from the `effective` entries (a value only when `effective`, else absent). An unknown layer leaves them absent: they only add reasons to a queue that already dead-letters, and the destination, which is what the library walks, is covered by `deadLetter: unknown`.
- **Delivery limit** (quorum queues only): the stat `delivery_limit` when it is a non-negative number (`finite`); a negative number is `unlimited`; any other value is `unknown`. When the stat is absent, the `delivery-limit` entry of `resolveEffective` (`effective` number: `finite`, negative: `unlimited`; anything else: `unknown`). A **classic or stream queue gets no `deliveryLimit`** (unknown, never unlimited), pending U-01(4) (OQ-1406).
- **Alternate exchange** of an exchange: the argument `alternate-exchange` if a string, else the `alternate-exchange` of the matching user policy (applies to `all` and `exchanges`); a policy match that cannot be decided leaves the AE absent and raises `policy-match-undecided`. No source was read for the exchange case; the general documented rule (arguments beat user policies) is the working default (OQ-1410).
- **`rejectable`** is `true` for a queue with at least one consumer that requires acknowledgement (it may nack); otherwise absent (OQ-1302, OQ-1411). The consumer read is best effort: if it fails or is cut, `consumers` in the answer says so.
- **Queue type**: the row `type` when it is `classic`, `quorum` or `stream`; anything else is absent.
- **`heldDeathSources`**: not readable here (no message is touched). The caller of `routing.dlx-sources` passes the source queues of the `x-death` it saw, and the action sets them on the target queue and echoes them (R7, OQ-1407).

**R3 The snapshot (`internal/snapshot.ts`).** One vhost, read with bounded paging: queues, exchanges, consumers (paged at 500, `pagination=true`, `columns` limited to what is used), bindings (whole array), policies and operator policies. Bounds in `TopologyLimits` with `DEFAULT_TOPOLOGY_LIMITS`: `maxQueues` 50,000, `maxExchanges` 10,000, `maxBindings` 200,000, `maxConsumers` 100,000, `maxPolicies` 1,000, `pageSize` 500, `snapshotTtlMs` 15,000, `maxSnapshots` 8, `yieldEveryItems` 500. A kind that exceeds its bound keeps the first rows and is **counted** (`truncation.<kind>`, a minimum when the broker's own count is unknown); the answer carries it and the gap `truncated`. A failure to read queues, exchanges or bindings fails the whole call with the port's Problem (fail closed); policies follow R1 (unreadable gives a gap) and consumers follow R2 (best effort, reported). A vhost the broker does not list is `NOT_FOUND`. Conversion of rows (effective-config per queue) yields to the event loop every `yieldEveryItems` rows (I-5); the yield is injectable. A finished snapshot is kept `snapshotTtlMs` (a bounded map, oldest evicted and counted, `refresh: true` bypasses it); the answer always carries `snapshot.takenAt`.

**R4 Graph and subgraph (`internal/graph.ts`, pure).** Nodes are exchanges and queues; edges are bindings (one edge per binding), alternate-exchange links (exchange to exchange) and dead-letter links (queue to exchange, when the setting is `set`). `topology.graph` is the whole vhost; `topology.subgraph` is the breadth-first neighbourhood of a focus (`{kind: 'exchange'|'queue', name}`) over the undirected adjacency, `depth` 0 to 2 (default 1), and marks every kept node that has neighbours outside it (`hasMore`). Both are held to `maxElements` (nodes plus edges; default and ceiling 2,000). When the scope is larger, nodes are ranked (focus first, then distance, then degree descending, then name), the largest prefix whose result fits is kept (binary search, then checked and shrunk if needed), and every dropped node is folded into an **aggregate node** per (kind, best-ranked kept neighbour) with a count, a sample of up to five names and one edge carrying the count of bindings behind it. The answer says `aggregated: true`, `omitted: {nodes, edges}` and the exact `totals` of the vhost. The same input gives the same output (no clock, no randomness; sorted).

**R5 `routing.simulate`.** Input: `cid`, `vhost`, `exchange` (`""` is the default exchange), `routingKey`, optional `headers`, `cc`, `bcc` (the library reads `CC` and `BCC` from the headers; the action builds them), `mandatory`. Output: the library's `RoutingResult` as an explicit schema (outcome, fate, queues, paths, `usedAE`, `exact`, refusal, unknown exchanges, loops, notes, truncation) plus `snapshot`, `gaps` (R6) and `exact` combined: **an answer built with any gap is not exact**, whatever the library says, so "unroutable" with unreadable policies reads "unroutable by what could be read". The optional **verification publish** of the issue is a mutation (a real message, behind the prod lock) and is not part of this work package (OQ-1403).

**R6 Gaps, honestly.** `gaps` is the sorted set of codes `policy-unreadable`, `operator-policy-unreadable`, `stats-fields-missing`, `other-clients-may-declare`, `policy-match-undecided`, `truncated`. Rules: the policy or operator-policy list was unreadable (R1); at least one queue row lacks the `policy` or `operator_policy` key, or a quorum queue lacks `delivery_limit` (stats off); the principal's profile identity is neither admin nor monitoring (`identity.isAdmin`, `identity.canMonitor`), so the listing may not show every queue and other clients may declare more (OQ-1408); R2's undecided match; a bound was hit. The first four are exactly the `ContextGap`s of `dlxSources` and are passed to it.

**R7 `routing.dead-letter` and `routing.dlx-sources`.** `routing.dead-letter`: `queue`, optional `reason` and `keys`; output `paths`, `ends`, `exact`, `notes`, `truncation` of `deadLetterPath`, plus the loops of `findDlxLoops` that include the queue, plus `gaps` and `snapshot`; `exact` is false when any gap exists. `routing.dlx-sources`: `queue` and optional `heldDeathSources` (bounded to 100 names); output `sources`, **`complete`**, **`unknownReasons`**, `truncation` exactly as the library returns them, `heldDeathSourcesConsidered` (the names passed, so a consumer can see whether x-death was looked at), `gaps` and `snapshot`. **An empty `sources` is "no hazard" only when `complete` is true**; the action adds no field that flattens this (no boolean "hazard" or "safe"), and a test fails if one appears.

**R8 Errors are Problems.** The connection must be visible to the principal (not theirs and not shared: `NOT_FOUND`, as in the explorer); a connection never probed or with an out-of-date profile: `NOT_FOUND` with a hint to probe; unknown vhost, queue or focus: `NOT_FOUND`; a broker failure other than R1's unreadable cases passes through as the port's Problem; invalid input is rejected by the contract (`VALIDATION_FAILED`, for example `depth: 3`). No broker text reaches an answer other than inside a Problem.

**R9 Codes, not prose.** Gap codes, notes, reasons and ends are the closed codes of the libraries and this spec; the UI words them. Honest wording applies to every summary (AGENTS.md section 1).

## Out of scope

- The **verification publish** of the issue ("routing.simulate with an optional verification publish (mandatory)"): a planned mutation behind the prod lock that delivers a real message; it needs the publish port and the executor's plan and consent path. It becomes its own issue (`routing.verify`, kind `command`, planning `required`), see OQ-1403. Here `routing.simulate` is pure and never touches a message.
- Reading `x-death` from messages (needs a peek; M1-13 passes the sources in), per-message `expiration`, per-node effective config of a mixed-version cluster, the hypothetical "what applies if I declare X" form of the resolver (M1-50 needs it; `resolveHypothetical` is not exposed here, OQ-1413).
- Streaming the bindings of a very large vhost (the port's 16 MiB body cap applies; the follow-up reads them as a stream like the explorer does), OQ-1404.
- Any UI, any change to `libs/shared/routing`, `libs/shared/effective-config`, the semantics registry, lab evidence or a protected path; wiring `svc-topology` into a live topic (these are queries).
- Lab proof that the simulator equals the broker (M1-05, OQ-1307) and the CF cells for the gap causes of A-2 (M1-18 and M1-05 get the list in OQ-1408).
