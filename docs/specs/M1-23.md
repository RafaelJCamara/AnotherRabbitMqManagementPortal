# M1-23 Credential providers and TokenManager (CON-07 core, DC-37/38)

**Issue:** #108 · **Milestone:** M1 · **Wave:** M1-W2 · **Size:** L · **Owner area:** engine / identity · **trust:critical:** yes

## Goal

Pluggable broker credential providers (password, client credentials, token command, static token, x509/EXTERNAL) and a `TokenManager` that renews a token at 75 % of its lifetime, per protocol, and refuses a refreshed token whose username claim differs from the first one. It also warns before use when a token is too large for the broker's header or pre-auth frame limits, and cancels the engine's own consumers at expiry on brokers that do not close the connection. Serves CON-07 (core), DC-37, DC-38, blueprint §7.5 and the invariants I-3, I-9, I-10 below.

Scope boundary: OAuth discovery, PKCE loopback, device code and issuer pinning are M1-24 (DC-39); the Keycloak 26 lab variant and the recorded expiry behaviour per version are M1-25 (U-14); the Vault/OpenBao and delegated-user providers are later work. This WP ships the engine core and its ports. It adds no HTTP action and no UI (see Out of scope and OQ-1455).

### Interfaces

```ts
// libs/engine/ports/src/identity.ts (new)
export type RenewalProtocol = 'http' | 'amqp091' | 'amqp10' | 'stream';

/** One RFC 6749 4.4 request. The secret is in `clientSecret` and nowhere in the URL. */
export interface TokenRequest {
  readonly endpoint: string; // https URL, or http only for a loopback lab issuer (OQ-1462)
  readonly clientId: string;
  readonly clientSecret: string;
  readonly scope?: string;
  readonly audience?: string;
}
export type TokenEndpointFailure =
  | 'unreachable' | 'egress-denied' | 'tls-untrusted' | 'timeout' | 'refused'
  | 'malformed' | 'too-large';
export type TokenResponse =
  | { ok: true; accessToken: string; expiresInSeconds: number | null; tokenType: string }
  | { ok: false; reason: TokenEndpointFailure };
export interface TokenEndpointPort {
  requestToken(request: TokenRequest, signal: AbortSignal): Promise<TokenResponse>;
}

/** Runs a configured command without a shell. Implemented in apps/engine (OQ-1460). */
export interface CommandRunnerPort {
  run(
    command: { readonly file: string; readonly args: readonly string[] },
    limits: { readonly timeoutMs: number; readonly maxStdoutBytes: number },
    signal: AbortSignal,
  ): Promise<
    | { ok: true; stdout: string }
    | { ok: false; reason: 'spawn-failed' | 'exit-nonzero' | 'timeout' | 'too-large' }
  >;
}

/** What the TokenManager asks of a live connection. The ConnectionManager implements it. */
export interface ConnectionAuthPort {
  /** AMQP 0-9-1 `connection.update-secret`. Rejects when the broker refuses (for example a different user). */
  updateSecret(connectionId: string, secret: string, reason: string): Promise<void>;
  /** AMQP 1.0 `PUT /auth/tokens` (4.1+). No implementation until M1-07 (OQ-1464). */
  putAuthToken?(connectionId: string, token: string): Promise<void>;
  /** Close and open again with the current credential (AMQP 1.0 on 4.0, streams). */
  reconnect(connectionId: string, protocol: RenewalProtocol): Promise<void>;
  /** Cancel the consumers the engine itself holds on this connection. Returns how many. */
  cancelOwnConsumers(connectionId: string, reason: 'token-expired'): Promise<{ cancelled: number }>;
  /** The broker closed the connection with 320 CONNECTION_FORCED 'credential expired' (4.2.6+). */
  onCredentialExpiredClose(listener: (connectionId: string) => void): () => void;
}

// libs/engine/svc-identity/src/provider.ts (new)
export type ProviderKind =
  | 'password' | 'client-credentials' | 'token-command' | 'static-token' | 'x509-external';
export type IssuedCredential =
  | { kind: 'password'; username: string; password: SecretValue }
  | { kind: 'bearer'; token: SecretValue; issuedAt: number; expiresAt: number | null; username: string | null }
  | { kind: 'external' };
export interface CredentialProvider {
  readonly kind: ProviderKind;
  acquire(
    request: { connectionId: string; protocol: CredentialProtocol },
    signal: AbortSignal,
  ): Promise<IssuedCredential>; // rejects with an AppError (a Problem), never a secret
}

// libs/engine/svc-identity/src/token-manager.ts (new)
export interface ResolvedCredential {
  readonly credential: IssuedCredential;
  /** Increments on each refresh. A 401 handler passes the generation it used, never the token. */
  readonly generation: number;
  readonly warnings: readonly SizeWarning[]; // emitted before this value is returned
}
export type TokenStateName =
  | 'valid' | 'refreshing' | 'failed' | 'expired' | 'username-changed';
export interface TokenState {
  readonly connectionId: string;
  readonly protocol: CredentialProtocol;
  readonly state: TokenStateName;
  readonly expiresAt: number | null;
  readonly nextRefreshAt: number | null;
  readonly consumersCancelled: number; // counted, never silent (I-13)
}
export interface TokenManager {
  credentialFor(connectionId: string, protocol: CredentialProtocol, signal: AbortSignal): Promise<ResolvedCredential>;
  /** Registers a live connection for renewal; returns a handle that stops it. */
  track(target: { connectionId: string; protocol: RenewalProtocol }): { release(): void };
  /** One refresh after the broker answered 401; a no-op if `generation` is no longer current. */
  refreshAfterUnauthorized(connectionId: string, protocol: CredentialProtocol, generation: number, signal: AbortSignal): Promise<ResolvedCredential>;
  state(connectionId: string, protocol: CredentialProtocol): TokenState | undefined;
  subscribe(listener: (state: TokenState) => void): () => void;
  dispose(): Promise<void>;
}
export function createTokenManager(deps: TokenManagerDeps): TokenManager;

// libs/engine/svc-identity/src/internal/renewal-plan.ts (pure)
export type RenewalAction = 'update-secret' | 'put-auth-token' | 'reconnect' | 'push-none';
export function renewalActionFor(
  protocol: RenewalProtocol,
  caps: { amqp10TokenRenewalEndpoint: boolean },
): RenewalAction;
export type ExpiryRule = 'cancel-own-consumers' | 'reconnect-on-forced-close';
export function expiryRuleFor(caps: { amqp091ClosesAtCredentialExpiry: boolean }): ExpiryRule;

// libs/engine/svc-identity/src/size-preflight.ts (pure)
export type SizeWarningCode = 'BEARER_HEADER_LARGE' | 'PLAIN_RESPONSE_LARGE';
export interface SizeWarning {
  readonly code: SizeWarningCode;
  readonly textKey: string; // identity.<code>.v1, English in i18n/en/warnings.json
  readonly bytes: number;
  readonly limit: number;
}
export const BEARER_HEADER_WARN_BYTES = 4000;
export function preflightSize(input: {
  token: string; username: string; protocol: RenewalProtocol | 'http'; asBasic: boolean;
  caps: { amqp091PreAuthFrame8192: boolean };
}): readonly SizeWarning[];
export function isRetryableAfter401(method: string): boolean; // GET, HEAD, OPTIONS only (OQ-1459)
```

Consumed from existing projects: `ConnectionStore.credentials`, `FieldSealer.open` (`@app/ports`, the same pair `apps/engine/src/broker/endpoints.ts` uses), `AppError` and `createCanaryScanner` (`@app/kernel`), `registry.capability(id, profile)` (`@app/semantics`), `eraOf`/profile node versions (`svc-capabilities` through the profile, never by import), the injected clock and timer of the kernel.

New capability rules in `auth-capabilities.data.ts` (OQ-1452; every rule needs `citations`, and each holds only while every node is inside the range):

| id | versions | meaning |
| --- | --- | --- |
| `amqp091ClosesAtCredentialExpiry` | `>=4.2.6` | The broker closes an AMQP 0-9-1 connection with 320 when the credential expires. Below it, consumers keep running and permission checks fail. |
| `amqp10TokenRenewalEndpoint` | `>=4.1.0` | `PUT /auth/tokens` renews an AMQP 1.0 connection. |
| `amqp091PreAuthFrame8192` | `>=4.1.0` | The pre-auth frame limit is 8,192 bytes; below it is 4,096. |

- **No `undici`.** The adapter uses Node's HTTP client over a socket the Dialer opens, the way `adapter-prometheus` does, so the generator ran without `--confine=undici` and `eslint.config.mjs` is unchanged (a confinement row for a package the project does not import would only loosen the table). - **Request.** `POST` with the client id and secret form-encoded and base64-ed in the HTTP Basic `Authorization` field (RFC 6749 2.3.1), and `grant_type`, `scope` and `audience` in the form body. Redirects are never followed (`malformed`); a login in the URL is `malformed`; plain `http` beyond loopback is `egress-denied` before any dial.
- **Answer.** At most 64 KiB, a declared `Content-Length` above it ends the read at the headers; a 200 answer needs a JSON media type, a token of the bearer-token character set, a `token_type` and an `expires_in` that is a positive number (or a digit string) or absent. Status map: 408/504 `timeout`, 429/5xx `unreachable`, 3xx `malformed`, other non-2xx `refused`.
- **Provider Problems.** `refused` is `UNAUTHENTICATED`; `unreachable` and `timeout` are `BROKER_UNREACHABLE`; `egress-denied` and `tls-untrusted` keep their own codes; `malformed`, `too-large` and a token type other than `bearer` are `BROKER_ERROR` (the spec named no code for them); an unreadable token is `VALIDATION_FAILED` through the shared bearer rules. The provider bounds the wait itself (20 s, `timeoutMs` in tests) as well as the adapter (15 s), and a port that rejects or throws is reported as `unreachable` with no `cause`.
- **Config.** `client-credentials` has `endpoint` (`https`, or `http` on `localhost`, `127.x` or `[::1]`; no login, no fragment), `clientId`, optional `scope` and `audience`, and `usernameClaims`. The client secret is the profile's stored secret, read through `StoredLoginPort`.

The row's text was first written for the whole of M1-24 (sign-in, discovery, key set); after the slice B review it is narrowed to what exists (feature "Broker OAuth (client credentials)", destination "The token endpoint of an identity provider an administrator configured (client credentials)", trigger "A credential acquisition or refresh"). "Built" means the adapter that dials the purpose is in the repository; nothing in the engine wires it until slice E. M1-24 widens the row when sign-in, discovery and the key set land.

## As built: hardening after the slice B review (2026-10-26)

An independent review of slice B (commits 2b6fa3f and dfb8b29) found no exploitable flaw. These items were fixed in follow-up commits on top of slice B; none changes a requirement or an AC.

- **N1, the `Host` header.** The agent's default port is 80, so an https endpoint on 443 was sent with `Host: idp.example.test:443`. The token endpoint now sends the URL's host (`url.host`): the scheme's default port is left out, any other port and a bracketed IPv6 literal are kept. `adapter-prometheus` had a hand-copied `DialerAgent` with the same flaw and is fixed in its own commit (`hostHeader` in `transport.ts`). Tests assert the `Host` header a real listener receives for https default and non-default ports, http default and non-default ports, and IPv6 literals, at both adapters.
- **N2, loopback by address, not by name.** Plain `http` was allowed for the name `localhost`, which the Dialer resolves with the system resolver. For `http:` the adapter now also requires that the connected socket's `remoteAddress` is on the loopback interface; otherwise it destroys the socket before a byte is sent and returns `egress-denied` (the request is written only after the agent hands over a socket, so the client secret does not leave). An https issuer is not subject to it. The name test and the address test are one pure module, `isLoopbackHost` and `isLoopbackAddress` in `libs/engine/ports/src/loopback.ts`, used by the adapter and by the provider config in `svc-identity`, so the two layers cannot drift (both may import `ports`; no new dependency). The name check accepts exactly `localhost`, `[::1]` and a dotted 127/8 address (no leading zeros, octets up to 255); the address check also accepts `::ffff:127.x.x.x` and fails closed on any form it does not know. Lookalike tests at both layers: `127.0.0.1.evil.test`, `evil.localhost`, `localhost.evil.test`, `notlocalhost`, `localhost.`, IPv4-mapped IPv6 literals, and a `localhost` that reaches `203.0.113.9`, `10.0.0.1`, `::ffff:203.0.113.9`, an empty or missing address (through a Dialer fake that connects to a loopback server but reports another peer). Manual mutations that were run and are killed: `hostname.endsWith('localhost')`, `startsWith`, a dropped `^` or `$` anchor, the octet bound, leading zeros, the address check off, the address check on for https, the socket not destroyed, the name check removed, a wrong failure code.
- **N7, the `oidc` row.** The row on the outbound-calls page described the whole of M1-24. It now reads feature "Broker OAuth (client credentials)", destination "The token endpoint of an identity provider an administrator configured (client credentials)", trigger "A credential acquisition or refresh", default "Never until a client-credentials provider is configured". The status stays `active`: the adapter that dials the purpose is in the repository, although nothing in the engine wires it before slice E. ## As built, slice C (2026-10-26)

Slice C (the TokenManager: renewal plan, username assertion, single flight, backoff and bounds; AC-9 to AC-17) differs from the text above in these ways. The files are `token-manager.ts`, `retry-policy.ts` and `internal/{renewal-plan,username-claim,limiter,signals}.ts` with their specs; `token-manager.spec.ts` holds AC-9 to AC-17 by name (AC-17 included, although `isRetryableAfter401` is declared in `retry-policy.ts` and not in `size-preflight.ts`, which slice D still creates).

- **Shape.** `createTokenManager({ providers, auth, capabilities, clock, timers, limits? })`. `providers` is a `ProviderLookup` (`providerFor(connectionId, protocol)`; slice E implements it over the `credential_providers` store and the provider factories), `auth` is `ConnectionAuthPort`, `capabilities(connectionId)` returns the two renewal flags and is asked at each use, so slice D only has to feed it from the registry. Nothing is logged: state changes go to subscribers (slice E logs there).
- **Additions to the interface of this spec.** `TokenState.problem` (a fixed-text Problem or null), `TokenManager.stats()` (entries, listeners, in-flight renewals, `pendingOperations`, `pendingTasks`, and the counters of refusals, evictions, listener errors and coalesced 320 closes: I-13), and an optional `generation` on `track` (the generation the connection logged in with; one that is behind is pushed at once). `ResolvedCredential.warnings` is **not** there: slice D adds it with `SizeWarning`. Generations come from one counter for the whole manager, so a stale 401 for an entry that was evicted and made again cannot look current.
- **Timers only for tracked entries.** `track` registers a live connection; only a tracked entry has a refresh timer and an expiry timer. An untracked entry (a plain HTTP caller) is renewed lazily by the `credentialFor` after its 75 % point, and reports `expired` from the clock without a timer. `track` before the first `credentialFor` makes a placeholder entry; the first token is then taken to be the one that connection holds, and is not pushed to it.
- **Single flight, and the push comes after.** Callers that arrive during a renewal share it; the shared promise settles when the new credential is adopted, and the push to the live connections starts only after that. The blueprint 7.5 "lazy credentials" reconnect asks `credentialFor` for its login while the manager is reconnecting it; had the push been inside the flight that call would wait for itself. A test makes a `reconnect` call `credentialFor` and checks it gets the new token. The flight has its own abort controller (a caller that gives up leaves it running for the others), and every provider call and push is cut off after `operationTimeoutMs` (30 s) or at `dispose`.
- **Renewal plan (OQ-1458).** The point is `iat + floor(3 * (exp - iat) / 4)` in integer milliseconds, never before 5 s after the start of the last refresh and never after `exp`. A future `iat` is read as the time the token arrived (N9: clamped, not refused: refusing would reject a token the broker accepts). A token with no `exp` (and no `expires_in`, which the provider already folded in) is held as it is: no refresh timer, no expiry timer, `expiresAt` and `nextRefreshAt` null, until `credentialFor` is asked and the token is still the same. A token already expired on arrival is `TOKEN_EXPIRED` and leaves no entry. A renewal that does not expire later than the token it replaces is refused for a scheduled or on-demand renewal (it would renew in a tight loop, and a command that caches would do that); not for a 401 or a forced reconnect.
- **Backoff and the floor.** A failed attempt retries after 2 s, doubling to 60 s, at most 8 attempts per lifetime (the 9th provider call of the first token is the 8th retry), and a retry that would fall on or after `exp` is not made. The 5 s floor is a floor on the *start* of a renewal on demand (a 401, an expired token, the lazy path), so an on-demand attempt waits for the longer of the floor and the backoff; a scheduled retry follows the backoff alone (2 s). After the cap nothing is scheduled until the token expires; a later `credentialFor` may still try once the wait is over. There is no jitter (the schedule is deterministic for the tests): OQ-1507.
- **Username assertion (DC-37).** The first bearer token fixes the name. A renewal with another name is refused as `username-changed`, one with no name as `failed`, both `UNAUTHENTICATED`, neither reaches `ConnectionAuthPort`, and neither starts an automatic retry (the old token goes on; after its expiry `credentialFor` may try once the wait is over). A renewal that changes the kind of credential is refused too. A first token that has no name is accepted, but then every renewal is refused (a missing name cannot be checked): OQ-1505. Changed by the hardening section below: the name is kept apart from the entry, and a first token with an expiry and no name is refused (OQ-1532).
- **Push per protocol (AC-12).** As specified; the push to each distinct protocol of an entry is made once per generation, a push that fails is retried alone (without asking the provider again) with the same backoff, and the failure is `BROKER_ERROR` with a fixed text, never what the connection layer said. A token that has expired is not pushed.
- **Expiry (AC-13, AC-14).** At `exp` the state is `expired` (a `username-changed` state stays, so the reason is not lost). With `amqp091ClosesAtCredentialExpiry` false the manager calls `cancelOwnConsumers` once for an entry that has a non-HTTP connection and adds the count to `consumersCancelled` (a count that is not a whole number of at least zero is not believed). With it true it waits for the 320 close. A 320 for an entry tracked as `amqp091` acquires a fresh token (a forced renewal, which skips the progress rule) and reconnects once, under either rule; one inside the 5 s floor or while a reconnect is running is ignored and counted. Only `amqp091` is reopened this way, and a failed reconnect is recorded and not retried here (the ConnectionManager owns reconnecting): OQ-1508.
- **Bounds (AC-16).** At most 256 entries (an idle one is evicted, oldest used first, before a new one is refused with `BUDGET_EXCEEDED`; one with a target, a renewal or a push running is never evicted), 32 listeners (`subscribe` throws `BUDGET_EXCEEDED` beyond it), 8 provider calls at once (the rest wait in order and leave the line when the manager stops), 30 s per operation. Every refusal is counted in `stats()`. `limits` overrides any of them and is validated when the manager is made. Entries are not removed when a profile's provider or secret changes: slice E has to drop them with `invalidate` (OQ-1506; the call is built in the hardening section below).
- **Dispose.** Aborts every flight and push, clears every timer, stops listening for 320 closes, refuses later calls with `ENGINE_SHUTTING_DOWN`, and returns one promise that settles when no task is left (`stats().pendingTasks` is 0).
- **Verification.** `pnpm nx run-many -t lint typecheck test -p svc-identity ports adapter-token-endpoint`, `pnpm nx test svc-identity --testNamePattern="AC-9|AC-11|AC-13|AC-14"`, `pnpm nx test arch-tests`, `pnpm nx run supply-chain:gates`, `pnpm format:check`, `pnpm nx affected -t lint typecheck test --base=origin/main`. No Docker daemon is needed.
- **Mutation pass (manual).** A manual pass over the renewal arithmetic (the 75 % numerator and denominator, rounding, the future-`iat` clamp, the floor and the ceiling), single flight, the backoff (growth, cap, attempt limit, "before `exp`"), the username assertion, the no-expiry and future-`iat` paths, the bounds, the 401 and 320 handling and `dispose`: about 200 textual mutations, each applied alone with the specs re-run and the tree restored after. First pass: 41 pure-rule mutants (40 killed; the survivor was an exponent cap that `Math.min` made redundant, now removed) and 151 manager mutants (108 killed, 42 survived, 1 did not apply). The survivors led to 21 more tests and four code changes: a failed push is settled when its connection was released, `pendingOperations` and `pendingTasks` in `stats()` (a controller that is never removed, or a task `dispose` does not wait for, was invisible), a simpler count guard and no retry time kept for a terminal entry. - **Size.** Slice C is about 3,400 hand-written lines (about 2,040 of them tests), over the 800-line guidance; it lands as two commits (the pure rules, then the manager).

## As built: hardening after the slice C reviews (2026-10-26)

Two fresh reviews of slice C (a `/review-wp` and a `security-review`) found the issues below; this section records what was changed (`Refs #108`; the issue stays open, slices D and E remain). The code is in `token-manager.ts`, the tests are in `token-manager.spec.ts` and the new `internal/limiter.spec.ts`. Where this section and "As built, slice C" disagree, this section wins.

- **Username continuity (security Vuln 1, review F3).** The expected user name used to live in the entry, and an idle entry is evicted when the table (256, across all tenants) is full: alice for c1, another connection takes the slot, c1 comes back with mallory and is accepted. A probe test reproduced the chain on the code of slice C before the fix. The first name of each (connection, protocol) now lives in a separate table (`knownUsernames`, 4,096 names of at most 256 characters: I-6) that eviction never touches; only `invalidate(..., { forgetUsername: true })` removes a row. The first token of a new entry is compared with it: another name is refused (`UNAUTHENTICATED`, state `username-changed`, counted in `usernameRefusals`), and a full table refuses a token that needs a new row (`BUDGET_EXCEEDED`, `refusedKnownUsernames`) instead of forgetting an old one. `track` takes an optional `username` (the name the connection logged in with): it becomes the remembered name, or a mismatch is refused with a Problem. OQ-1533.
- **`invalidate(connectionId, protocol?, { forgetUsername? })` (OQ-1506).** Drops the cached credential, the renewal timer, the failure count and the wait after a failure, aborts a renewal or push in flight and throws its late result away (an epoch and an abort scope per entry; a stale flight records nothing and does not clear a newer one). An untracked entry is deleted. A tracked entry keeps its expiry timer, because the live connection still holds the old token (state `invalidated`, then `expired` with the usual cancel of the engine's consumers) and is brought up to date when something asks `credentialFor` again. The user name is kept unless asked. It does nothing after `dispose`. **Slice E must call it** on a profile edit or delete, a secret rotation, a vault lock and a prod lock, and the manager methods take no principal, so they must never be exposed through a route with a caller-chosen connection id. OQ-1534.
- **Token shapes (OQ-1505, OQ-1532).** A first bearer token with an expiry and no user name is refused at the first request (every renewal of it would be); one with no expiry is held, since it is never renewed. A renewal that drops the expiry the previous token had is refused for every reason. A name over 256 characters is refused.
- **Sweep (item 4).** One timer for the whole manager, armed only while some entry has a deadline timer, looks at the tracked entries every `sweepIntervalMs` (10 s) and runs a refresh or an expiry that is more than 1 s past (a wall clock set forward, or a machine that slept, leaves the monotonic timers waiting). Bounded by the entry cap, one timer, each action counted in `sweptDeadlines`. OQ-1535.
- **Copies of the Problem (item 5).** `TokenState.problem` is a copy for every reader, and every listener gets its own snapshot.
- **F1.** `capabilities()` is read inside the expiry timer callback; a throw there would have ended the process. It is caught, counted (`capabilityErrors`), and the engine takes the conservative branch (cancel its own consumers).
- **F2.** The limiter slot was already returned in a `finally`; the probe test proves it (and fails when the release is moved out of it). `armAt` re-arms an early timer and `onExpiry` still checks `exp`; the new test fails when `armAt` does not re-arm. The work started at expiry and at a 320 close is counted in `pendingTasks`. The "dead branch" of `armWake` was checked: the branch that picks the 75 % point when it is sooner than a retry is reachable (a 401 that fails 1 s before the point), it was only never exercised, and a test now covers it; nothing was deleted. A new `limiter.spec.ts` covers the limiter.
- **F4.** A first token that failed leaves its entry behind with the failure count and the wait (the floor and the backoff of a renewal); a request inside the wait is answered with the last Problem and no provider call (`coolingRefusals`). Twenty immediate failing requests make one provider call. A cooling entry is not evicted for room. OQ-1536.
- **F5.** A connection that was just closed (320) is left out of the push list until its reconnect has run, so a scheduled renewal in flight no longer sends `update-secret` to a closed connection; a push already on the wire is not recalled. The push loop also stops at a newer token (it never hands a replaced token to a connection that is later in the list). OQ-1508.
- **F6.** AC-17 proves the predicate `isRetryableAfter401` only; nothing enforces it until the HTTP client (a later slice) uses it. Recorded in OQ-1537.
- **Not done, for later slices (OQ-1537).** Per-protocol expiry rule with a watchdog of about 10 s that closes or suspends publishers through `ConnectionAuthPort` (a new port method: slice E); the TLS trust of each identity provider (N3); the wiring of `invalidate` and an adversarial review of it; the token command runner only in delivery modes that allow commands.
- **Bounds (changes to the slice C list).** Entries: 256, but a cooling entry is not evictable. New: 4,096 remembered user names of at most 256 characters, one sweep timer, `maxKnownUsernames` and `sweepIntervalMs` in `limits`. Everything that is refused is counted in `stats()`: `usernameRefusals`, `refusedKnownUsernames`, `coolingRefusals`, `capabilityErrors`, `sweptDeadlines`, `invalidations`, and `knownUsernames` shows the table size.
- **Verification.** As for slice C, plus `pnpm nx test svc-identity --testNamePattern="hardening"`.
- **Mutation pass (manual, 122 mutants).** Each mutant applied alone, the specs re-run, the tree restored (the runner is kept outside the repository, as for slice C). Over the username table, `invalidate`, the epoch and scope, the sweep, the cooling wait, the push list, the Problem copies, the `capabilities()` guard and the F2 targets (the limiter release, `armAt` re-arming, `trackBackground`, the floor counted from the start, the equal-expiry rule on `demand`, the `renewed` flag, the operation timeout, the cancel failure text, the `refreshing` publish, the stale 401, pre-aborted requests). First pass: 84 killed, 36 survived, 1 did not apply (its text matched twice) and 1 hung (an endless loop in the push list: a kill by non-termination). The survivors led to 9 more tests (every refusal counted, the failure count, problem and expired state after `invalidate`, a request waiting for a slot, a late expiry left to its timer, a cooling-free eviction, the floor from the start, a pre-aborted 401 with an entry) and 6 removals of lines that turned out dead or redundant (the `retryNotBefore` reset in `invalidate`, the epoch checks in the push loop, the forced-close pre-marking in `adopt`, a replaced-entry check in the sweep). Final: 116 mutants applied against the final code, 106 killed (one by non-termination), 10 survived, none changes behaviour a spec could observe: clearing `entry.pushing` at `invalidate` and the identity guard in its `finally` (the old push loop ends within a few microtasks of the abort, a race the manual timers cannot order), resetting `terminal` at `invalidate` (`adopt` resets it), the epoch re-check after the provider answers (the abort rejects first, so it cannot be reached), the sweep being synced in `armWake` and `onWake` (the neighbouring calls keep it in step), `!disposed` in the sweep's need (`dispose` disarms every entry), `hasTimer` ignoring a wake-only entry (a refresh point always comes with an expiry), removing the abort listener from the scope (a leak, not behaviour), and the already-aborted scope branch of `guarded` (the limiter refuses first). The mutation pass of slice C over the unchanged code stands.
- **Size.** About 1,750 hand-written lines (about 1,360 of them tests), over the 800-line guidance because the reviews asked for the fixes and their probe tests together; it lands as two commits (the probe tests that already hold, about 500 lines, then the fixes with the rest of the tests, about 1,250 lines and the docs).

## As built, slice D (2026-10-26)
