# M1-23 Credential providers and TokenManager (CON-07 core, DC-37/38)

**Issue:** #108 · **Milestone:** M1 · **Wave:** M1-W2 · **Size:** L · **Owner area:** engine / identity · **trust:critical:** yes

## Goal

Pluggable broker credential providers (password, client credentials, token command, static token, x509/EXTERNAL) and a `TokenManager` that renews a token at 75 % of its lifetime, per protocol, and refuses a refreshed token whose username claim differs from the first one. It also warns before use when a token is too large for the broker's header or pre-auth frame limits, and cancels the engine's own consumers at expiry on brokers that do not close the connection. Serves CON-07 (core), DC-37, DC-38, blueprint §7.5 and the invariants I-3, I-9, I-10 below.

Scope boundary: OAuth discovery, PKCE loopback, device code and issuer pinning are M1-24 (DC-39); the Keycloak 26 lab variant and the recorded expiry behaviour per version are M1-25 (U-14); the Vault/OpenBao and delegated-user providers are later work. This WP ships the engine core and its ports. It adds no HTTP action and no UI (see Out of scope and OQ-1455).

### Interfaces

```ts
// libs/engine/ports/src/identity.ts (new)
export type RenewalProtocol = 'http' | 'amqp091' | 'amqp10' | 'stream';

/** One RFC 6749 4.4 request. The secret is in `clientSecret` and nowhere in the URL. */
export interface TokenRequest {
  readonly endpoint: string; // https URL, or http only for a loopback lab issuer (OQ-1462)
  readonly clientId: string;
  readonly clientSecret: string;
  readonly scope?: string;
  readonly audience?: string;
}
export type TokenEndpointFailure =
  | 'unreachable' | 'egress-denied' | 'tls-untrusted' | 'timeout' | 'refused'
  | 'malformed' | 'too-large';
export type TokenResponse =
  | { ok: true; accessToken: string; expiresInSeconds: number | null; tokenType: string }
  | { ok: false; reason: TokenEndpointFailure };
export interface TokenEndpointPort {
  requestToken(request: TokenRequest, signal: AbortSignal): Promise<TokenResponse>;
}

/** Runs a configured command without a shell. Implemented in apps/engine (OQ-1460). */
export interface CommandRunnerPort {
  run(
    command: { readonly file: string; readonly args: readonly string[] },
    limits: { readonly timeoutMs: number; readonly maxStdoutBytes: number },
    signal: AbortSignal,
  ): Promise<
    | { ok: true; stdout: string }
    | { ok: false; reason: 'spawn-failed' | 'exit-nonzero' | 'timeout' | 'too-large' }
  >;
}

/** What the TokenManager asks of a live connection. The ConnectionManager implements it. */
export interface ConnectionAuthPort {
  /** AMQP 0-9-1 `connection.update-secret`. Rejects when the broker refuses (for example a different user). */
  updateSecret(connectionId: string, secret: string, reason: string): Promise<void>;
  /** AMQP 1.0 `PUT /auth/tokens` (4.1+). No implementation until M1-07 (OQ-1464). */
  putAuthToken?(connectionId: string, token: string): Promise<void>;
  /** Close and open again with the current credential (AMQP 1.0 on 4.0, streams). */
  reconnect(connectionId: string, protocol: RenewalProtocol): Promise<void>;
  /** Cancel the consumers the engine itself holds on this connection. Returns how many. */
  cancelOwnConsumers(connectionId: string, reason: 'token-expired'): Promise<{ cancelled: number }>;
  /** The broker closed the connection with 320 CONNECTION_FORCED 'credential expired' (4.2.6+). */
  onCredentialExpiredClose(listener: (connectionId: string) => void): () => void;
}

// libs/engine/svc-identity/src/provider.ts (new)
export type ProviderKind =
  | 'password' | 'client-credentials' | 'token-command' | 'static-token' | 'x509-external';
export type IssuedCredential =
  | { kind: 'password'; username: string; password: SecretValue }
  | { kind: 'bearer'; token: SecretValue; issuedAt: number; expiresAt: number | null; username: string | null }
  | { kind: 'external' };
export interface CredentialProvider {
  readonly kind: ProviderKind;
  acquire(
    request: { connectionId: string; protocol: CredentialProtocol },
    signal: AbortSignal,
  ): Promise<IssuedCredential>; // rejects with an AppError (a Problem), never a secret
}

// libs/engine/svc-identity/src/token-manager.ts (new)
export interface ResolvedCredential {
  readonly credential: IssuedCredential;
  /** Increments on each refresh. A 401 handler passes the generation it used, never the token. */
  readonly generation: number;
  readonly warnings: readonly SizeWarning[]; // emitted before this value is returned
}
export type TokenStateName =
  | 'valid' | 'refreshing' | 'failed' | 'expired' | 'username-changed';
export interface TokenState {
  readonly connectionId: string;
  readonly protocol: CredentialProtocol;
  readonly state: TokenStateName;
  readonly expiresAt: number | null;
  readonly nextRefreshAt: number | null;
  readonly consumersCancelled: number; // counted, never silent (I-13)
}
export interface TokenManager {
  credentialFor(connectionId: string, protocol: CredentialProtocol, signal: AbortSignal): Promise<ResolvedCredential>;
  /** Registers a live connection for renewal; returns a handle that stops it. */
  track(target: { connectionId: string; protocol: RenewalProtocol }): { release(): void };
  /** One refresh after the broker answered 401; a no-op if `generation` is no longer current. */
  refreshAfterUnauthorized(connectionId: string, protocol: CredentialProtocol, generation: number, signal: AbortSignal): Promise<ResolvedCredential>;
  state(connectionId: string, protocol: CredentialProtocol): TokenState | undefined;
  subscribe(listener: (state: TokenState) => void): () => void;
  dispose(): Promise<void>;
}
export function createTokenManager(deps: TokenManagerDeps): TokenManager;

// libs/engine/svc-identity/src/internal/renewal-plan.ts (pure)
export type RenewalAction = 'update-secret' | 'put-auth-token' | 'reconnect' | 'push-none';
export function renewalActionFor(
  protocol: RenewalProtocol,
  caps: { amqp10TokenRenewalEndpoint: boolean },
): RenewalAction;
export type ExpiryRule = 'cancel-own-consumers' | 'reconnect-on-forced-close';
export function expiryRuleFor(caps: { amqp091ClosesAtCredentialExpiry: boolean }): ExpiryRule;

// libs/engine/svc-identity/src/size-preflight.ts (pure)
export type SizeWarningCode = 'BEARER_HEADER_LARGE' | 'PLAIN_RESPONSE_LARGE';
export interface SizeWarning {
  readonly code: SizeWarningCode;
  readonly textKey: string; // identity.<code>.v1, English in i18n/en/warnings.json
  readonly bytes: number;
  readonly limit: number;
}
export const BEARER_HEADER_WARN_BYTES = 4000;
export function preflightSize(input: {
  token: string; username: string; protocol: RenewalProtocol | 'http'; asBasic: boolean;
  caps: { amqp091PreAuthFrame8192: boolean };
}): readonly SizeWarning[];
export function isRetryableAfter401(method: string): boolean; // GET, HEAD, OPTIONS only (OQ-1459)
```

Consumed from existing projects: `ConnectionStore.credentials`, `FieldSealer.open` (`@app/ports`, the same pair `apps/engine/src/broker/endpoints.ts` uses), `AppError` and `createCanaryScanner` (`@app/kernel`), `registry.capability(id, profile)` (`@app/semantics`), `eraOf`/profile node versions (`svc-capabilities` through the profile, never by import), the injected clock and timer of the kernel.

New capability rules in `auth-capabilities.data.ts` (OQ-1452; every rule needs `citations`, and each holds only while every node is inside the range):

| id | versions | meaning |
| --- | --- | --- |
| `amqp091ClosesAtCredentialExpiry` | `>=4.2.6` | The broker closes an AMQP 0-9-1 connection with 320 when the credential expires. Below it, consumers keep running and permission checks fail. |
| `amqp10TokenRenewalEndpoint` | `>=4.1.0` | `PUT /auth/tokens` renews an AMQP 1.0 connection. |
| `amqp091PreAuthFrame8192` | `>=4.1.0` | The pre-auth frame limit is 8,192 bytes; below it is 4,096. |

## Risks / questions

Each question has a default this spec implements. None is answered by this spec. New ids continue from OQ-1437 (the last used, in the M1-12 section of `docs/open-questions.md`); they are added there with this spec.

- **OQ-1451 (no Keycloak in the lab).** The issue's first criterion says "a 4.3 broker with Keycloak". The lab has the broker's oauth2 backend with a per-run signing key, and no identity provider. Default: AC-24 and AC-25 run on that `oauth` variant with tokens minted by the test, which exercises the broker's real `update-secret`, username check and expiry handling; a real Keycloak 26 run belongs to M1-25 (#110, open). The TokenManager is not GA (no UI offers it) until M1-25's cells are green (U-14).
- **OQ-1452 (the renewal matrix is registry data).** No registry row says when a broker closes a connection at credential expiry, which versions renew AMQP 1.0, or the pre-auth frame size. I-3 forbids comparing versions in `svc-identity`. Default: three capability rules (table above), `code-derived`, each citing the source reading in `docs/research/auth-network-security.md` (V12, V13, V41, V09) and the release notes it names. The 4.2.5/4.2.6 split is a source reading (V13), not a lab result. CF-AUTH-* cells and the lab confirmation come with M1-25.
- **OQ-1453 (verification versions).** Default: the `it` target runs 4.1.8, 4.2.9 and 4.3.6; 4.1.8 is the only lab build (with 3.13.7 and 4.0.9) that behaves as "4.2.5 or earlier". The command in the issue is changed; please confirm.
- **OQ-1454 (the AMQP adapter has no `updateSecret`).** The issue's scope lists only `svc-identity` files, but update-secret needs the adapter. Default: a small additive change in `adapter-amqp091` and `ports` (slice E, counted in the size estimate), reached by the TokenManager only through `ConnectionAuthPort`, which the ConnectionManager implements at the composition root.
- **OQ-1455 (where provider configuration lives).** A profile keeps one sealed secret per protocol and a strict versioned config with only `basic`/`bearer`/`plain`/`none`. A provider needs non-secret settings (token endpoint, client id, scope, command and arguments, username claims). Default: do not change `StoredConfigSchema`; store them in a new table `credential_providers` (key: connection id and protocol; JSON validated by the provider's zod schema; the secret stays in the existing sealed `credentials` row) behind a `CredentialProviderStore` port, with an in-memory fake for tests. No action or UI writes it in this WP; a follow-up issue adds the action and form. Alternative: a `StoredConfig` v2 migration. The migration (about 150 lines with its spec) can be deferred if the maintainer prefers; slice E then reads the store from the fake only.
- **OQ-1456 (username claim, opaque tokens, error code).** The broker names an OAuth user from `preferred_username_claims`; the research notes (V21) give the default as `sub` then `client_id`, which this repository has not read from source. Default: a per-provider `usernameClaims` list, default `['sub','client_id']`; the first token fixes the expected name; a refreshed token with a different or missing name is refused (fail closed, AC-11); a token that is not a readable JWT is refused (the broker's oauth2 backend validates JWTs). The refusal uses the existing `UNAUTHENTICATED` Problem. A dedicated code such as `IDENTITY_USERNAME_CHANGED` would change the contracts (and `api-docs`): not done unless the maintainer asks.
- **OQ-1457 (pre-auth frame headroom).** The frame limit covers the whole `connection.start-ok` frame, not only the PLAIN response; the size taken by client properties and mechanism name is not measured. Default: `PREAUTH_HEADROOM_BYTES = 1024`, a stated estimate, so the warning says "may exceed"; M1-25 records the real thresholds and the constant is replaced by them. The Bearer header threshold (4,000 B) is the issue's value.
- **OQ-1458 (refresh policy details).** The issue fixes only 75 %. Defaults: the lifetime is `exp - iat` (the acquisition time when `iat` is absent); the provider-reported `expires_in` is used only when the token is not a JWT with `exp`; a token without `exp` is not scheduled and is reported as such; a floor of 5 s between refreshes and between forced-close reconnects; backoff 2 s doubling to 60 s with at most 8 attempts before `exp`; a token already expired on acquisition is refused with `TOKEN_EXPIRED`.
- **OQ-1459 (the 401 retry).** DC-37 says only idempotent requests are retried after a 401. Default: `isRetryableAfter401` allows GET, HEAD and OPTIONS (narrower than RFC 9110 idempotence, because PUT and DELETE on the management API change broker state); `refreshAfterUnauthorized` is delivered here and the retry wiring in `adapter-mgmt-http` (with the I-8 `BrokerScheduler` path) is a follow-up issue.
- **OQ-1460 (the token command).** A configured command is code execution. Default: argv array, `execFile` semantics (no shell), a 10 s timeout, a 16 KiB stdout cap, an allow-listed minimal environment, stderr never returned or logged, run through `CommandRunnerPort` implemented in `apps/engine`. It is registered only in delivery modes that run on the person's own machine (`desktop`, `local`); in the team server the port is absent and the provider fails closed. The mode check lives in `apps/engine/src/{entry,modes,modules}` as AGENTS.md section 8 requires. Please confirm the mode list and the limits.
- **OQ-1461 (x509/EXTERNAL cannot connect yet).** `net-truststore` has no client certificate, and `AmqpAuthKindSchema` has no `external`, although the AMQP adapter already speaks EXTERNAL. Default: the provider and its contract ship (AC-4); presenting the certificate needs a follow-up issue for `TlsTrust` and the profile schema, and the provider is not offered by any action until then. The HTTP API has no certificate login (V24).
- **OQ-1462 (the token request, the `oidc` purpose).** A service cannot import `undici`. Default: a new adapter `adapter-token-endpoint` behind `TokenEndpointPort` (M1-24 will reuse it), dialling through the Dialer with purpose `oidc`; the purpose goes `planned` to `active` and the generated outbound-calls page is regenerated (a reviewed change). No new dependency: the request is a small form POST built by hand, so no `openid-client` and nothing in the catalog or the allow-list changes. Plain `http` is accepted only for a loopback issuer (the lab); everything else must be `https` verified by the TrustStore.
- **OQ-1463 (I-2 and the housekeeping calls).** `updateSecret`, `reconnect` and cancelling the engine's own consumers touch a connection but not a user's messages, and run from a timer, not from a user action. Default: `svc-identity` holds no `WritePort` and no lease; it calls `ConnectionAuthPort`, which the ConnectionManager implements; the architecture test must stay green with no exception. Whether such timer-driven housekeeping should be a `defineJob` is the maintainer's call (AGENTS.md says the `defineJob` check is planned). Also: there is no `svc-tap` yet, so "without dropping taps" is proved with a consumer on a lab queue (AC-24) and with the fake source/observe leases in the unit tests.
- **OQ-1464 (AMQP 1.0 and streams).** `adapter-amqp10` (M1-07, #92) and a stream adapter do not exist. Default: the renewal plan and the `putAuthToken`/`reconnect` seams are built and unit-tested with fakes (AC-12); with no sink, the manager reconnects. - **OQ-1465 (size).** Estimate 3,400 to 4,200 changed lines including specs (sources about 1,500), far over the 800-line guidance. Proposed slices below; each lands as one commit on `main`. `oversize-approved` is not asked for, as in M1-12.

## As built, slice A (2026-10-26)

Slice A (`svc-identity`, the ports in `libs/engine/ports/src/identity.ts`, `SecretValue`, `readTokenClaims`, `ProviderConfigSchema`, and the password, static-token, token-command and x509-external providers) differs from the text above in these ways. The maintainer accepted the first.

- **`StoredLoginPort`.** A fourth port, beside `TokenEndpointPort`, `CommandRunnerPort` and `ConnectionAuthPort`. The providers do not consume `ConnectionStore.credentials` and `FieldSealer.open` directly, because the sealed-row location and the stored user name belong to `svc-connections`, which a service cannot import. `apps/engine` implements the port in slice E over `configOf` and `openSecret`. The alternative was to copy the sealing constants into `svc-identity`.
- **AC-5.** Its client-secret case needs the client-credentials provider, so slice B extends the AC-5 test; slice A covers the other secrets.
- **Refusals.** A token that cannot be read as a JWT is refused with `VALIDATION_FAILED`. The token command also refuses output above its cap (`UNAUTHENTICATED`) even if the runner reports success. Failure texts are fixed per reason.
- **`ProviderConfigSchema`** had no `client-credentials` kind in slice A; slice B added it.
- **Hardening from the adversarial review (2026-10-26).** (1) The calls to `CommandRunnerPort.run` and `StoredLoginPort.open` are wrapped: a rejection becomes a fixed-text `AppError` with no `cause`, because a spawn error carries the command line. (2) A token whose expiry is more than 366 days away, or whose `exp` or `expires_in` overflows the millisecond range, is refused with `VALIDATION_FAILED` (the maintainer-approved bound; it keeps the TokenManager from holding a token that never renews or ends). (3) The token command's `file` must be an absolute path (POSIX, a Windows drive or a UNC share), so no PATH search or working-directory lookup happens (maintainer decision). Four `M1-23 hardening` tests prove them and fail without the fixes.
- **Size.** Slice A is about 1,000 hand-written lines (about 440 of them tests), over the 800-line guidance.

## As built, slice B (2026-10-26)

Slice B (`adapter-token-endpoint`, the `oidc` purpose, the client-credentials provider) differs from the text above in these ways.

- **No `undici`.** The adapter uses Node's HTTP client over a socket the Dialer opens, the way `adapter-prometheus` does, so the generator ran without `--confine=undici` and `eslint.config.mjs` is unchanged (a confinement row for a package the project does not import would only loosen the table). The files are `token-endpoint.ts` and `token-endpoint.spec.ts` as listed; the factory is `createTokenEndpoint({ dialer, trust, route?, timeoutMs? })`, and the generator's `TokenEndpointAdapter` placeholder class is not kept. CODEOWNERS still needs the line in Risks.
- **Request.** `POST` with the client id and secret form-encoded and base64-ed in the HTTP Basic `Authorization` field (RFC 6749 2.3.1), and `grant_type`, `scope` and `audience` in the form body. Redirects are never followed (`malformed`); a login in the URL is `malformed`; plain `http` beyond loopback is `egress-denied` before any dial.
- **Answer.** At most 64 KiB, a declared `Content-Length` above it ends the read at the headers; a 200 answer needs a JSON media type, a token of the bearer-token character set, a `token_type` and an `expires_in` that is a positive number (or a digit string) or absent. Status map: 408/504 `timeout`, 429/5xx `unreachable`, 3xx `malformed`, other non-2xx `refused`.
- **Provider Problems.** `refused` is `UNAUTHENTICATED`; `unreachable` and `timeout` are `BROKER_UNREACHABLE`; `egress-denied` and `tls-untrusted` keep their own codes; `malformed`, `too-large` and a token type other than `bearer` are `BROKER_ERROR` (the spec named no code for them); an unreadable token is `VALIDATION_FAILED` through the shared bearer rules. The provider bounds the wait itself (20 s, `timeoutMs` in tests) as well as the adapter (15 s), and a port that rejects or throws is reported as `unreachable` with no `cause`.
- **Config.** `client-credentials` has `endpoint` (`https`, or `http` on `localhost`, `127.x` or `[::1]`; no login, no fragment), `clientId`, optional `scope` and `audience`, and `usernameClaims`. The client secret is the profile's stored secret, read through `StoredLoginPort`.
- **`oidc` purpose.** Now `active`; its row on the outbound-calls page reads "Built". The row's text was first written for the whole of M1-24 (sign-in, discovery, key set); after the slice B review it is narrowed to what exists (feature "Broker OAuth (client credentials)", destination "The token endpoint of an identity provider an administrator configured (client credentials)", trigger "A credential acquisition or refresh"). "Built" means the adapter that dials the purpose is in the repository; nothing in the engine wires it until slice E. M1-24 widens the row when sign-in, discovery and the key set land.
- **AC-5.** The client-secret case is added to the slice A test: a success, a refusal, and a port that rejects with the secret in its message and `cause`.
- **Size.** Slice B is about 1,400 hand-written lines, about 840 of them tests, over the 800-line guidance; it lands as two commits (the adapter with the purpose, then the provider).

## As built: hardening after the slice B review (2026-10-26)

An independent review of slice B (commits 2b6fa3f and dfb8b29) found no exploitable flaw. These items were fixed in follow-up commits on top of slice B; none changes a requirement or an AC.

- **N1, the `Host` header.** The agent's default port is 80, so an https endpoint on 443 was sent with `Host: idp.example.test:443`. The token endpoint now sends the URL's host (`url.host`): the scheme's default port is left out, any other port and a bracketed IPv6 literal are kept. `adapter-prometheus` had a hand-copied `DialerAgent` with the same flaw and is fixed in its own commit (`hostHeader` in `transport.ts`). Tests assert the `Host` header a real listener receives for https default and non-default ports, http default and non-default ports, and IPv6 literals, at both adapters.
- **N2, loopback by address, not by name.** Plain `http` was allowed for the name `localhost`, which the Dialer resolves with the system resolver. For `http:` the adapter now also requires that the connected socket's `remoteAddress` is on the loopback interface; otherwise it destroys the socket before a byte is sent and returns `egress-denied` (the request is written only after the agent hands over a socket, so the client secret does not leave). An https issuer is not subject to it. The name test and the address test are one pure module, `isLoopbackHost` and `isLoopbackAddress` in `libs/engine/ports/src/loopback.ts`, used by the adapter and by the provider config in `svc-identity`, so the two layers cannot drift (both may import `ports`; no new dependency). The name check accepts exactly `localhost`, `[::1]` and a dotted 127/8 address (no leading zeros, octets up to 255); the address check also accepts `::ffff:127.x.x.x` and fails closed on any form it does not know. Lookalike tests at both layers: `127.0.0.1.evil.test`, `evil.localhost`, `localhost.evil.test`, `notlocalhost`, `localhost.`, IPv4-mapped IPv6 literals, and a `localhost` that reaches `203.0.113.9`, `10.0.0.1`, `::ffff:203.0.113.9`, an empty or missing address (through a Dialer fake that connects to a loopback server but reports another peer). Manual mutations that were run and are killed: `hostname.endsWith('localhost')`, `startsWith`, a dropped `^` or `$` anchor, the octet bound, leading zeros, the address check off, the address check on for https, the socket not destroyed, the name check removed, a wrong failure code.
- **N7, the `oidc` row.** The row on the outbound-calls page described the whole of M1-24. It now reads feature "Broker OAuth (client credentials)", destination "The token endpoint of an identity provider an administrator configured (client credentials)", trigger "A credential acquisition or refresh", default "Never until a client-credentials provider is configured". The status stays `active`: the adapter that dials the purpose is in the repository, although nothing in the engine wires it before slice E. The page is regenerated with `pnpm nx run net-dialer:outbound-calls`. M1-24 widens the row when sign-in, discovery and the key set land.

Decided for later slices, not done here:

- **N3, TLS trust per identity provider (slice E).** `createTokenEndpoint` binds one `TlsTrust` at construction, while the endpoint varies per request, so a profile with its own CA or the insecure-TLS override would apply to every issuer the adapter ever calls. Slice E must either take a trust per identity provider (the trust comes with the request, or a factory per profile) or refuse the insecure-TLS override for the `oidc` purpose, and document the choice in the README of `adapter-token-endpoint`.
- **N9, client authentication and tokens without a lifetime (slice C).** Only `client_secret_basic` is sent, so an identity provider that accepts only `client_secret_post` will not work; adding it is a config choice, not a default. A token with neither `exp` nor `expires_in` is accepted with `expiresAt` null; slice C must handle that per OQ-1458 (no `exp` means no schedule) and must also check that a future `iat` is refused or clamped.
- **Problem codes for identity-provider answers.** A malformed, too-large or non-bearer answer is `BROKER_ERROR` today, but "broker" means RabbitMQ everywhere else: OQ-1500. The mapping of an identity provider's 4xx answers is OQ-1501 and issue #295.
- **Follow-up issues (all refer to #108).** #293: pass an `AbortSignal` from the `DialerAgent` to `Dialer.dial` in `adapter-token-endpoint` and `adapter-prometheus` (N4). #294: one `DialerAgent` in `net-dialer` and an I-9 confinement row for `node:http`, `node:https`, `node:http2` and `node:dgram` (N5). #295: the identity-provider status-to-reason mapping (N6).
- **Needs a maintainer (CODEOWNERS is a protected path).** Add `/libs/engine/adapter-token-endpoint/ @RafaelJCamara` and `/libs/engine/svc-peek/ @RafaelJCamara` (finding B1).
