# M1-41 Command registry, palette, keymap and native menus (EXP-04)

**Issue:** #126 · **Milestone:** M1 · **Wave:** M1-W1 · **Size:** M · **Owner area:** ui · **trust:critical:** no

Status: working spec, written under the maintainer's standing agile-mode instruction (the spec-approval stop is waived; every choice below is a working default recorded as an additive row in `docs/open-questions.md`, OQ-824 onward). Checked against `a056296`. The issue depends on M0-51 (the web shell), which has landed; the explorer (M0-54) deliberately left "no context menu, no row activation, no command palette" to this work package (M0-54 Q-23).

## Goal

A VS Code-style command system for the web app, shared by the palette (Ctrl or Cmd+K), the keyboard shortcuts and, later, the desktop menus: one typed registry `{id, title, category, when, keybinding, run}` in a shared UI library, a keymap (defaults plus the person's overrides kept by the engine through `keybindings.get` and `keybindings.put`, conflicts reported and never silent), commands that are closed with the engine's reason when the engine's gates or `allowedActions` close them, a palette with a fuzzy filter, and a typed menu model generated from the registry that the desktop shell will hand to `PlatformBridge.setMenu`. Serves EXP-04, DC-31 (gates rendered as sent), DC-15 (honest wording), ADR-021 (no `innerHTML`, strict CSP), I-7 (nothing unbounded: the registry holds registered commands only, the palette draws at most 50 rows), I-13 (no silent loss: a failed load or save of the keymap, a conflict and a refused command are all said in words).

## Rules

**R1 Chords** (`chord.ts`). Text form `Mod+Shift+K`, `Alt+1`, `/`, `F1`, `Escape`: modifiers `Mod` (Ctrl; Cmd on macOS), `Ctrl`, `Meta`, `Alt`, `Shift` in any order and case, then one key. `parseChord` returns a canonical value or `null` (empty, unknown modifier, two keys, a modifier alone, over 64 characters); `formatChord` writes the canonical text; `displayChord(chord, platform)` writes the text a person reads (`Ctrl+K`, `Cmd+K` as the Cmd sign on macOS); `acceleratorOf(chord)` writes the desktop menu syntax (`CmdOrCtrl+K`). `matchesChord(event, chord, platform)`: exact modifier match (`Mod` is Meta on macOS, Ctrl elsewhere and the other one must be up); letters compare without case; a key that is one non-alphanumeric character (`/`, `?`) ignores Shift; an event with `AltGraph` active, `isComposing` or `repeat` never matches.

**R2 Reserved chords** (`reserved.ts`). `RESERVED_CHORDS` lists what a browser keeps for itself or what the product keeps by policy: new tab/window/private window, close tab, tab switching, reload, print, save, find, bookmark, address bar, history, developer tools, quit, hide, and the grid's cell chords (Ctrl+C, Shift+F10, ContextMenu). `reservedReason(chord)` returns why or `null`. A default binding that is reserved is a defect (a test fails); a reserved chord in the persisted overrides is reported as a conflict and is not bound.

**R3 Registry** (`registry.ts`). `CommandRegistry.register(def)` returns a dispose function; `def = {id, title, category, when?, keybinding?, action?, gate?, menu?, bindable?, run}`. `title` and `category` are text (or a function of signals, so a language change updates them). Registrations of one id stack: the latest wins, disposing it restores the one below. `commands()` is a computed list sorted by category then title, with the effective chords and the live availability. `when` is a function of the context getter and is evaluated inside a `computed`, so it is reactive; a command whose `when` is false is not listed and does not run. `execute(id)` runs a command only when it is listed and enabled, catches a throw or a rejected promise and reports it (R9); it never runs a command that is closed. `registerSource(signal)` adds a dynamic list (switch to a connection).

**R4 Contexts** (`context.ts`). `CommandContext.set(key, value)`/`get(key)` over a signal map of strings, booleans and null; `bind(key, signal)` ties a key to a signal for the life of an injection context. The shell sets `connection.active`; a page sets `explorer.page` (`overview`, `queues`, ...). The palette sets `palette.open`.

**R5 Availability** (`availability.ts`). A command is open (`{enabled: true}`) or closed with a reason, from the capability snapshot (`COMMAND_CAPABILITIES`: status `none | loading | unknown | ready`, `allowedActions`, `gates`): (a) `gate` (a function returning the engine's `GateDecision`, or a feature id looked up in `gates`): `enabled !== true` is closed and the reason and source are the engine's, as sent; (b) `action`: closed unless the snapshot is `ready` and the list has the action; the reasons are "capabilities are loading", "capabilities are not known" or "the engine does not allow `<action>` for you"; (c) `unavailable` (a function the feature supplies, for its own states such as the 10 s refresh floor). Anything else is open. A command with no requirement is open even while the snapshot is unknown (navigation needs no permission).

**R6 Keymap** (`keymap.ts`). Effective chords of a command: its override if one exists (`null` is "unbound", a string replaces every default), else its default chords. `keymap.conflicts()` lists every chord that two or more commands with a true `when` share (so two commands of different pages do not conflict), every reserved chord in use, and every override that does not parse. A chord in conflict is bound to nothing: the shortcut does not run either command and the host says why (R8). `keymap.assign(id, chord)` refuses (returns the reason) an unparseable, reserved or conflicting chord, unless `{replace: true}` which unbinds the others in the same save; `keymap.unbind(id)` and `keymap.reset()` write `null` and clear. Overrides for ids that are not registered stay in the document untouched.

**R7 Keymap store** (`keymap-store.ts`). Loads with `keybindings.get` once when the host starts; a failure leaves the defaults and sets `loadStatus: 'failed'` with the Problem as received. Every change is saved with `keybindings.put` (the whole document, after 400 ms without another change, or at once with `flush()`); a failed save keeps the override in force for the session, sets `saveStatus: 'failed'` with the Problem, and offers `retry()`. Both states are shown in words by the cheat sheet and announced.

**R8 Dispatcher** (`command-host.component.ts`). One `keydown` listener on the document (bubble phase, after the widgets under it have handled the key) matches the effective chords. It ignores an event that is `defaultPrevented`, a bare key (no Ctrl, Meta or Alt, and not a function key or Escape) typed in an input, textarea, select or editable element, and every chord while a modal other than the palette is open (`aria-modal` dialog). When the palette is open only `palette.open` (to close) and the palette's own keys are handled. A match calls `preventDefault` and `execute`; a closed command is not run and its reason is announced in the polite live region; a conflicting chord announces the conflict.

**R9 Announcements.** The host owns one visually hidden polite live region: result counts of the palette, "<command> is not available: <reason>", conflicts, load and save failures of the keymap, and a failed command ("<command> failed"). Nothing in the registry is silent.

**R10 Fuzzy filter** (`fuzzy.ts`). `rankCommands(query, items, limit)` scores a subsequence match of the query's non-space characters over the title and the id (the id's dotted segments count as word starts): consecutive characters, word starts (after a space, `.`, `-` or at the start) and a match in the title score higher than scattered ones and than the id; an item without every character is dropped; ties keep the registry order. The result carries `matches`, the index ranges to highlight in the title (or in the id when only the id matched), drawn as text with `<mark>`, never as HTML. An empty query returns the commands in registry order. The limit is 50 rows.

**R11 Palette** (`palette.component.ts`, lazy through `@defer`). A modal dialog with a labelled text input that is a combobox (`role=combobox`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-autocomplete=list`) over a listbox of options (`role=option`, `aria-selected`, `aria-disabled` and `aria-describedby` the reason for a closed command, the chord shown in a `kbd`). Arrow Down/Up move (wrapping), Page Down/Up jump five options (Home and End keep moving the caret in the text field), Enter runs the active option, Escape closes, Tab stays in the dialog. Opening remembers the focused element; closing returns focus to it, and a chosen command runs after the focus has returned, so a command that moves focus (focus the filter) wins. Choosing a closed command does not close the palette and announces the reason. The count is announced after the list has changed (not on every keystroke of one burst). Locally written, no CDK (M0-54 Q-27).

**R12 Cheat sheet** (`shortcuts.component.ts`, lazy). A dialog listing every listed command that has a chord or an override: command, effective chords, whether it is the default or the person's; the conflicts and reserved chords as a list above the table; the load and save status of the keymap with a retry; `Change` (captures the next chord with the registry's own parser; Escape cancels; conflicts are refused with the reason unless the person chooses to replace), `Unbind`, and `Reset all`. It is opened by the command `help.keyboard-shortcuts`.

**R13 Menu model** (`menu-model.ts`). `buildMenuModel(commands, platform)` returns `{menus: [{id, label, items: [{kind: 'command', id, label, accelerator?, enabled, reason?} | {kind: 'separator'}]}]}` from the commands that declare `menu: {menu, order, group?}`; the labels are the commands' titles; the accelerators come from the effective chords; a closed command is `enabled: false` with its reason; a menu with no item is dropped. `syncNativeMenu(bridge, model)` calls `bridge.setMenu(model)` only when `bridge.kind === 'desktop'` and routes `onMenuCommand(id)` to `execute(id)`. The browser never calls it.

**R14 Commands of this WP.** The app (`apps/web`, registered by the shell host while a connection is shown): open the explorer overview, queues, exchanges, connections and bindings (a tab, through `WorkspaceTabs`), switch to each other connection (dynamic), add a connection, manage connections, check the capabilities of this connection (opens its connection page, where the check lives), toggle the theme, open the palette, show the keyboard shortcuts. The explorer (registered by the page while it is alive): focus the filter, refresh, save the view (action `views.create`), open the column chooser, copy the selected rows. Row activation and the grid's context menu are not wired (no entity page exists; M1-42); nothing here sends a command that changes the broker.

**R15 Strings.** Every string is a Transloco key; the scopes are `palette` (ui-commands), `commands` (apps/web) and `explorer.commands.*` (feature). No string uses "read-only", "non-destructive", "without side effects" or "safe peek".

**R16 What is proved where.** Node/Vitest (no DOM): R1, R2, R6, R10, R13 and the reserved-collision check. Angular component specs (`test-components`, jsdom, serial): R3 to R5, R7 to R9, R11, R12 and R14 with a `FakeEngine`; no layout, no paint. **Only against fakes: everything.** No real engine, broker or browser run is part of this WP (the maintainer runs the first manual test); whether `keybindings.get` and `keybindings.put` are served by a real engine depends on the engine wiring (OQ-441, OQ-472, OQ-669 lineage).

// @app/ui-commands (proposal)
export interface CommandDefinition {
  readonly id: string;                         // ^[a-z][A-Za-z0-9.-]{0,99}$
  readonly title: string | (() => string);
  readonly category: string | (() => string);
  readonly when?: (get: ContextGetter) => boolean;
  readonly keybinding?: string | readonly string[];  // default chords
  readonly action?: string;                    // engine action id: closed unless allowedActions has it
  readonly gate?: string | (() => GateDecision | null | undefined); // a feature id, or a decision
  readonly unavailable?: () => string | null;  // the feature's own reason
  readonly menu?: { menu: 'file' | 'view' | 'go' | 'help'; order?: number; group?: string };
  readonly bindable?: boolean;                 // default true; false for dynamic commands
  run(): void | Promise<void>;
}
export type Availability = { enabled: true } | { enabled: false; reason: DisabledReason };
export class CommandRegistry { register(def): () => void; registerSource(list: Signal<readonly CommandDefinition[]>): () => void; commands: Signal<readonly ListedCommand[]>; execute(id: string): Promise<ExecuteOutcome>; }
export const COMMAND_CAPABILITIES: InjectionToken<Signal<CapabilitySnapshot>>;
export function rankCommands(query: string, items: readonly Rankable[], limit?: number): readonly Ranked[];
export function buildMenuModel(commands: readonly ListedCommand[], platform: Platform): MenuModel;

- Native menus in Electron, accelerators registered with the OS, the desktop `onMenuCommand` wiring beyond the typed sync (M2-P14).
- Entity search ("engine search" over queues and exchanges) and navigation to an entity (M1-42), row activation, the grid's context menu items, and any command that changes the broker (purge, delete, publish). Chord sequences (`Mod+K Mod+S`). A key-by-key editor for a user's keyboard layout. Moving layouts through the palette (OQ-784).
- `tinykeys` and `@angular/aria`/CDK (no new dependency; patterns written locally).
