# M1-42 Deep links, linked navigation and entity detail tabs (EXP-05/06)

**Issue:** #127 · **Milestone:** M1 · **Wave:** M1-W1 · **Size:** M by label; five slices with hard budgets (see "Slices") · **Owner area:** ui (`area:engine` on the issue is not used: no engine change is made) · **trust:critical:** no

Status: working spec, written under the maintainer's standing "agile mode" instruction (the spec-approval stop is waived; no questions, working defaults, every assumption recorded as a row of `docs/open-questions.md`, "Spec questions: M1-42"). Checked against the worktree at `a056296`. The issue depends on #47 (M0-51, the shell) and #50 (M0-54, the explorer grids); both have landed.

## Goal

From a row in the Queues, Exchanges, Connections or Bindings grid the person opens an **entity detail tab**: a queue, an exchange, a connection or one binding, showing the fields the engine already returns (identity, type, state, counts, policy, who binds to it) and linking to the entities it relates to (a queue to the bindings that feed it, a binding to its exchange and its queue). Every such address is a **deep link** (`/c/:cid/queues/:key[/:tab]`) that survives a reload and a copy, and that the **connection switcher** carries to another connection when the object exists there. Everything is read-only inventory: no message is read, no broker-changing action is called, no peek.

Serves: EXP-05 (linked navigation and deep links, web part) and EXP-06 (entity detail tabs, the tab framework and the tab sets), DC-31 (gates rendered as sent, with their why-disabled reason), DC-15 (honest wording), ADR-021, ADR-034; invariants I-7 (bounded: one followed key, at most five 200-row windows scanned for bindings), I-10 (nothing secret is shown or copied), I-13 (no silent loss: stale, partial, vanished and truncated are said). Blueprint 3.2 (resource map: object keys as one opaque path segment, ADR-003), 10.

## Rules

**R1 Addresses.** `/c/:cid/{queues|exchanges|connections|bindings}/:key[/:tab]`. `:key` must match `ObjectKeySchema` and decode (`decodeObjectKey`); an address with an unknown kind, an undecodable key or more segments is not an entity address. `entityUrl(cid, ref, tab?)` and `parseEntityPath(path)` are inverse for every vhost and name, including `/`, unicode and 255-character names. The tab segment is optional; no segment means Overview. A tab that is not in the entity's tab set is not rewritten: the page shows the Overview with a notice that the address named a tab this entity does not have.

**R2 Tab sets** (data in `@app/explorer-model`, EXP-06). Queue: Overview, Messages, Publish, Tap, Consumers, Routing, Config, Charts, Forecast, Lint. Stream (a queue whose `type` is `stream`; known once the row is read): Overview, Browse, Consumers, Routing, Config (Messages is replaced by Browse). Exchange: Overview, Publish, Routing, Config. Connection and binding: Overview. Each tab says whether it is **built** in this version (Overview, Consumers, Routing, Config are; the rest are not) and which **gate** it needs (Messages `amqp.peek`, Browse `streams.browse`, Publish `amqp.publish`, Tap `amqp.tap`). A tab that is not built, or whose gate is not `enabled === true`, is rendered `aria-disabled` and focusable with its reason: the engine's `reason` and `source` as sent for a closed gate, otherwise "arrives in a later version". A deep link to such a tab shows the reason in the panel. No tab of any set reaches a message: no `get`, no peek, no publish.

**R3 One entity, live.** `createEntityWatch(data, {cid, kind, key})` over `ExplorerData`: for a swept kind it subscribes once with `keys: [key]` and reads one window of one row of the kind for the freshness; for `bindings` it finds the row by key over the vhost's windows (R5) once and again on `refresh()`. The state is `{phase, row, freshness, live, problem, ...}`:
- `loading` until the first snapshot (or the first answer) and, for an absent row, until the freshness is known;
- `found` with the row (the topic omits the key from the row; it is put back);
- `missing` with `certain: true` only when the freshness is `live`, `complete`, not `truncated` and `dropped` is 0; otherwise `certain: false` ("not in what has been read so far");
- `vanished` when a row that was shown is removed by a delta, or is absent from a later snapshot: the last row stays, marked removed;
- `error` when nothing could be read, with the Problem as received; an ended topic after a row was read keeps the row and sets `live: 'ended'` with the Problem (I-13).
A `gap` waits for the next snapshot; a `reset` asks for the freshness again. `refresh()` reads the freshness again (and, for bindings, the row). `destroy()` aborts and unsubscribes. No timer, no polling.

**R4 Existence for the switcher.** `lookupEntity(data, cid, kind, key, signal)` answers `found`, `absent` (certain, R3) or `unknown`. An abort, an error, a partial or loading inventory is `unknown`. `addressExists` in the feature maps `unknown` and `found` to true and `absent` to false, and answers false for an address it does not recognise as an entity address (the switcher's own default, so nothing unknown is carried over).

**R5 Related bindings.** `loadRelatedBindings(data, {cid, vhost, name, as})`: `inventory.query` kind `bindings`, `filter {vhosts: [vhost], text: name}`, windows of 200 from offset 0, stopping at `matched`, at an empty window or at `RELATED_SCAN_MAX` = 1000 rows scanned. Rows whose **destination equals `name` and `destinationType` equals the kind** are "bindings in" (queues and exchanges); rows whose **source equals `name`** are "bindings out" (exchanges). Each list shows at most 200 rows, the rest are counted. The result says `scanned`, `matched`, `truncated` (more matched than scanned), the freshness, and the Problem when a window failed (the rows read so far stay). A name of `''` (the default exchange) asks nothing and says that the broker does not list its implicit bindings.

**R6 Linked navigation.** Every name that names another entity is an `<a href>` (so middle-click and copy-link work) whose plain click calls `EXPLORER_NAVIGATION.open(cid, target, label)`: the shell opens or activates a workspace tab and shows it; outside the shell the default navigates the router. A binding row links its exchange (`exchanges`, key of vhost and source) and its queue or exchange destination (by `destinationType`) and the binding itself (`bindings`, its row key). The breadcrumb of an entity page is Explorer > kind list > the entity (vhost shown as text), each a link; history is the browser's: every open is one navigation.

**R7 States** (each in words; none is colour alone; the freshness banner of M0-54 is reused for stale, partial, truncated and dropped): no connection (nothing, no call); never probed (the probe prompt, no read); an address that is not valid (named as such, no call); loading; found; missing, certain ("not on this connection") and uncertain ("not found in what has been read so far", with the freshness lines); vanished ("removed after it was last read", last values kept and labelled); error (the Problem as sent, its hint by code, a Retry button); live updates ended (the Problem). A field the broker did not send reads "not reported", never `0`, `false` or blank (M0-54 R7).

**R8 Copy.** "Copy as text" puts plain `label: value` lines (the vhost, name, type, state, counts and the address) on the clipboard through `GRID_CLIPBOARD`; "Copy link" the absolute address. A clipboard that refuses is said, not ignored. Nothing secret is on the page, so nothing is masked (I-10); the copy holds exactly what the page shows.

**R9 Strings and accessibility.** One scope, `explorer` (keys `explorer.entity.*`, `explorer.breadcrumb.*`). The tab strip is `role="tablist"` with roving tabindex, Left/Right/Home/End, `aria-selected`, a disabled tab is `aria-disabled` and its reason is `aria-describedby`; the panel is `role="tabpanel"` labelled by the tab; the state lines are polite `role="status"`; the page has one `h1`; focus is not stolen on load. No string says "read-only", "non-destructive", "without side effects" or "safe peek".

**R10 Deep links from the OS** (allow-list). `parseDeepLink(path)` accepts only `/c/:cid/explorer[/queues|exchanges|connections|bindings]` (query `vhost`, `view`) and entity addresses, and returns the router URL, or `null` for everything else (a scheme, `..`, a backslash, a path outside `/c/:cid/`, a query it does not know, an action). The handler subscribes to `PlatformBridge.onDeepLink` when the bridge has it and navigates; it never calls an engine action.

## Out of scope

- Any message operation: Messages, Browse, Publish, Tap, Replay. The tabs exist in the sets as disabled entries with their reason; nothing behind them (M1-MSG*, M1 tap/peek WPs).
- A consumer list, queue or exchange arguments, channel lists, per-queue rates, charts, forecast, lint: the inventory does not carry them and no new engine action is made here (OQ rows; `libs/shared/contracts` and `svc-explorer` are untouched).
- Registering a coined URL scheme with the OS, the desktop `focus` of the window and `pnpm nx e2e e2e-desktop --grep=@deeplink` (M2; the allow-list and the handler are here). `pnpm nx e2e e2e-web --grep=@navigation` (M0-60 has not landed an e2e project): proved by the real router over in-memory services instead.
- Per-tab persistence of the chosen sub-tab in the workspace tab (a workspace tab keeps the entity's address, which opens Overview) (OQ).
- Command palette entries (EXP-04), breadcrumbs for pages other than entity pages, a tree level of entities (the tree stays static).
- Any change to `libs/engine/kernel`, the guardrail, `libs/shared/contracts`, `svc-explorer`, `apps/engine/src/entry`, or a protected path.

## Risks / questions

Each is a working default recorded in `docs/open-questions.md`, "Spec questions: M1-42".

- **Q-1 Route schema.** Default: the issue's `/c/:cid/queues/:key/:tab`, beside (not under) `/c/:cid/explorer/...`. The grids stay at `explorer/<kind>`.
- **Q-2 One key per entity via `explorer.window`.** There is no `queues.get`. Default: follow one key, plus a one-row window for the freshness. A real `*.get` action (fields the inventory lacks: arguments, consumers) is a follow-up issue.
- **Q-3 Absence.** Default: "not found" is certain only for a live, complete index with nothing dropped.
- **Q-4 Grid names are not links.** A grid cell is text. Default: Enter, double click and the menu open the entity. A link cell renderer in `ui-grid` is a follow-up.
- **Q-5 Workspace tab keeps the entity's address**, so re-activating it opens Overview; the chosen sub-tab is in the address only.
- **Q-6 Stream tab set** keeps Overview and Routing besides the plan's Browse, Consumers, Config.
- **Q-7 Unbuilt tabs** are listed, disabled, with a reason, so the framework and the sets are visible; their content is other work packages.
- **Q-8 Switcher** treats "cannot know" as "carry it over". 
- **Q-9 OS links**: handler and allow-list here; scheme registration, desktop focus and e2e in M2.
- **Q-10 Binding "group".** Read as: one binding page, and the bindings in/out lists of a queue or exchange.
- Estimated changed lines across the five slices: about 1,240, hard budgets 2,630, against the 800 guidance, which is why the work is five slices; `oversize-approved` is not requested.
