# M1-46 Monaco ESM wrapper and publish studio UI with history (PUB-01/02 UI)

**Issue:** #131 · **Milestone:** M1 · **Wave:** M1-W3 · **Size:** M by label; eight slices with budgets (see "Slices") · **Owner area:** ui (`area:ui`; the issue also carries `area:metrics` and `area:topology`, which this work does not touch) · **trust:critical:** no. Publishing is a write, but the UI only calls `EngineApi`; every guard (prod lock, plan, consents, audit) stays in the engine (I-2). The protected paths it needs are a dependency change and one override, which a maintainer applies (see "Proposed changes for a maintainer").

Status: draft for human approval (written with `/wp-spec`). Nothing is implemented. Checked against `origin/main` at `1d6179c` on 2026-10-26. Every question is a row of `docs/open-questions.md`, section "Spec questions: M1-46", ids OQ-1509 and up, each with the default this spec implements.

## Goal

A publish studio inside the web shell (PUB-01) and its history (PUB-02): compose one message in a VS Code-grade editor (Monaco, own ESM wrapper, lazy chunk), send N copies through `messages.publish`, and see an honest outcome for each copy (`confirmed`, `nacked`, `returned: NO_ROUTE`, `blocked`, `timeout`, `failed`, `not-sent`); browse the last 30 days of what the person published on this connection, grouped by day, and send one again with its secrets masked. Serves PUB-01, PUB-02, DC-12 (mandatory and confirms, shown as fixed facts), DC-15 (honest wording), DC-31 (gates rendered as sent), ADR-021 (Monaco wrapper, CSP and Trusted Types), ADR-034, and the invariants I-1, I-2, I-6, I-7, I-10 and I-13.

Not part of this work package: bulk publish, templates and variables, the RPC and consumer test bench, AMQP 1.0 publish, copy as code (all M4), the engine side (M1-19, landed through slice D), and wiring the real `ConnectionManager` (OQ-357, OQ-771, OQ-1446).

## Rules

**R1 Monaco is a lazy, trimmed, owned chunk.** Nothing in the initial bundle imports `monaco-editor`. `loadMonaco()` first installs the environment, then imports the Monaco entry, in that order and in one single-flight promise (the language guarantees the order; OQ-1513). The entry imports the editor core, the JSON language contribution, the XML/YAML/plaintext tokenizers and no command palette, quick-open, or other language. Only `libs/ui/editor` imports the package (I-11), and no `eslint-disable` is used for it.

**R2 The environment is exactly S-04's.** Two Trusted Types policies are created, `app-worker-url` and `app-monaco-html`; `dompurify` appears by itself on the first Markdown hover; `angular` is the shell's. `app-worker-url` mints only a URL from `EDITOR_WORKER_PATHS`, same origin, no query, no traversal. `MonacoEnvironment.createTrustedTypesPolicy` routes every Monaco policy through `app-monaco-html`. Every `<style>` Monaco creates carries the page nonce (the `csp-nonce` meta tag). A realm without Trusted Types installs plain worker URLs from the same list. The CSP is never loosened: no `unsafe-eval`, no `unsafe-inline` for scripts, no `blob:` worker.

**R3 Disposal and bounds (I-6).** Every editor, model, listener, resize observer and diff pair is disposed exactly once, also when the component is destroyed before the lazy load resolves. A value is never truncated silently: over `maxBytes` the editor keeps it and emits `overLimit`; the studio blocks Send with the limit named. Markers are capped at 100 per model.

**R4 The studio composes, the engine decides.** The studio builds a `MessagesPublishInput` from the draft and calls `EngineApi.plan` then `EngineApi.execute` (OQ-1515). It renders the plan's `gates` (reason, source, fix), `warnings`, `consentsRequired`, `confirmationPhrase` and `approvals` as sent and executes only what the plan allows. It never decides whether the person may publish. A closed prod lock is shown with `lockGate` and `ArmingStore` as in `feature-connections`; the engine still refuses a locked call.

**R5 Outcomes in words, one per copy (I-13, DC-15).** Every copy of the answer appears once. `confirmed` is worded as "the broker confirmed it", never "delivered" or "received by a consumer". `returned: NO_ROUTE` is shown exactly in that form and explained: the broker found no queue for this exchange and key, and the message was returned to the publisher (the broker did not keep it for this publish). `nacked`: the broker refused it. `timeout`: no confirm in time, the broker may still have routed it. `blocked`: the connection was blocked, nothing was sent for that copy. `failed`: shows the contract error code. `not-sent`: the loop stopped before it. The summary shows the seven counts; the success state ("All N copies confirmed") appears only when `allConfirmed` is true. A `historyRecorded: false` answer says in words that the publish happened and was not saved to the history. The wording never says "read-only", "non-destructive", "safe" or "undo"; a publish is a write and cannot be undone from here.

**R6 Masked values on re-send (I-10).** The UI never holds a secret it was not typed: the history gives it only the masked form and `resend.masked`. "Send again" fills the draft from `resend`, marks every listed place with a badge and a sentence ("This value was masked when the publish was saved. Type the real value, or send the mask text on purpose."), and keeps the places in `draft.masked`. A place leaves the set when the person edits that field to a value other than the mask text, or ticks "Send the mask text for this value". Send is disabled with a reason that names the remaining places. The UI does not parse the text for `[REDACTED]` or `[long]` to guess; it relies on the list. A notice always says that a re-send is a starting point, not a copy, and that a secret the mask did not recognise may still be visible (OQ-1442). Nothing from the history is written to storage, URLs, tab labels or announcements.

**R7 Drafts and secrets.** The draft is kept in memory per connection while the page is open (it survives a tab switch, not a reload) and is never written to `localStorage`, `sessionStorage`, IndexedDB, the URL, the tab label or a log (OQ-1518). Only the prefill query parameters `vhost`, `exchange`, `routingKey` (each at most 255 characters) are read from the address. Header values are typed in clear; they are not echoed in the plan dialog (the plan's preview shows exchange, key, copy count, byte size and header count) or in the result panel.

**R8 States, each in words.** No connection (nothing, no call); loading; ready; composing with form errors; sending (the button busy, one request in flight, no second send); result; failure before any outcome (the Problem as sent, its hint by code, the form untouched); `CAPABILITY_MISSING` (the Problem as sent and the hint "this engine build cannot publish yet: no publish connection is wired", nothing marked as sent); history loading, empty, partial, failed (Problem and Retry), expired entry. A field the engine did not send reads "not reported", never blank or zero.

**R9 History panel (I-7).** A keyset window of 50 (`limit`), "Load more" follows `nextCursor`, one request per click, newest first, grouped under local-day headings by the entry's `at` (the full ISO time in the tooltip). Filters: vhost, exchange (the default exchange is shown as "(default exchange)"), routing-key prefix, from and to. There is no body search control. The panel states the 30-day retention. After a send the list is refreshed once. Reads need no gate; a permission refusal is shown as a Problem.

**R10 Routing-key and exchange suggestions (I-7, I-8).** From `scanBindings` for the chosen exchange (rows whose `source` equals the exchange), at most 1,000 rows, deduplicated routing keys, at most 50 shown, with a count of destinations; the default exchange suggests queue names from the queues window. A truncated scan says "partial". The exchange type, when known from the exchanges row, gives a hint (topic: pattern, fanout: key is ignored, headers: routing on headers); an unknown type gives no hint. A picked topic pattern is inserted as text with a notice to replace wildcards by real words. The UI never computes whether a key would route (no simulation here; the broker's answer after the send is the truth). Missing permission, an unprobed connection or an error turns the suggestions off with one line naming why; typing and Send are never blocked by it.

**R11 Accessibility.** Standalone components, zoneless, OnPush, signals; every control has an accessible name from an i18n key; the editors get `ariaLabel`, a visible, keyboard-reachable hint for leaving the editor with Tab (Monaco's focus-mode toggle, Ctrl+M) and no keyboard trap; the outcome list and the history are real lists/tables with text for every state (no colour alone); result and form errors are announced politely; the suggestion list follows the combobox pattern (roles, `aria-activedescendant`, Escape); 1280x720 has no horizontal page scroll; the high-contrast theme maps to a high-contrast Monaco theme.

**R12 Strings.** One scope, `publish` (`libs/ui/feature-messages/src/i18n/en.json`), registered like `EXPLORER_SCOPE`; keys by area (`publish.form.*`, `publish.outcome.*`, `publish.plan.*`, `publish.history.*`, `publish.masked.*`, `publish.suggest.*`, `publish.editor.*`, `publish.hint.*`, `publish.state.*`). The editor library has no strings of its own: labels arrive as inputs. `@app/ui-no-raw-template-text` and `@app/honest-wording` pass.

## Risks / questions

Every question has a default that this spec implements; each is a row of `docs/open-questions.md` ("Spec questions: M1-46", OQ-1509 to OQ-1525). Please read OQ-232 (existing, blocks A2), OQ-1509, OQ-1512, OQ-1515 and OQ-1517 first.

- **OQ-1509 dependency intake.** `monaco-editor@0.57.0` and an override of `dompurify@3.4.15` to 3.4.17 (see above). Default: as proposed. Closes when a maintainer applies items 1 to 3.
- **OQ-1510 the 1.1 MB budget.** The issue and `.claude/rules/ui.md` say "at most 1.1 MB"; `web:budgets` measures gzip. S-04's untrimmed `editor.main` was 2.7 MB minified, so a raw 1.1 MB is probably out of reach, and a gzip 1.1 MB would be easily met. Default: the limit is **gzip bytes of all Monaco chunks together, 1,100,000, workers reported separately**, with the raw size printed; slice A2 measures the trimmed build and reports both, and the maintainer may tighten it. A marker-based exception row (like AG Grid's) is added to `tools/web-budgets` in slice G.
- **OQ-1511 XML and YAML "workers".** Monaco has no XML or YAML worker. Default: JSON worker for JSON (schema validation, body and, later, headers), Monarch syntax colouring for XML and YAML, no validation, and the studio says so. A `monaco-yaml` worker would be a second dependency.
- **OQ-1512 how Monaco builds under Angular.** The Angular application builder may not import Monaco's CSS and font assets from TypeScript, nor emit ES module workers under our policy (`new Worker(new URL(...))` is a pattern the builder detects, and the policy needs `new Worker(trustedURL)`). Default: A2 tries the plain build first; if it fails, the editor entry and the two workers are prebuilt with the esbuild that `@angular/build` ships (as `spikes/csp` does) into an asset directory and loaded by URL. **Worker version skew:** the shell keeps the previous build's assets (N and N-1) for a tab that has not reloaded; fixed worker names would pair an old Monaco with a new worker. Default: workers get content-hashed names and the path list is generated at build time and injected as a constant, so the policy stays a fixed list per build. This is the main unknown of the work package, which is why A2 is its own slice.
- **OQ-1513 where the load-order hooks live (answers OQ-233).** S-04 put them in Angular's `polyfills`. Default: `ui-editor` owns them and `loadMonaco()` awaits the environment before it imports the Monaco entry, so the order is guaranteed by the sequence of `import()` calls and the initial bundle stays free of Monaco; the `polyfills` entry is the fallback if A2 shows a chunk-order problem. Either way, the one rule is that nothing else imports Monaco statically.
- **OQ-1514 names and route.** The issue says `libs/ui/feature-messages/publish`. Default: library `feature-messages` (the viewer of M1-45 may join it later; a feature never imports another), folder `publish`, route `/c/:cid/publish`, scope `publish`, library `ui-editor` at `libs/ui/editor`. Alternative: `feature-publish`.
- **OQ-1515 plan first.** `messages.publish` has optional planning that the guardrail policy raises in prod and staging. Default: Send always calls `plan` and then `execute`; with nothing required (no consents, phrase, approvals or blocking gate) the Send click is the consent and `execute` follows at once; otherwise the dialog of AC-30 shows. Alternative: a direct call and handling of 428; it hides the plan in dev and duplicates the path.
- **OQ-1516 Send while the engine cannot publish.** No gate says the writes are unwired; `amqp.publish` is about the broker handshake. Default: Send stays enabled, the engine's `CAPABILITY_MISSING` Problem is shown with a fixed hint (AC-31). Alternative: a feature flag or a gate from the engine, which would be an engine change.
- **OQ-1517 masked values on re-send.** Default (R6): the UI uses `resend.masked`, blocks Send until each place is edited or explicitly acknowledged, and never guesses. Alternatives: allow Send with only a warning (easier to publish a mask by mistake), or drop masked fields from the prefill (loses the shape).
- **OQ-1518 draft persistence.** Default: memory only, per connection, lost on reload, never in storage (headers can hold secrets typed in clear). Alternative: persist non-secret fields only, which needs a rule for what is secret that the UI should not own.
- **OQ-1519 "searchable history".** PUB-02 says searchable; the engine offers filters and no body search (OQ-1442). Default: vhost, exchange, routing-key prefix and time-range filters, day grouping done in the browser in local time, windows of 50, retention stated. Body search would be an engine change over sealed data.
- **OQ-1520 suggestions.** Default (R10): bounded `scanBindings`, 50 shown, patterns inserted as text, no routing simulation, off when `broker.read` is missing. Alternative: call `routing.simulate` for a "would route" hint (adds a second source of truth next to the broker's answer).
- **OQ-1521 scope cuts.** Default: no JSON Schema pane, no diff surface in the studio, no binary file import, no queue/exchange Publish tab wiring in this work package; the wrapper provides the schema and diff editor. Follow-up issues are opened by a maintainer if wanted.
- **OQ-1522 `@publish` e2e.** `apps/e2e-web` does not exist (M0-60). Default: interim proof as listed in "Verification"; a comment on #52 asks for a `@publish` flow; no separate issue.
- **OQ-1523 Monaco features and chords.** Default: the Monaco command palette (F1), quick-open and go-to-symbol are not in the entry, so the app's command palette is the only one; Ctrl+M focus-mode is documented in the editor's hint; the app's reserved chords are not bound by the wrapper.
- **OQ-1524 outcome wording.** The texts of R5 are mine; they need a maintainer's read for DC-15 (in particular "returned to the publisher" for `NO_ROUTE` and the `timeout` sentence).
- **OQ-1525 vhost and exchange source.** There is no vhost list kind. Default: the vhost field starts at the connection's AMQP vhost and is editable text; exchanges are suggested from the `exchanges` window filtered by text (needs `broker.read`).

## As built, slice A1 (2026-10-26)

Slice A1 (`libs/ui/editor`, project `ui-editor`: the environment, the loader and the facade types, no Monaco package) differs from the text above in these ways. Slice A2 starts from what the code does.

- **Scaffold.** The `library` generator cannot make a project whose name differs from its folder, so it ran as `--name=ui-editor --directory=libs/ui` and the output was moved to `libs/ui/editor` with its paths rewritten (OQ-1529). `vitest.config.mts` gained `setupFiles` and `src/test-setup.ts` (the Angular test environment, copied from `ui-commands`) because `MONACO_LOADER` is an injection token. No `test-components` target: A1 has no component.
- **Files.** `environment/{realm,trusted-types,style-nonce,monaco-environment}.ts`, `loader.ts`, `facade.ts`. The spec lists `facade.ts` with "the narrow types"; `EditorHost`, `EditorHandle` and `EditorOptions` are a minimal shape (create an editor, read and set value, language, read-only and markers, a change listener) that slice B may change. `environment/realm.ts` holds the small interfaces (`EditorRealm` and friends) that let the environment run against a fake page in specs; `environment/environment-spec-support.ts` holds the fakes.
- **Public API.** `installEditorEnvironment`, `EDITOR_WORKER_PATHS`, `MONACO_LOADER` and the facade types as specified, plus `loadMonaco`, `createMonacoLoader`, `EditorLoadError` and the type `EditorRealm`. `loadMonaco` and `MONACO_LOADER` are in `loader.ts`.
- **No Monaco entry yet.** The default `importHost` rejects with `EditorLoadError('not-bundled')`. A2 replaces its body with `import('./monaco-entry')`. Nothing pretends an editor exists in this build.
- **Worker URL rule.** The policy accepts a URL only when it is exactly the listed path, or that path on the page's own origin (the input must equal what the URL parser makes of it). This is stricter than S-04's spike (which only compared the origin and the parsed path) and also rejects `..`, backslash and encoded forms. An opaque origin gets no workers (OQ-1531). The page origin plus the path being the whole URL replaced three separate checks (origin, `'null'`, empty), found redundant by the mutation pass below.
- **Retry.** `installEditorEnvironment` keeps the policies it created per realm, so a call repeated after a later step failed (for example a refused policy name) does not create a name twice (a second `createPolicy` of the same name throws in a browser).
- **Style nonce hook.** It patches the object up the prototype chain that owns `createElement` (`Document.prototype` in a browser), not a global `Document`, so it works for any document of the realm. It is global and starts at the first load (OQ-1530).
- **Honest scope.** AC-1 to AC-6 run against fake pages (a recording `trustedTypes`, a fake `Worker`) and, for AC-4, the jsdom document. They show the logic, not that a real browser accepts it; that is AC-7 and AC-8 in A2.
- **Mutation pass.** The repository has no Stryker setup, so 45 hand-made mutants of the four source files were run against the specs (origin and canonical-URL checks, the path list, the label mapping, each policy and its cache, the html and script routing, every branch of the nonce hook, idempotence and the stored state, module worker options, the nonce hook call, the default list check without Trusted Types, single flight, the kept success, the uncached failure, both error codes, the typed error passthrough, the order of install and import). Nine survived the first pass: three were redundant checks (removed from the code), one an extra listed path (the list is now asserted exactly), and five were four behaviours without a test (the second install replacing the environment object, which killed two mutants; the nonce hook not installed by `installEditorEnvironment`; a policy re-created after a later failure; `createElement` arguments dropped). Each now has a test; the final pass killed 42 of 42.
