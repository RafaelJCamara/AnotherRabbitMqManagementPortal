# kernel

Primitives shared by every engine module (M0-16): configuration loading, a redacting logger, a clock and id generator, Problem mapping, and the bounded buffers of I-6. The scheduler (M0-23) and the action layer (M0-29: ActionExecutor, PlanStore, `implementAction`) sit beside them. The hash-chained audit, the receipt store and the local guardrails with the prod lock (M0-30) sit with the executor. The drain coordinator (M0-31) is the budgeted shutdown; the job runner it drains lives in `@app/jobs`.

Tags: `type:kernel`, `runtime:node`. `src/actions/` is trust-critical (CODEOWNERS). Imports `@app/contracts` (types and schemas), `@app/ports` (types and `LANES`), `zod`, `yaml` and `pino`. `pino` is confined to this project (I-11).

## Invariants

- **I-2 (M0-29).** Mutations and message touches run only through `ActionExecutor.run` and `execute`. The `execute()` of an action is reached after, and only after, every check of blueprint 5.1 passed, and the write ports (`ExecutorWrite`) exist only in the context of `execute()`: `plan()` and `revalidate()` get a context without them. `register` accepts only what `implementAction` returned (a `WeakSet`), and the executor uses its own registered definition, never the caller's copy. The architecture test in `tools/arch-tests` fails any file outside the plumbing that names a write-capable port without calling `implementAction` or `defineJob`.
- **Fail closed (ADR-006).** Each of these stops the call before `execute()`: an unknown action, a malformed principal, an authorizer answer other than `allowed: true`, a guardrail policy that throws, a missing or reused idempotency key, an expired, used or tampered plan, a missing consent, a wrong typed phrase, too few approvals from other principals, drift in `revalidate` or in the profile fingerprint, and a failed audit-attempt write. An unset or unknown environment class is `prod`.
- **Audit and lock (M0-30).** `createActionExecutor` has no default for `audit`, `guardrails` or `receipts`: leaving one out throws at start-up. Prod is locked until armed, peeks count as mutations, and the lock is re-checked at execute. The audit chain is append-only (the database also refuses UPDATE and DELETE); a tampered, deleted or reordered row is reported by `verify` at the first seq that does not hold, and a truncated tail or a rewrite to the end needs an anchor (OQ-273). Stored text is redacted and bounded (`log/scrub.ts`); no input, sensitive payload or message body reaches an audit row or a receipt (I-10).
- **Plans.** The digest covers every bound field and is also sealed inside the AES-GCM payload (AAD `plans:payload:<id>`), so a row edited in the database fails with `PLAN_STALE`. Payloads are purged at expiry, rejection and execution; the digest stays. A plan runs once: a failed run consumes it.
- **Drain (M0-31).** Time comes from the injected `Clock` and `Timers`, so `drain` is deterministic under `createManualTimers`. A drain never waits longer than `totalMs` for a phase to end, whatever the phase does (`src/drain/drain-coordinator.spec.ts`, `AC-1`); what an overrunning phase leaves undone is the phase's own to report (OQ-312).
- **I-6.** Every buffer is bounded by items and bytes, and every drop is counted (`dropped`, `droppedBytes`) and reported to `onDrop`. The classes live in `src/bounded`, the one place `@app/bounded-buffers-only` does not apply. Their add methods are named `add` and `offer` because the rule rejects `.push` on anything named like a buffer.
- **I-8.** The scheduler is the only code that runs management and Prometheus HTTP work. At most one background request per broker is ever in flight, and interactive work never waits for background work (it may wait for other interactive work when the lane is at its cap). Cached results are shared between callers: treat them as immutable. `src/scheduler/broker-scheduler.spec.ts` carries AC-1 and AC-2, a model test over random lanes, brokers and outcomes, and the cancellation, queue-full and shutdown cases.
- **I-10.** Secrets do not reach logs or Problems. The logger masks, on the finished line, values of keys such as `authorization`, `cookie`, `password`, `token`, `secret`, `x-*` credential headers, `body` and `payload`, and scrubs credentialed URIs (AMQP, HTTP, shovel and federation), secret query parameters, JWTs and Bearer values in every string. `toProblem` redacts `detail` and never copies the message or stack of an unknown error. `ConfigError` names keys and rules, never values. Redaction errs towards masking too much.
- **I-11.** `pino` (and `pino-*`) may be imported only here; other projects use the `Logger` interface.
- **Config.** Unknown keys are rejected in every source (environment, file, defaults), even when the schema would strip them. Environment variables are `PREFIX_SECTION__KEY` (`APP_SERVER__PUBLIC_URL` is `server.publicUrl`); `..._FILE` reads the value from a file. Text from the environment or a file is converted to the number, boolean, array (JSON) or object (JSON) the schema asks for.
