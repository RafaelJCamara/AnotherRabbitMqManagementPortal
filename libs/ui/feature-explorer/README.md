# feature-explorer

The explorer of a connection: grids for queues, exchanges, connections and bindings with filters and saved views, and the cluster overview (M0-54, EXP-02 and EXP-03, UI side). It reads the inventory through `inventory.query`, follows the rows on screen through the `explorer.window` topic, and says in words whenever what it shows is loading, stale, partial or truncated. It reads no message and calls no action that changes the broker; its only commands keep a person's own saved views (`views.create`, `views.delete`), and on a person's press of the button of a never-probed connection it runs `probe.run` (OQ-821).

Tags: `type:ui-feature`, `runtime:browser`. Not `trust:critical`.

## Public API

- `explorerRoutes` and `explorerRoutesFor(connection)`: the child routes the web shell mounts at `c/:cid/explorer`. The app never imports this lazy library statically, so it loads it with `loadChildren: () => import('@app/feature-explorer').then((m) => m.explorerRoutesFor(() => inject(ActiveConnection).cid))`; `explorerRoutesFor` provides `EXPLORER_CONNECTION` from that factory. The parent route provides the `explorer` Transloco scope (`provideExplorerScope`, a bundled-JSON `import()` loader; keys read `explorer.<path>`).
- `@app/feature-explorer/testing`: `markedExplorerScope`, the English file with every text replaced by `[[explorer.<path>]]`, for specs of an app that mounts the explorer (provide it as `EXPLORER_SCOPE_LOADER`).
- `EXPLORER_CONNECTION`: an injection token for a `Signal<string | null>` with the connection id. The web shell provides it on the mounting route; a feature never imports `apps/web`. `null` means no content and no call.
- `EXPLORER_SCOPE`: the scope name.
- Pages (lazy, one chunk): `InventoryPage` (`<app-inventory-page [kind] [vhost]>`: the filter bar, a banner that says what the list is, and `<app-data-grid>` over a window source of `explorer-model`), `InventoryRoute` (kind from the route data, `?vhost=` for bindings), `FilterBar` and `FacetPicker` (disclosure panels; a text change applies after 200 ms or on Enter, any other change at once; only the contract's filter with the facets that apply to the kind; chips that remove themselves; caps refuse with a reason), `FreshnessBanner` (what the last answer's freshness said: loading, stale, truncated, dropped, incomplete, hazards and the engine's reason as sent; the live feed: following, paused, ended with its Problem; a failed window with its Problem; a count-free polite announcement of the state).
- Overview (`lib/overview`, the route's empty path): `OverviewPage` (totals as the broker sent them, an absent one reads "not reported"; messages with their source in words, the time they describe and "partial" when the sum is; rates, or why they are unavailable and no number; the nodes as a table; alarms: an active one is an alert naming node and resource, none says none is reported, unknown says the state could not be read and is never worded as none; the inventory freshness as the grid banner words it), `OverviewStore` (one `overview.get` on open and one per press of Refresh after a 10 s floor; never a timer-driven call; a failed read keeps the last answer, marked as earlier).
- Capability card (`CapabilityCard`, a region of the overview): one row per gate of the profile, in id order, as the engine sent it: open only for `enabled: true`, otherwise "Not available" (a string, a missing field and a non-object are closed), with the engine's reason and source as sent; a source is a link only when it is an absolute https URL without credentials (`rel="noopener noreferrer"`); a profile that is absent, failed, empty or unreadable says the capabilities are not known, never "available". It has no control and computes no authorisation.
- First-run prompt (`lib/profile`): `ProbePrompt` (`<app-probe-prompt [need]>`: why the engine has no usable profile, what the probe does in words, the one button, the Problem of a failed probe as sent with a sentence of help), and `ProfileStore.needsProbe` / `ProfileStore.probe()` which the inventory pages and the capability card read; the inventory page makes no source, so asks nothing of the engine, until the profile is known and usable.
- Saved views (`lib/views`): `ViewsControl` (a disclosure: list of the person's views of the kind, apply, save the current filters and columns, replace, delete after an inline confirmation; Save and Delete are `<app-gated>` from the profile's `allowedActions`, closed with a stated reason when the action is not listed or the profile is not known; what a view names and the kind cannot apply is listed; an engine refusal is shown as sent; focus returns to the button), `ViewsStore` (`views.list`, `views.create`, `views.delete`; replace is create then delete) and `ProfileStore` (`profile.get` parsed with `BrokerProfileSchema`; anything else is unknown). The applied view lives in `?view=`.
- Entity pages (M1-42, `lib/entity` and `lib/navigation.ts`): `entityRoutesFor(kind, connection)` (one lazy mount per kind in the shell: `/c/:cid/{queues|exchanges|connections|bindings}/:key[/:tab]`, one matcher so a tab change reuses the page), `EntityPage` (the fields the inventory carries, in words; the breadcrumb; Copy as text, Copy link and Read again; loading, found, not found with the certainty of the index, removed after it was read, failed with a retry, live updates ended; a tab strip with the tab sets of the model, the unbuilt or closed ones disabled with the engine's reason and source as sent), `EntityTabs` (WAI-ARIA tab list, one tab stop), `RoutingPanel` (the Routing tab: the bindings that feed a queue or an exchange and, for an exchange, the bindings that leave it, matched exactly over at most five windows of 200, with what was not read and not shown said, a failed window's Problem as sent, and a link on every name), `EntityLink` (a real anchor whose plain click opens a workspace tab), the binding page (source and destination as links, one tab), `injectEntityRead` (the model's entity watch as a signal). `EXPLORER_NAVIGATION` is how the feature opens an entity or a page (the router by default; the web shell provides workspace tabs); the grids open an entity on Enter, a double click and the row menu (Open details, Copy link). `addressExists` (the connection switcher's question) and `EXPLORER_DATA` are exported for the shell.
- Entity pages (M1-42, `lib/entity` and `lib/navigation.ts`): `entityRoutesFor(kind, connection)` (one lazy mount per kind in the shell: `/c/:cid/{queues|exchanges|connections|bindings}/:key[/:tab]`, one matcher so a tab change reuses the page), `EntityPage` (the fields the inventory carries, in words; the breadcrumb; Copy as text, Copy link and Read again; loading, found, not found with the certainty of the index, removed after it was read, failed with a retry, live updates ended; a tab strip with the tab sets of the model, the unbuilt or closed ones disabled with the engine's reason and source as sent), `EntityTabs` (WAI-ARIA tab list, one tab stop), `injectEntityRead` (the model's entity watch as a signal). `EXPLORER_NAVIGATION` is how the feature opens an entity or a page (the router by default; the web shell provides workspace tabs); the grids open an entity on Enter, a double click and the row menu (Open details, Copy link). `addressExists` (the connection switcher's question) and `EXPLORER_DATA` are exported for the shell.
- Commands (`lib/commands`, M1-41): `registerInventoryCommands` and `registerOverviewCommands` register, while a page lives, what a person can do from the keyboard or the command palette: focus the filter (bare `/`, ignored while typing; `EXPLORER_DEFAULT_CHORDS`), reload the list, save the view (action `views.create`: closed with the engine's words unless its `allowedActions` has it), choose the columns, copy the selected rows, and refresh the overview (closed inside the 10 s floor). Each presses a control the page already has (`FilterBar.focus`, `ViewsControl.openSave`, `DataGrid.openColumnChooser`, `copySelection`); none sends a command that changes the broker. The titles are keys under `explorer.commands`.
- Internal: `createEngineExplorerData(api, live)` (`lib/data`): the `ExplorerData` port over `EngineApi` and `LiveClient`; and a spec testbed (`lib/testing`) that runs the real `EngineApi` and live client over the fake engine with the inventory answered by the model's fake.

## Invariants

- Depends on ui-data, ui-design, ui-lib (`ui-grid`), ui-platform, contracts, pure (`explorer-model`) and domain-model; never on another feature (blueprint 2.2). Only `ui-grid` imports AG Grid (I-11).
- All copy lives in `src/i18n/en.json` (the scope root); templates contain bindings only (`@app/ui-no-raw-template-text`, `@app/honest-wording`). No string says "read-only", "non-destructive", "without side effects" or "safe peek".
- Talks to the engine through EngineApi and the live client, never `fetch` or sockets (`@app/no-direct-fetch`).
- Renders untrusted text through bindings, never `innerHTML` (`@app/no-inner-html`).
- Bounded (I-6, I-7): 200-row blocks, 25 blocks, at most 500 followed keys and 48 KiB of key text per subscription; no list-all.

## Known limits

- The two view commands, `views.create` and `views.delete`, declare `scope: 'local'` (they change only the engine's own state), so a running engine runs them with nothing armed (OQ-783; OQ-380 is answered). The control still shows an engine Problem as sent and loses nothing (AC-19, against the fake engine); a view saved against the real router is proved in the testkit (AC-28).
- A new filter keeps the grid's scroll position (clamped to the new length) instead of returning to the first row; a sort returns to the top. The browser run (AC-27) found it and starts every filter step from the top for that reason (OQ-789).
- A connection is added in the page (`/connections`, M0-52); until one exists the explorer pages show their empty and error states.
- **The first run (OQ-821).** A connection that was never probed has no cached profile, so the engine answers 404 to `profile.get` and to every `inventory.query` (the overview does not need one). The connection form probes once right after a create, so the usual path never meets this; for a connection saved some other way (or a probe that failed) the inventory pages read nothing, show "This connection has not been checked yet" and one button, **Check capabilities and load**, which runs `probe.run` and then loads the list with the profile the probe answered. The overview's capability card offers the same button. A probe that fails shows the engine's Problem as sent and a sentence of help for the codes a first session meets (wrong login, broker not reachable), and the button stays. The explorer therefore calls `probe.run`, but only on that press.
- **Edge states (OQ-823).** Broker unreachable or login refused: the Problem as sent plus one sentence by code (`explorer.hint.*`). Inventory not read: the engine's words plus a pointer to the overview, which asks the broker directly (the sweep's own Problem is not in the inventory answer). Sweep not started: "Loading the inventory: 0 loaded", never "no rows". Empty broker: "This broker has no queues" only for a live, complete answer with no filter. Proved in specs against fakes; not seen against a real broker.
